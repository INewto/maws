# Как работают тесты в MAWS

Документ описывает прогон тестов «от и до»: от атрибутов в исходнике до строки `[ok]` в отчёте.
Он про то, **как это устроено сейчас**, а не про то, как писать контракт (это — `FORLLM.md`, §12).

Короткая суть: **тесты в MAWS не пишут руками.** Руками пишется контракт — декларативные атрибуты над
классом и методами. Команда читает эти атрибуты, генерирует по ним обычный PHP-файл с вызовами
`$run->gives(...)`, `$run->fails(...)` и запускает его. Проверяется не текст атрибута, а **вызов метода**
— поэтому объявление, разошедшееся с телом, ловится прогоном, а не чтением.

---

## 1. Два входа

| Команда | Что делает | Область |
|---|---|---|
| `php maws.php make test:<файл>` | читает контракт одного файла, **пишет** тест в `app/Tests/**` и тут же **запускает** его | один файл, путь от корня проекта |
| `php maws.php test` | находит все файлы `core/**` с `#[Subject]`, для каждого запускает `make test:` **отдельным процессом** и печатает сводку | весь `core/**` |

Это не два разных механизма. `maws test` — обёртка: он для каждого источника делает ровно то же, что
`make test:<файл>`, только в своём процессе и с разбором результата.

### 1.1 `maws make test:<файл>`

```bash
php maws.php make test:core/System/Helpers/Path/Path.php
php maws.php make test:app/World/Public/Places/Home/Tools/ExampleTool/ExampleTool.php
```

Путь — **от корня проекта**, обратные слэши допустимы, ведущий `./` срезается. Тест ложится зеркально:

| Источник | Файл теста |
|---|---|
| `core/Ai/Ai.php` | `app/Tests/Core/Ai/AiTest.php` |
| `core/System/Helpers/Path/Path.php` | `app/Tests/Core/System/Helpers/Path/PathTest.php` |
| `app/World/Public/Places/Home/Workspace.php` | `app/Tests/App/World/Public/Places/Home/WorkspaceTest.php` |

Правило зеркала: `core/…` → `Core/…`, `app/…` → `App/…`, расширение `.php` → `Test.php`.

Файл теста **перезаписывается при каждом запуске**. Правки в нём теряются — править надо контракт в
источнике. Сам каталог `app/Tests/` — вывод, а не исходник.

### 1.2 `maws test`

Обходит `core/**`, ищет источники **по тексту файла**, а не отражением:

```php
private const SUBJECT = '/^#\[Subject\(/m';
```

То есть `#[Subject(` должен стоять **с начала строки** (без отступа), и файл должен лежать в `core/`.
Каталоги, в пути которых есть `/templates/`, пропускаются: там объявление написано для будущего класса,
а не для существующего. Список сортируется по пути.

Каждый контракт идёт **своим процессом**:

```php
$command = escapeshellarg(PHP_BINARY)
    . ' ' . escapeshellarg($root . '/maws.php')
    . ' ' . escapeshellarg('make')
    . ' ' . escapeshellarg('test:' . $source)
    . ' 2>&1';
exec($command, $lines, $code);
```

Причина: в общем процессе прогон унёс бы с собой соединение с базой, сессию и файлы песочницы, а фатал
в одном контракте оборвал бы остальные.

### 1.3 Коды возврата

| Код | `make test:<файл>` | `maws test` |
|---|---|---|
| 0 | все случаи прошли | все контракты прошли (контракты без проверок не считаются провалом) |
| 1 | был провал, **или** тест не создан (нет файла, нет `#[Subject]`, ноль случаев, класс не загрузился) | хотя бы один контракт `[!!]` |

«Не проверялось» никогда не выглядит успехом: пустой прогон возвращает 1.

## 2. Полная цепочка одного прогона

```
исходник с атрибутами
        │
        │  MakeTest::run()
        │  1. разбор аргумента, проверка файла
        │  2. token_get_all → имена классов файла
        │  3. загрузка файла (require_once) + база направления для app/World/**
        │  4. Reflection: #[Subject], #[Fixture], Gives/Has/Fails/Changes/Responds
        │  5. рендер шаблона test.tpl.php → app/Tests/**/…Test.php
        │  6. passthru(PHP_BINARY тест)
        ▼
сгенерированный тест
        │
        │  $run = new Runner('<источник>');
        │  $run->subject(...); $run->fixture(...); $run->gives(...); …
        │  $run->finish();
        ▼
Runner (один случай)
        │
        │  1. свежая песочница + фикстура
        │  2. Scaffold::begin() — сброс памяти, соединения, сессии
        │  3. сборка корня фабрикой, спуск по path до получателя
        │  4. before-шаги (подготовка состояния, именованные ссылки)
        │  5. вызов метода, сравнение с ожиданием
        │  6. [ok] / [fail] + причина
        ▼
отчёт + код возврата
```

Читателю важно понять три вещи, которые происходят **до** первого вызова:

1. Атрибуты читаются **один раз**, на этапе генерации. Дальше тест — обычный PHP-файл; никакого
   Reflection во время прогона нет (кроме `isStatic()` у метода получателя).
2. Ожидания из атрибутов переносятся в файл **литералами**. Поэтому в атрибутах допустимы только
   константные выражения — объект туда не записать (для этого есть токены).
3. Между генерацией и прогоном нет ручного шага: `make test:` сразу запускает созданный файл.

## 3. Карта файлов

| Путь | Роль |
|---|---|
| `core/System/Contract/*.php` | сами атрибуты: `Subject`, `Purpose`, `Param`, `Returns`, `Throws`, `Effect`, `Gives`, `Has`, `Fails`, `Changes`, `Responds`, `Fixture` + класс `Token` (не атрибут) |
| `core/System/Cli/MakeTest/MakeTest.php` | генератор: читает атрибуты, пишет тест, запускает его |
| `core/System/Cli/MakeTest/templates/test.tpl.php` | шаблон генерируемого теста |
| `core/System/Test/Runner.php` | исполнитель: `subject`, `fixture`, `gives`, `has`, `fails`, `changes`, `responds`, `finish`, `failures` |
| `core/System/Test/Scaffold.php` | строитель корня: `man`, `placePass`, `place`, `workspace`, `tool`, `dbase`, `dbaseRights`, `policy`, `aiAccess`, `aiDbase`, `ai`; песочница и общие на прогон актёры — `begin`, `sandbox`, `path`, `world`, `screen` |
| `core/System/Test/Areafold.php` | собирает раздел тем же путём, что роутинг (нужен `workspace`/`tool`) |
| `core/System/Test/Layers.php` | контракт границы «ядро не зовёт хелперы» (сам тоже прогоняется) |
| `core/System/Test/Invariants.php` | контракт обещаний сборки человека (final, readonly, запрет клона) |
| `core/System/Cli/RunTests/RunTests.php` | пакетный обход `core/**` |
| `app/Tests/**` | сгенерированные тесты |
| `core/System/Cli/Support/Support.php` | `render`/`put`: рендер шаблона и атомарная запись файла |

**Единственный читатель атрибутов в проекте — `MakeTest`.** Больше `getAttributes()` не вызывается
нигде: ни в CLI, ни в ядре. Это важно для понимания, что «документирующие» атрибуты ничего не проверяют.

## 4. Атрибуты

### 4.1 Кто что читает

| Атрибут | Куда ставится | Повторяемый | Читает генератор | Влияет на прогон |
|---|---|---|---|---|
| `Subject` | класс | нет | да | да — без него теста нет |
| `Fixture` | класс, метод | нет | да | да — файлы песочницы |
| `Gives` | метод | да | да | да — случай |
| `Has` | метод | да | да | да — случай |
| `Fails` | метод | да | да | да — случай |
| `Changes` | метод | да | да | да — случай |
| `Responds` | метод | да | да | да — случай |
| `Purpose` | класс, метод | нет | нет | нет |
| `Param` | метод | да | нет | нет |
| `Returns` | метод | нет | нет | нет |
| `Throws` | метод | да | нет | нет |
| `Effect` | метод | да | нет | нет |

Пять последних — **декларация для человека**. Они описывают метод и нужны, чтобы читать код без
докблоков; прогон их не смотрит и проверить не может. Это осознанно: атрибут, который «проверяется»
разбором, создавал бы иллюзию проверки.

Дальше каждый атрибут разобран отдельно: сигнатура, параметры с типами и умолчаниями, пример на каждый
вариант.

### 4.2 `Subject` — как собрать получателя

Ставится на класс, один раз. Четыре параметра, все позиционные:

```php
#[Subject(string $class, string $factory, array $args = [], string $path = '')]
```

| № | Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|---|
| 1 | `class` | `string` | — (обязателен) | класс-получатель: тот, чьи методы проверяются. Пишется `X::class`, строкой не пишется |
| 2 | `factory` | `string` | — (обязателен) | чем построить **корень** — объект, от которого начинается спуск |
| 3 | `args` | `array` | `[]` | аргументы фабрики: константы и токены |
| 4 | `path` | `string` | `''` | цепочка публичных свойств через `->` от корня до получателя; пусто — получатель и есть корень |

Те же четыре можно писать по именам: тогда видно, что чему, и не надо считать запятые.

```php
#[Subject(Head::class, factory: 'Scaffold::man', path: 'head')]   // args остался по умолчанию
```

**Пример, в котором занят каждый параметр.** По строке на параметр, в комментарии — что именно задано.
Ниже каждый параметр разобран отдельно, со своими примерами.

```php
#[Subject(Path::class, 'new')]                                 // 1 и 2; args = [], path = ''
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]    // 3: имя файла прав
#[Subject(Head::class, 'Scaffold::man', [], 'head')]           // 4: путь в один шаг
#[Subject(Hands::class, 'Scaffold::man', [], 'body->hands')]   // 4: путь в два шага
#[Subject(File::class, 'in', ['@sandbox'])]                    // 3: токен вместо литерала
```

#### Параметр `class` — что именно проверяем

Класс, методы которого вызывают случаи. Пишется `X::class`: строку собирает компилятор, поэтому
переименование класса не оставит в контракте мёртвую строку.

```php
#[Subject(Path::class, 'new')]                                // проверяем Path
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]   // проверяем Dbase
```

`class` не сверяется с классом-носителем атрибута: случаи берутся из носителя, а вызов идёт в `class`.
Держать их разными незачем — расхождение проявится провалом на несуществующем методе.

#### Параметр `factory` — чем построить корень

Корень — объект, от которого начинается спуск по `path`. Фабрика вызывается **один раз на случай**, и
результат кэшируется: `@subject` и вызов метода работают с одним и тем же объектом (6.1).

Три формы, различаются записью.

**Форма 1 — `'new'`.** Класс берётся из параметра `class`, вызывается его конструктор.

| Что стоит в `factory` | Что будет вызвано |
|---|---|
| `'new'` | `new <класс из class>(...args)` |

```php
#[Subject(Path::class, 'new')]           // new Path()
#[Subject(Screen::class, 'new', [])]     // new Screen() — то же самое, пустые args выписаны явно
```

**Форма 2 — `'метод'`.** Статический метод **самого класса получателя**: имя класса не пишется, он
берётся из `class`.

| Что стоит в `factory` | Что будет вызвано |
|---|---|
| `'метод'` | `<класс из class>::метод(...args)` |

```php
#[Subject(Memory::class, 'up', [])]                             // Memory::up()
#[Subject(DbaseSpelling::class, 'fromDeclaration', ['public.test_table', 'dbase.json'])] // DbaseSpelling::fromDeclaration('public.test_table', 'dbase.json')
```

**Форма 3 — `'Класс::метод'`.** Статический метод другого класса — чаще всего строитель из `Scaffold`.

| Что стоит в `factory` | Что будет вызвано |
|---|---|
| `'Класс::метод'` | `<Класс>::метод(...args)` |

```php
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]        // Scaffold::dbase('dbase.json')
#[Subject(Place::class, 'Maws\System\Test\Scaffold::place', ['Public/Home'])]  // полное имя класса
#[Subject(Tools::class, 'Maws\World\System\Tools::of', ['@sandbox/ok', 'Public/Home'])]  // не Scaffold
```

Имя класса без `\` разворачивается в пространство прогона: `'Scaffold::man'` →
`Maws\System\Test\Scaffold::man`. Полное имя работает так же — и только оно однозначно, если в проекте
есть свой `Scaffold`.

#### Параметр `args` — аргументы фабрики

Массив уходит в вызов распакованным (`...$args`): число и порядок — как в сигнатуре фабрики, имена не
передаются.

| Что можно | Пример | Чем становится |
|---|---|---|
| литерал | `['dbase.json']` | строка `'dbase.json'` |
| число | `[200, 'ok']` | `200` и `'ok'` |
| константа класса | `[self::CONFIG]` | значение константы |
| токен | `['@sandbox']` | каталог песочницы текущего случая |
| токен с путём | `['@sandbox/ok']` | файл `ok` внутри песочницы |
| пусто | `[]` | вызов без аргументов |

```php
#[Subject(Date::class, 'fromArray', [self::CONFIG])]    // константа класса
#[Subject(File::class, 'in', ['@sandbox'])]             // каталог песочницы
#[Subject(Tools::class, 'Maws\World\System\Tools::of', ['@sandbox/ok', 'Public/Home'])]  // два аргумента
```

Токены разворачиваются заново на каждый случай (раздел 5): `'@sandbox'` в объявлении — не строка, а
«каталог текущего случая». Выражений и вызовов здесь быть не может: атрибут обязан быть константным.

#### Параметр `path` — от корня до получателя

Строка делится по `->`; каждый сегмент читается как **публичное свойство** текущего объекта, напрямую,
без вызовов методов. Спуск начинается с того, что вернула фабрика.

**Пусто — получатель и есть корень.**

| Что стоит в `path` | Куда придём |
|---|---|
| `''` | `Man` — тот объект, что вернула фабрика |

```php
#[Subject(Man::class, 'Scaffold::man')]      // корень Man, он же получатель
```

**Один шаг — вложенный орган.**

| Что стоит в `path` | Куда придём |
|---|---|
| `'head'` | `Man->head` → `Head` |
| `'legs'` | `Man->legs` → `Legs` |

```php
#[Subject(Head::class, 'Scaffold::man', [], 'head')]
#[Subject(Legs::class, 'Scaffold::man', [], 'legs')]
```

**Два шага — через тело.**

| Что стоит в `path` | Куда придём |
|---|---|
| `'body->head'` | `Man->body->head` → `Head`, тот же объект, что `Man->head` |
| `'body->hands'` | `Man->body->hands` → `Hands` |

```php
#[Subject(Head::class, 'Scaffold::man', [], 'body->head')]    // длинная дорога к тому же Head
#[Subject(Hands::class, 'Scaffold::man', [], 'body->hands')]  // своего контракта у Hands пока нет
```

Правила разбора:

- свойство читается прямым обращением, поэтому приватное даёт
  `Error: Cannot access private property` и провал случая — «нет свойства» здесь не бывает (6.4);
- пустые сегменты пропускаются: `'head->'` — то же, что `'head'`;
- у статического метода получателя `path` не используется: корень не строится (6.1);
- существование свойства при сборке не проверяется: опечатка в имени даёт
  `Warning: Undefined property` и провал случая, а не отказ объявления (6.2).

#### Ошибки объявления

| Ситуация | Что будет |
|---|---|
| `#[Subject]` на одном классе объявлен дважды | `Error: Attribute "…\Subject" must not be repeated` — PHP отказывает при разборе атрибута, тест не создаётся |
| класс из `class` не объявлен в файле | отказывает генератор: «Класс источника не объявлен: …», тест не создан, код 1. Фабрика роли не играет — в том числе `Scaffold::…`. `TestMisuse` «класс … не найден…» — только в тесте, написанном руками, и в сгенерированном, чей класс исчез позже |
| фабрика `'Scaffold::метод'`, а класса фабрики нет | `TestMisuse`: «фабрика … не найдена: нет класса …» |
| в `path` нет такого свойства | `Warning: Undefined property`, затем провал случая (`TypeError` при возврате) |

```php
#[Subject(Path::class, 'new')]
#[Subject(Path::class, 'new')]   // Error: Attribute "Maws\System\Contract\Subject" must not be repeated
```

Остальные проверки сборки — в 6.2.

Если в файле несколько классов с `#[Subject]`, генератор сделает блок для каждого — это допустимо, но на
практике так не пишут.

### 4.3 `Purpose` — зачем существует

```php
#[Purpose(string $text)]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `text` | `string` | — (обязателен) | одна фраза: что делает метод или зачем существует класс |

Параметр один, а мест два — и фраза в них разная.

На классе — зачем он существует:

```php
#[Purpose('Человек: тело с органами и доступ к миру через них.')]
final class Man
```

На методе — что он делает:

```php
#[Purpose('Приводит путь к одному виду: прямые слэши, без «.» и лишних «..».')]
public static function normalize(string $path): string
```

Без пересказа реализации и без «возвращает строку» — это видно в сигнатуре. Не повторяется.

### 4.4 `Param` — параметр метода

```php
#[Param(string $name, string $type, string $note = '')]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `name` | `string` | — (обязателен) | имя как в сигнатуре |
| `type` | `string` | — (обязателен) | тип **строкой** (`'string'`, `'string\|false'`, `'array'`) — описание, а не проверка |
| `note` | `string` | `''` | уточнение смысла; можно не писать, если имя говорит само |

Ставится по разу на параметр, в порядке сигнатуры. Повторяемый.

**Пример: атрибуты и сигнатура рядом.** Один `Param` — один параметр, слева направо, как в методе:

```php
#[Param('path', 'string', 'путь относительно корня')]
#[Param('content', 'string', 'что записать')]
public static function write(string $path, string $content): void
```

**`note` — необязателен.** Если имя говорит само, его не пишут; если без пояснения нельзя — пишут:

```php
#[Param('bytes', 'int')]                              // «байты» — уточнять нечего
#[Param('mode', 'string', 'r — чтение, w — запись')]   // а здесь пояснение обязательно
```

**`type` — строка, а не проверка.** С сигнатурой её никто не сверяет: `'string'` здесь значит «я
утверждаю, что тут строка», и читает это человек. Опечатка в типе не поймается ничем — поэтому тип
пишут копией из сигнатуры.

### 4.5 `Returns` — что возвращает

```php
#[Returns(string $type, string $note = '')]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `type` | `string` | — (обязателен) | тип **строкой**, как в `Param` |
| `note` | `string` | `''` | что именно значит значение: когда `false`, что в пустом случае |

**Пример с пояснением** — когда у значения есть второе дно:

```php
#[Returns('string|false', 'содержимое или false, если файла нет')]
public function read(string $path): string|false
```

`false` здесь не «ошибка», а «файла нет» — и это записано, потому что из типа не видно.

**Пример без пояснения** — когда тип говорит всё:

```php
#[Returns('bool')]
public function exists(string $path): bool
```

Для `void` **не ставится**: тип виден в сигнатуре. Не повторяется.

### 4.6 `Throws` — когда бросает

```php
#[Throws(string $exception, string $when = '')]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `exception` | `string` | — (обязателен) | класс исключения; пишется `X::class` |
| `when` | `string` | `''` | условие отказа одной фразой: при каком входе бросает |

По разу на каждый случай отказа. Повторяемый.

**Пример: два отказа — две строки.**

```php
#[Throws(FileMisuse::class, 'путь абсолютный, выходит за корень или ведёт за него через ссылку')]
#[Throws(FileFailure::class, 'файл есть, но не читается')]
public function read(string $path): string|false
```

**`when` — это условие, а не пересказ имени класса.** «Файл есть, но не читается» говорит, при каком
входе бросает; «FileFailure» говорит только название. Поэтому `when` пишут всегда — кроме случаев, где
условие очевидно из одного имени.

`Throws` описывает **весь** набор отказов метода; конкретные вызовы, которые обязаны упасть, задаёт
`Fails`.

### 4.7 `Effect` — внешние эффекты

```php
#[Effect(string $kind)]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `kind` | `string` | — (обязателен) | одна из констант `Effect::*` — что метод делает с внешним миром |

Что бывает в `kind`:

| Константа | Значение |
|---|---|
| `Effect::NONE` | эффектов нет |
| `Effect::DB_CONNECT` | открывает соединение с базой |
| `Effect::DB_READ` | читает базу |
| `Effect::DB_WRITE` | пишет в базу |
| `Effect::DB_UNGUARDED` | идёт в базу мимо стража (дверной метод) |
| `Effect::FS_READ` | читает файлы |
| `Effect::FS_WRITE` | пишет файлы |
| `Effect::HTTP` | HTTP-обмен: входящий запрос или исходящий вызов чужого сервиса |
| `Effect::SCREEN` | формирует/отправляет ответ |
| `Effect::LOG` | пишет журнал |
| `Effect::INPUT` | читает входные данные запроса (`$_POST` / `$_GET`) |

**Пример: одно действие.**

```php
#[Effect(Effect::FS_READ)]
public function read(string $path): string|false
```

**Пример: ничего не трогает.** Ставят явно, чтобы «эффектов нет» было видно, а не подразумевалось:

```php
#[Effect(Effect::NONE)]
public static function normalize(string $path): string
```

**Пример: действий два.** Атрибут повторяемый — по строке на каждое:

```php
#[Effect(Effect::FS_READ)]
#[Effect(Effect::FS_WRITE)]
public function copy(string $from, string $to): void
```

`Effect` — утверждение автора для читающего: прогон не смотрит в тело метода и проверить это не может.

### 4.8 `Gives` — успешный вызов

```php
#[Gives(array $args, mixed $expect, array $before = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `args` | `array` | — (обязателен) | аргументы вызова: константные выражения и токены |
| `expect` | `mixed` | — (обязателен) | ожидаемое значение |
| `before` | `array` | `[]` | шаги подготовки до вызова (необязательно) |

**Пример простой: аргументы и ожидание.**

```php
#[Gives(['/a/./b/../c//'], '/a/c')]
#[Gives([''], '')]
public static function normalize(string $path): string
```

**Пример с токеном в ожидании** — когда вернуть надо объект, а записать объект в атрибут нельзя:

```php
#[Gives(['SELECT 1'], Token::STATEMENT)]   // ждём PDOStatement, а не значение
```

**Пример с подготовкой.** `before` — список шагов; шаг это `[путь, аргументы]`:

```php
#[Gives([], true, before: [['beginTransaction', []]])]
```

Шаг `['beginTransaction', []]` читается так: «дойти от корня до метода `beginTransaction` и вызвать его
без аргументов». Путь разрешается от корня — как в `Changes` (4.11).

Сравнение — **строгое** (`===`), с тремя исключениями (см. §9.1): `Token::STATEMENT`, `Token::SUBJECT`
и путь песочницы в ожидании.

### 4.9 `Has` — вызов вернул массив с нужными ключами

```php
#[Has(array $args, array $keys, array $before = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `args` | `array` | — (обязателен) | аргументы вызова: константные выражения и токены |
| `keys` | `array` | — (обязателен) | ключи, которые обязаны быть в результате |
| `before` | `array` | `[]` | шаги подготовки до вызова |

Случай проверяет **только наличие ключей**. Значения не сверяются вовсе, лишние ключи не мешают: чем
наполнена строка и какие колонки появились в таблице — право того, кто ведёт данные, а не предмет
контракта. Провал будет, если метод вернул не массив или если объявленного ключа в результате нет.

**Пример: строка раздела.**

```php
#[Has([], ['id', 'name', 'place_id', 'main', 'parent_id', 'url'],
       before: [['head->getWorkspace', ['']]])]
public function pageMeta(): array
```

Случай говорит: пустой адрес ведёт в раздел, и у раздела есть эти шесть колонок. Переименовали главную
или заполнили `og_*` — случай зелёный; убрали из `areas` колонку `url` — красный: «нет ключей url».

**Чем отличается от `Gives`.** `Gives` сверяет значение целиком, поэтому массив в ожидании пришлось бы
выписать со всеми значениями — и случай краснел бы от правки в админке. `Has` берёт от `Gives` вызов и
подготовку, а от результата — форму.

### 4.10 `Fails` — отказной вызов

```php
#[Fails(array $args, string $exception, array $before = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `args` | `array` | — (обязателен) | аргументы вызова |
| `exception` | `string` | — (обязателен) | класс ожидаемого исключения; пишется `X::class` |
| `before` | `array` | `[]` | шаги подготовки |

**Пример простой: вход, который обязан упасть.**

```php
#[Fails(['../123'], PathFailure::class)]      // normalize('../123') — отказ
#[Fails(['/etc/passwd'], FileMisuse::class)]  // read('/etc/passwd') — отказ
```

**Пример с подготовкой** — та же форма шага, что в `Gives` (4.8):

```php
#[Fails([], DbaseMisuse::class, before: [['beginTransaction', []]])]
```

**Класс сверяется точно** — `get_class($e) === $exception`. Если метод бросает `FileMisuse`, а в атрибуте
написано `MawsMisuse` (его родитель), случай **провалится**: подкласс не подойдёт. Сообщение не
сравнивается вовсе — важен только класс.

### 4.11 `Changes` — мутирующий вызов

```php
#[Changes(array $args, array $then, array $before = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `args` | `array` | — (обязателен) | аргументы вызова |
| `then` | `array` | — (обязателен) | список проверок **после** вызова: `[путь, аргументы, ожидание]` |
| `before` | `array` | `[]` | шаги подготовки |

**Пример: проверка методом.**

```php
#[Changes(['new.txt', 'привет'], [['read', ['new.txt'], 'привет']])]
```

Шаг `['read', ['new.txt'], 'привет']` читается так: «от корня дойти до `read`, вызвать с `['new.txt']`,
ждать `'привет'`».

**Пример: метод без аргументов** — второй элемент пустой, вызов без аргументов:

```php
#[Changes([], [['inTransaction', [], true]])]
```

**Пример: проверка свойством, а не методом** — сначала подойти к месту, потом войти:

```php
#[Changes(['Public/Home'], [['head->currentLocation', [], 'Public/Home']],
          before: [['legs->walk', ['Public/Home']]])]
```

**Третий элемент можно не писать** — тогда ожидание `null`:

```php
#[Changes([], [['inTransaction', []]])]   // ждём, что inTransaction() вернёт null
```

Путь в `then` разрешается **от корня** (не от получателя): `'head->currentLocation'` — свойство `head`
у корня, затем `currentLocation` у головы. Последний шаг может быть публичным свойством или публичным
методом; метод вызывается с аргументами из второго элемента.

### 4.12 `Responds` — место ответило само

```php
#[Responds(array $args, string $body, int $status = 200, array $before = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `args` | `array` | — (обязателен) | аргументы вызова |
| `body` | `string` | — (обязателен) | ожидаемое тело, **байт в байт** |
| `status` | `int` | `200` | ожидаемый код ответа |
| `before` | `array` | `[]` | шаги подготовки |

**Пример: перенаправление** — тела нет, код 301:

```php
#[Responds(['home'], '', 301)]
```

**Пример: тело и код по умолчанию** — 200:

```php
#[Responds(['<h1>Ответ места</h1>'], '<h1>Ответ места</h1>')]
```

**Пример: тело — JSON.** Сравнение байт в байт, поэтому пробелы и порядок ключей в ожидании должны
совпадать с тем, что напечатает метод:

```php
#[Responds([['ok' => true]], '{"ok":true}')]   // не '{"ok": true}' — пробел сделает тело другим
```

`before` — те же шаги подготовки, что в `Gives` (4.8).

Ставится у методов, которые печатают тело и завершаются `ResponseSent` (`Response::send`,
`Response::json`, `Screen::screenInterface` с командой `redirect`). Прогон ловит `ResponseSent`,
забирает напечатанное из буфера и сверяет тело и `http_response_code()`.

### 4.13 `Fixture` — файлы песочницы

```php
#[Fixture(array $files = [])]
```

| Параметр | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `files` | `array` | `[]` | пары «путь внутри песочницы → содержимое»; пусто — «наследовать» (правило 2 ниже) |

Пары «путь внутри песочницы → содержимое». Путь относителен песочницы; вложенные каталоги создаются.
Атрибут можно ставить на класс (фикстура для всех случаев) и на метод (с этого места и дальше).

**Пример: один файл.**

```php
#[Fixture(files: ['read.txt' => 'привет'])]      // можно и без имени: #[Fixture(['read.txt' => 'привет'])]
```

**Пример: файл прав для базы.**

```php
#[Fixture(files: ['dbase.json' => '{"tables":["public.test_table"]}'])]
```

**Пример: несколько файлов и вложенные каталоги.**

```php
#[Fixture(files: [
    'plain/settings.json' => '{"tools": {"list": []}}',
    'bad-ttl/settings.json' => '{"tools": {"list": []}, "cache": {"ttl": "60"}}',
])]
```

`plain/` и `bad-ttl/` создаются сами: путь — относительный, каталоги под него дописываются.

Три правила, которые надо знать наизусть.

**1. Фикстура липкая.** `#[Fixture]` на методе действует на этот метод и на все следующие, пока
следующий не объявит свою. Это не «фикстура метода», а «с этого места и до конца файла».

```php
#[Fixture(files: ['read.txt' => 'привет'])]
public function first() {}     // песочница: read.txt

public function second() {}    // та же песочница: read.txt — объявления нет, а фикстура жива

#[Fixture(files: ['other.txt' => 'пока'])]
public function third() {}     // песочница сменилась: other.txt, read.txt больше нет
```

**2. `#[Fixture(files: [])]` — это «наследовать», а не «пустая песочница».** Пустой список отсекается
до сравнения и не сбрасывает предыдущую фикстуру.

```php
#[Fixture(files: ['read.txt' => 'привет'])]
public function first() {}     // read.txt

#[Fixture(files: [])]
public function second() {}    // read.txt — пустой список ничего не отменил
```

**3. Смена печатается один раз.** Если два метода подряд объявили одну и ту же фикстуру, второй вызов
`$run->fixture(...)` не появится.

```php
#[Fixture(files: ['read.txt' => 'привет'])]
public function first() {}     // в тесте есть $run->fixture([...])

#[Fixture(files: ['read.txt' => 'привет'])]
public function second() {}    // та же фикстура — второй строки в тесте нет
```

`Fixture` **не повторяемый**: второй такой атрибут на одном элементе — ошибка PHP
(«Attribute … must not be repeated») в момент генерации.

## 5. Токены и ссылки

`Maws\System\Contract\Token` — не атрибут, а держатель имён. Они подставляются туда, где объект
записать нельзя: в аргументы, в ожидание, в шаги `before` и `then`.

| Имя | Значение | Где работает | Что подставляет |
|---|---|---|---|
| `Token::SANDBOX` (`@sandbox`) | `'@sandbox'` | аргументы, ожидание | путь каталога песочницы текущего случая |
| `'@sandbox/путь'` | строка с префиксом | аргументы, ожидание | полный путь файла в песочнице |
| `Token::SUBJECT` (`@subject`) | `'@subject'` | аргументы, ожидание | сам получатель |
| `Token::WORLD` (`@world`) | `'@world'` | аргументы | карта мира прогона |
| `Token::SCREEN` (`@screen`) | `'@screen'` | аргументы | экран прогона |
| `Token::STATEMENT` (`@statement`) | `'@statement'` | **только ожидание** | ничего: означает «вернулось `PDOStatement`» |
| `'@имя'` | произвольная строка | аргументы | значение, привязанное шагом `before` с третьим элементом `имя` |

**Пример на каждый токен.** Слева — что стоит в атрибуте, в комментарии — что получит метод:

```php
#[Subject(File::class, 'in', ['@sandbox'])]    // каталог песочницы: File::in() принимает корень
#[Subject(Tools::class, 'Maws\World\System\Tools::of', ['@sandbox/ok', 'Public/Home'])]  // файл в песочнице
#[Gives([['X-A' => 'b']], Token::SUBJECT)]     // метод вернул $this — ждём тот же объект
#[Gives(['SELECT 1'], Token::STATEMENT)]       // ждём PDOStatement, а не значение
#[Gives(['@pass'], true, before: [['enterPlace', ['Public/Home'], '@pass']])]  // ссылка из подготовки
```

`@world` и `@screen` в контрактах ядра не встречаются: они подставляют карту мира и экран прогона —
нужны методу, который принимает их аргументом.

Разбор строки-аргумента (`Runner::value`):

```php
if (!is_string($arg) || !str_starts_with($arg, '@')) return $arg;

if (str_starts_with($arg, Token::SANDBOX . '/')) return Scaffold::path(substr($arg, strlen(Token::SANDBOX) + 1));
if ($arg === Token::SANDBOX) return Scaffold::sandbox();
if ($arg === Token::SUBJECT) return $this->subjectUp();
if ($arg === Token::WORLD)   return Scaffold::world();
if ($arg === Token::SCREEN)  return Scaffold::screen();

if (!array_key_exists($arg, $this->bindings)) throw new TestMisuse("ссылка {$arg} ни на что не указывает");

return $this->bindings[$arg];
```

Токены `@world` и `@screen` работают только в аргументах: в ожидании они не разворачиваются, и
сравнение свело бы строку с объектом. `@statement` — наоборот, только в ожидании: в аргументах он
попадёт в разбор ссылок и даст `TestMisuse` «ссылка @statement ни на что не указывает».

Именованные ссылки — механизм для случаев, когда подготовка возвращает объект, а записать его в
атрибут нельзя:

```php
#[Gives(['@pass'], true, before: [['enterPlace', ['Public/Home'], '@pass']])]
```

Третий элемент шага — имя; результат шага запоминается и доступен как `'@pass'` в аргументах этого
случая. Пример выше читается так: подготовка вызывает `enterPlace('Public/Home')`, запоминает результат
под именем `@pass`; затем проверяемый метод получает этот объект первым аргументом и должен вернуть
`true`. Привязки живут **в пределах одного случая**: перед каждым `bindings = []`.

В текущих контрактах ядра именованные ссылки не используются — есть только токены. Механизм при этом
реализован в `Runner::prepare` / `Runner::value` и работает.

## 6. Как строится получатель

### 6.1 Порядок

1. `Runner::run()` начинает случай: `Scaffold::begin($sandbox)`.
2. Смотрит через Reflection, **статический** ли метод получателя.
3. Статический — корень не строится, вызывается `Класс::метод(...)`.
4. Нестатический — строится корень (`rootUp()`), от него спуск по `path` (`subjectUp()`), затем
   выполняются `before`-шаги, и вызов идёт у полученного объекта.

Корень строится **один раз на случай** и кэшируется в `$this->root`: `subjectUp()` не пересобирает его
при каждом обращении, поэтому `@subject` и вызов метода работают с одним и тем же объектом.

**Пример: один случай целиком.** Объявление из `Man`:

```php
#[Changes(['Public/Home'], [['head->currentLocation', [], 'Public/Home']],
          before: [['legs->walk', ['Public/Home']]])]
public function enterPlace($place): PlacePass
```

Что прогон делает по шагам:

| Шаг | Что происходит |
|---|---|
| 1 | `Scaffold::begin(...)` — новая песочница, сброшены память, соединение, сессия |
| 2 | `enterPlace` нестатический — корень нужен |
| 3 | `rootUp()` → `Scaffold::man()` → `Man`; дальше корень берётся из кэша |
| 4 | `subjectUp()` с пустым `path` → тот же `Man` |
| 5 | `before`: `legs->walk('Public/Home')` — человек подходит к месту |
| 6 | вызов: `Man::enterPlace('Public/Home')` |
| 7 | `then`: `head->currentLocation` от **корня** — ждём `'Public/Home'` |

### 6.2 Проверки при сборке

| Ситуация | Что будет |
|---|---|
| `subject()` не вызван | `TestMisuse`: «фабрика не объявлена: сначала вызови $run->subject(...)» |
| фабрика `'метод'`, а класса нет в файле | ловит **генератор**, а не прогон: «Класс источника не объявлен: …», тест не создан, код 1. То же при `Scaffold::…`: генератор требует класс при любой фабрике. `TestMisuse` «класс … не найден…» — только для теста, написанного руками, и для сгенерированного, чей класс исчез позже |
| фабрика `'Scaffold::метод'`, а класса `Maws\System\Test\Scaffold` нет | `TestMisuse`: «фабрика … не найдена: нет класса …» |
| в `path` нет свойства | PHP выдаёт `Warning: Undefined property: Класс::$имя`, спуск возвращает `null`, и случай падает с `TypeError: … subjectUp(): Return value must be of type object, null returned` |
| в `path` приватное свойство | `Error: Cannot access private property Класс::$имя` — провал случая. `TestMisuse` для `path` не бывает: спуск идёт прямым обращением, без `has()` |

Проверки тут двух уровней, и путать их нельзя. Часть делает **генератор** — до того, как файл теста
появился: тогда печатается своё сообщение и команда выходит с кодом 1. Часть — `Runner`, уже во время
прогона: это и есть `TestMisuse`.

Все `TestMisuse` — это `MawsMisuse`: ошибка **объявления контракта**, а не проверяемого кода. Она
печатается как провал случая, но исправлять надо контракт.

**Пример на каждую ситуацию.**

```php
// 1. случай объявлен, а subject() не вызван
$run = new Maws\System\Test\Runner('…');
$run->gives('join', [], 'x');          // TestMisuse: фабрика не объявлена: сначала вызови $run->subject(...)

// 2. фабрика 'метод', а такого класса нет
#[Subject(Nope::class, 'build')]        // генератор: Класс источника не объявлен — тест не создан

// 3. фабрика ссылается на класс, которого нет
#[Subject(Path::class, 'Nope::build')]  // TestMisuse: фабрика Nope не найдена: нет класса …\Nope

// 4. опечатка в path
#[Subject(Head::class, 'Scaffold::man', [], 'haed')]   // Warning: Undefined property, затем TypeError
```

### 6.3 Статический метод и `before`

Если метод статический, а у случая есть `before`, прогон отказывает:

```php
throw new TestMisuse('подготовка до вызова неприменима к статическому методу');
```

Причина: `before` — это шаги **по корню** (свойства и методы объекта). У статического вызова корня нет,
и подготовке не к чему применяться. Молча проигнорировать `before` было бы хуже: случай проверял бы не
то состояние, о котором говорит объявление.

Следствие: `Changes` для статического метода тоже не работает — проверки `then` разрешаются от корня, а
корня нет. В отчёте это `TypeError: peek(): Argument #1 ($root) must be of type object, null given`.
`Gives`/`Fails`/`Responds` для статики работают нормально.

### 6.4 Путь (`path`) и `peek`

Один и тот же синтаксис `'->'` используется в трёх местах:

| Где | Что означает | Пример |
|---|---|---|
| `Subject::path` | от корня до получателя, только свойства | `'body->hands'` |
| шаг `before` / `then` | от корня до свойства или метода | `'legs->walk'`, `'head->currentLocation'` |
| `expect` | путей нет; только `@sandbox/…` | `'@sandbox/ok'` |

`Runner::peek()` разбирает путь так: все сегменты кроме последнего — **публичные свойства**; последний
— публичное свойство или публичный метод (тогда вызывается с аргументами шага). Приватное свойство
путём не видно: `property_exists` есть, а `isPublic()` — нет, и прогон скажет «нет свойства».

Это про шаги — `before` и `then`. Путь самого получателя (`Subject::path`) идёт другой дорогой:
`Runner::subjectUp()` читает свойство напрямую, без `has()`, поэтому приватное свойство там даёт
`Error: Cannot access private property`, а опечатка — `Warning` и `TypeError` (см. §6.2).
`TestMisuse` для `Subject::path` не бывает: он стережёт шаги, а не спуск к получателю.

## 7. Песочница и изоляция

### 7.1 Каталог

```php
$this->sandboxRoot = sys_get_temp_dir() . '/maws-tests-' . getmypid();
$dir = $this->sandboxRoot . '/' . $this->case;   // отдельный каталог на каждый случай
```

Песочница создаётся заново **для каждого случая**: номер случая в пути, файлы фикстуры пишутся с нуля.
Случай, который пишет файлы, не влияет на следующий. Если файл фикстуры не записался — `TestMisuse`
(«не записать файл песочницы …»), и случай падает.

**Пример: три случая — три каталога.**

```
<временный каталог>/maws-tests-12345/1/read.txt
<временный каталог>/maws-tests-12345/2/read.txt
<временный каталог>/maws-tests-12345/3/read.txt
```

Имя файла в каждом случае одно и то же, а файлы разные: второй случай не увидит того, что записал первый,
даже если фикстура у них одинаковая.

Путь наружу отдаётся двумя способами: `Token::SANDBOX` (каталог) и `'@sandbox/имя'` (файл). В
`Subject`-фабрику обычно передают именно `'@sandbox'`:

```php
#[Subject(File::class, 'in', ['@sandbox'])]
```

### 7.2 Что сбрасывается между случаями

`Scaffold::begin()` делает три вещи:

```php
Memory::$instance = null;   // память головы — синглтон на процесс
DbConnector::reset();       // соединение общее: открытая транзакция пережила бы случай
Session::reset();           // $_SESSION и её файл пережили бы случай
```

Плюс `Runner::run()` сбрасывает `http_response_code(200)` — код ответа это состояние процесса, и случай,
который его выставил, иначе «протёк» бы в следующий.

**Что не сбрасывается:** `Scaffold::$world` и `Scaffold::$screen` — они создаются один раз на процесс.
Именно поэтому каждый контракт запускается отдельным процессом: внутри файла мир и экран общие, между
файлами — нет.

### 7.3 Вывод проверяемого места

Вывод перехватывается дважды:

- внешний `ob_start()` в конструкторе `Runner` — чтобы отчёт не считался «уже отправленным» и
  `header()` в проверяемом коде не падал с «headers already sent»;
- внутренний `ob_start()` вокруг каждого случая — чтобы `echo` места не попадал в отчёт.

Внутренний буфер читает только `responds` (через `ob_get_contents()`), после чего буфер уничтожается
(`ob_end_clean()`). Для остальных видов случаев напечатанное просто пропадает.

### 7.4 Уборка

`finish()` удаляет `sys_get_temp_dir()/maws-tests-<pid>` целиком, рекурсивно, только если путь содержит
`maws-tests-` и каталог существует. Уборка идёт и при провале: `finish()` вызывается всегда, потому что
это последняя строка шаблона.

Если процесс убит до `finish()`, каталог останется — это временный мусор ОС, а не данные проекта.

## 8. Один случай по шагам

Точный порядок `Runner::run()`:

1. `$this->case++`; `$this->bindings = []`; `$this->root = null`.
2. `http_response_code(200)`.
3. `Scaffold::begin($this->freshSandbox())` — каталог случая + файлы фикстуры + сброс памяти,
   соединения, сессии.
4. `ReflectionMethod::isStatic()`.
5. Статический:
   - если `before !== []` → `TestMisuse` (провал случая);
   - `$call = fn () => Класс::$method(...значения)`;
   - корень остаётся `null`.
   Нестатический:
   - `$root = rootUp()` — сборка фабрикой (один раз);
   - `$target = subjectUp()` — спуск по `path`;
   - `prepare($root, $before)` — шаги подготовки, привязки;
   - `$call = fn () => $target->$method(...значения)`.
6. `ob_start()` — буфер вывода места.
7. Выполняется проверка (замыкание конкретного вида случая).
8. `ob_end_clean()` — в `finally`, чтобы буфер снялся даже при исключении.
9. Приговор:
   - `null` → `passed++`, печать `  [ok]   <метка>`;
   - строка → `failed++`, печать `  [fail] <метка>` и второй строкой причину.

Исключения, пойманные снаружи проверки:

| Исключение | Что печатается |
|---|---|
| `ResponseSent` | «место ответило само (ResponseSent): вывод тестом не проверяется» — провал |
| любое `Throwable` | `КлассИсключения: сообщение` — провал |

Первое важно: если метод, у которого нет `Responds`, вдруг отправил ответ и бросил `ResponseSent`,
случай **падает**, а не зеленеет. Иначе «место ответило само» выглядело бы как успешный вызов.

## 9. Семантика пяти видов случаев

### 9.1 `Gives` — сравнение значения

```php
$got = $call();
return $this->fits($got, $expect) ? null : 'получено ' . show($got) . ', ожидалось ' . want($expect);
```

`fits()` — три особых случая и строгое равенство:

| Ожидание | Проверка |
|---|---|
| `Token::STATEMENT` | `$got instanceof \PDOStatement` |
| `Token::SUBJECT` | `$this->root !== null && $got === $this->subjectUp()` |
| `Token::SANDBOX` или `'@sandbox/…'` | ожидание разворачивается в реальный путь, затем `===` |
| всё остальное | `$got === $expect` |

Следствия строгого сравнения:

- `1` и `'1'` — разные значения;
- `null` и `false` — разные;
- массивы сравниваются `===`: порядок ключей и типы значений важны;
- объект вернуть нельзя — сравнение по идентичности не сработает, а записать объект в атрибут
  невозможно. Для объектов есть `Token::SUBJECT` (тот же объект) и `Token::STATEMENT`.

`Token::SUBJECT` в ожидании работает только для нестатических методов: у статического корня нет, и
проверка даст провал с текстом «получено 1, ожидалось тот же объект» — значение при этом верное, не
сходится именно обещание «тот же объект».

### 9.2 `Has` — сравнение ключей

```php
$got = $call();

if (!is_array($got)) return 'получено … , ожидался массив';

$missing = array_values(array_diff($keys, array_keys($got)));
return $missing === [] ? null : 'нет ключей … , в результате …';
```

Сверяется разность: объявленные ключи минус ключи результата. Пустая разность — зелёный. Отсюда:

- значения не участвуют в сравнении вообще — ни типы, ни пустота, ни порядок;
- лишние ключи проходят молча: новая колонка в таблице случай не ломает;
- порядок объявленных ключей на результат не влияет — `array_diff` смотрит только на наличие;
- пустой массив провалится на первом же объявленном ключе.

### 9.3 `Fails` — сравнение исключения

```php
try {
    $call();
} catch (\Throwable $e) {
    return get_class($e) === $exception ? null
        : 'получено ' . get_class($e) . ': ' . $e->getMessage() . ', ожидалось ' . $exception;
}

return 'исключения не было, ожидалось ' . $exception;
```

- Ловится **любой** `Throwable`, включая `Error` (например, `TypeError`).
- Сравнивается **точный класс**: `PathFailure` не подойдёт, если объявлен `MawsException`.
- Сообщение и код не сверяются: `Fails` отвечает на вопрос «тем ли классом отказал», а не «тем ли
  текстом».
- Если метод не бросил ничего — провал, даже если вернул «неправильное» значение.

### 9.4 `Changes` — состояние после вызова

```php
$call();

foreach ($then as $step) {
    $got  = $this->peek($root, $step[0], $step[1] ?? []);
    $want = $step[2] ?? null;

    if ($got !== $want) {
        return $step[0] . ' = ' . show($got) . ', ожидалось ' . show($want);
    }
}
```

- Сначала вызов (его результат не проверяется), потом все шаги `then` **по порядку**.
- Шаг — `[путь, аргументы, ожидание]`; аргументы и ожидание можно опустить, тогда это `[]` и `null`.
- Сравнение строгое (`!==`), как в `Gives`.
- Первое расхождение обрывает случай: в отчёте будет путь и оба значения.
- Путь разрешается от **корня**, а не от получателя.

### 9.5 `Responds` — тело и код ответа

```php
try {
    $call();
} catch (ResponseSent $e) {
    $got = $output();                       // ob_get_contents()

    if ($got !== $expect) return 'тело …, ожидалось …';

    $code = http_response_code();

    return $code === $status ? null : 'код ответа …, ожидался …';
}

return 'метод вернул управление, ожидался ResponseSent';
```

- Метод обязан бросить `ResponseSent`. Вернул управление — провал, даже если напечатал ровно то, что
  ждали: значит, ответ не был завершён, и в бою сцена продолжила бы работу.
- Тело сверяется **байт в байт**, без нормализации переводов строк и пробелов.
- Код берётся из `http_response_code()`, который до случая сброшен в 200. Поэтому `status: 200`
  означает и «выставлен явно», и «не выставлен вовсе» — в веб-SAPI это одно и то же.
- `headers()` в CLI не отправляются, но `http_response_code()` работает, поэтому проверка кода
  возможна без HTTP-сервера.

### 9.6 `before` — подготовка

Шаг: `[путь, аргументы]` или `[путь, аргументы, имя]`.

- Выполняется **до** вызова, для всех пяти видов случаев.
- Путь разрешается от корня тем же `peek`: свойства и публичные методы.
- Возвращённое значение с именем попадает в `bindings` и доступно как `'@имя'` в аргументах этого
  случая.
- Ошибка в шаге (нет свойства, метод бросил) — провал случая с текстом ошибки.
- Для статического метода `before` запрещён целиком.

### 9.7 Что считается провалом

| Причина | Текст в отчёте |
|---|---|
| значение не совпало | `получено X, ожидалось Y` |
| объявленного ключа нет | `нет ключей K, в результате [ключи]` |
| вернулось не массив | `получено X, ожидался массив` |
| исключение не то | `получено Класс: сообщение, ожидалось Класс` |
| исключения не было | `исключения не было, ожидалось Класс` |
| тело ответа не то | `тело X, ожидалось Y` |
| код ответа не тот | `код ответа X, ожидался Y` |
| метод не завершил ответ | `метод вернул управление, ожидался ResponseSent` |
| ответ отправлен там, где не ждали | `место ответило само (ResponseSent): вывод тестом не проверяется` |
| состояние после вызова не то | `путь = X, ожидалось Y` |
| ошибка объявления контракта | `Maws\System\Test\Exception\TestMisuse: …` |
| любое другое исключение | `Класс: сообщение` |

**Как выглядит успех по каждому виду** — пять строк, по одной на вид:

```
  [ok]   Demo::twice([2]) → 4
  [ok]   Demo::meta([]) → ключи
  [ok]   Demo::twice(["x"]) → отказ DemoMisuse
  [ok]   Demo::reset([]) → состояние
  [ok]   Demo::redirect(["home"]) → ответ
```

Хвост метки и есть вид случая: значение, ключи, отказ, состояние, ответ.

## 10. Отчёт

### 10.1 `Runner` (один контракт)

```
MAWS — прогон контракта
Источник: core/System/Helpers/Path/Path.php
Получатель: Maws\System\Helpers\Path\Path

  [ok]   Path::join(["a", "b", "c"]) → "a/b/c"
  [ok]   Path::join(["/a/", "/b"]) → "/a/b"
  …
  [ok]   Path::normalize(["../123"]) → отказ PathFailure

Итог: 42 проверок, 42 прошло, 0 провалено
```

Метка случая строится так: `КороткоеИмяКласса::метод(аргументы) → ожидание`.

| Вид | Хвост метки |
|---|---|
| `gives` | `→ <ожидание>` |
| `fails` | `→ отказ <Класс>` |
| `changes` | `→ состояние` |
| `responds` | `→ ответ` |

Значения печатаются через `show()`: строки — в JSON-виде (`"a/b/c"`, слэши и кириллица не экранируются),
массивы — `[1, 2]` или `["k" => 1]` (ключ печатается тем же `show()`, поэтому в двойных кавычках),
`true`/`false`/`null` как есть, объект — `объект Класс`.

Провал занимает две строки:

```
  [fail] Demo::twice([2]) → 5
         получено 4, ожидалось 5
```

Если случаев не было вовсе:

```
Проверок нет.
```

и код возврата 1. Это защита от «зелёного пустого прогона».

`Runner::failures()` возвращает число провалов — часть публичного API исполнителя; штатный отчёт
обходится без него.

### 10.2 `MakeTest` (генерация + запуск)

```
Создан тест: app/Tests/Core/System/Helpers/Path/PathTest.php
Проверок в контракте: 42

MAWS — прогон контракта
…
```

Строка «Проверок в контракте:» называет **собранное** — сколько случаев попало в тест. За полнотой
следит не она, а генератор: он судит имена атрибутов (опечатка, забытый `use`) и считает случаи дважды —
по тексту и отражением, — отказывая при расхождении или атрибуте не на методе (§14, ловушка 1). Число
остаётся для человека — по нему видно, что тест неожиданно похудел.

### 10.3 `RunTests` (пакет)

```
MAWS — пакетный прогон контрактов
Источников: 50

[ok]   core/Ai/Ai.php — 9 проверок, 0 провалено
[ok]   core/Ai/System/AiAccess.php — 2 проверок, 0 провалено
…
[--]   core/… — объявлен, проверок нет
[!!]   core/… — 12 проверок, 3 провалено

=== core/…
  [fail] …
         получено …, ожидалось …

Итог: контрактов 50, прошло 48, провалено 1, без проверок 1
```

| Метка | Значение |
|---|---|
| `[ok]` | код 0 и в выводе нашлась сводка |
| `[--]` | `#[Subject]` есть, а случаев нет: файл ничего не проверяет — не провал, но и не успех |
| `[!!]` | всё остальное: провал, фатал, нет базы, источник не загрузился |

Сводка из вывода вытаскивается регулярным выражением
`~Итог:\s*(\d+)\s+проверок,\s*(\d+)\s+прошло,\s*(\d+)\s+провалено~u`. Если сводки нет (например,
процесс упал на фатале), `[!!]` печатается без чисел, а в разборе — весь вывод.

Разбор провалов (`reasons`) оставляет только строки `[fail]` и «Нет живой базы» плюс следующую строку
причины. Если не нашлось ни одной — печатает вывод целиком, чтобы причина не осталась за кадром.

На код возврата эти метки влияют по-разному: `[--]` провалом не считается, `[!!]` — считается.

## 11. Как рождается файл теста

### 11.1 Разбор источника

`MakeTest` не подключает файл, чтобы узнать имена классов: `token_get_all()` читает текст и собирает
`T_NAMESPACE` и `T_CLASS`. `T_CLASS`, перед которым стоит `T_DOUBLE_COLON`, пропускается — иначе
`Foo::class` дал бы ложное объявление.

Затем файл загружается (`require_once`). Для источника из `app/World/{Направление}/` сначала грузится
база направления:

```php
\Maws\World\World::loadDirection('{Направление}');
```

Без этого класс места не загрузится: он наследует `{Направление}Workspaces`, а мира, который её обычно
грузит, в CLI нет. Ошибка загрузки запоминается и печатается как «Источник не загрузился: …».

### 11.2 Порядок случаев

Методы обходятся **в порядке объявления**, конструктор и деструктор пропускаются. Внутри метода порядок
жёсткий и не зависит от того, как атрибуты записаны в коде:

1. `Gives`
2. `Has`
3. `Fails`
4. `Changes`
5. `Responds`

Атрибуты одного вида сохраняют порядок объявления.

### 11.3 Липкая фикстура в генераторе

```php
$current = <фикстура класса>;

foreach ($methods as $method) {
    $files = <фикстура метода>;

    if ($files !== [] && $files !== $current) {
        $cases[] = '$run->fixture(' . literal($files) . ');';
        $current = $files;
    }

    …случаи метода…
}
```

Отсюда: фикстура класса печатается один раз в начале блока; фикстура метода — только при смене; пустая
фикстура не печатается вовсе.

### 11.4 Литералы

Значения атрибутов переносятся в файл через `literal()`:

- массив печатается в строку, если он короткий (до 88 символов с учётом отступа), иначе — блочно, по
  элементу на строку;
- строка — в одинарных кавычках, `\` и `'` экранируются;
- `null`, `true`, `false`, целые и дробные — как есть;
- всё остальное (объект, ресурс) — `null`. Поэтому объект в атрибут записать нельзя: он превратится в
  `null` молча. Для объектов есть токены.

### 11.5 Шаблон

```php
$root = __DIR__;

for ($i = 0; $i < 20 && !is_file($root . '/maws.php'); $i++) {
    $root = dirname($root);
}

if (!is_file($root . '/maws.php')) {
    fwrite(STDERR, 'Не найден корень проекта выше ' . __DIR__ . "\n");
    exit(1);
}

require_once $root . '/app/config.php';
require_once $root . '/vendor/autoload.php';
{{Bootstrap}}
$run = new Maws\System\Test\Runner('{{Source}}');

{{Body}}
$run->finish();
```

`{{Bootstrap}}` — либо пусто, либо `require_once` источника (для `app/**`), с `loadDirection` перед ним.
`{{Body}}` — блоки `subject`/`fixture`/случаи, по блоку на каждый класс с `#[Subject]`.

Файл пишется атомарно: `Support::put()` пишет во временный `.tmp` рядом и переименовывает. Оборванная
запись не оставит наполовину затёртый тест.

### 11.6 Запуск

```php
passthru(escapeshellarg(PHP_BINARY) . ' ' . escapeshellarg($target), $code);
exit($code);
```

Код возврата теста становится кодом возврата команды. Никакой интерпретации: `make test:` — это
«сгенерируй и прогони», а не «сгенерируй и расскажи, что получилось».

## 12. Требования среды

| Требование | Почему |
|---|---|
| Живая PostgreSQL по `DBASE_DSN` | `Runner::__construct` открывает `PDO` и без базы печатает «Нет живой базы: …» и выходит с кодом 1 |
| `app/config.php` + `vendor/autoload.php` | тест подключает их первым делом |
| PHP CLI | `maws.php` отказывается работать в веб-SAPI |
| Права на запись в `app/Tests/` | тест создаётся и перезаписывается |
| Права на запись во временный каталог | песочница: `sys_get_temp_dir()/maws-tests-<pid>` |
| Часовой пояс не важен | `Runner` фиксирует `UTC`: примеры `Gives` записаны в UTC, а пояс машины задаётся `php.ini` |

Фиксация пояса — свойство **прогона**, а не фреймворка: сайт живёт в поясе сервера, оракул — в UTC.
Без этого прогон отвечал бы на настройку сервера, а не на код.

**Пример: нет базы.**

```
Нет живой базы: <DBASE_DSN>
<сообщение драйвера>
```

Код возврата 1, и до первого случая дело не доходит: соединение открывается в конструкторе `Runner`, а не
при первом запросе.

## 13. Пример от и до

Возьмём настоящий контракт `Path` (сокращённо):

```php
#[Subject(Path::class, 'new')]
#[Purpose('Приводит путь к одному виду…')]
final class Path
{
    #[Purpose('Склеивает части пути, не оставляя двойных разделителей.')]
    #[Returns('string', 'склеенный путь')]
    #[Effect(Effect::NONE)]
    #[Gives(['a', 'b', 'c'], 'a/b/c')]
    #[Gives(['/a/', '/b'], '/a/b')]
    public static function join(string ...$parts): string { … }

    #[Purpose('Приводит путь к одному виду…')]
    #[Returns('string', 'нормализованный путь')]
    #[Throws(PathFailure::class, '«..» некуда схлопывать')]
    #[Effect(Effect::NONE)]
    #[Gives(['/a/./b/../c//'], '/a/c')]
    #[Fails(['../123'], PathFailure::class)]
    public static function normalize(string $path): string { … }
}
```

**Шаг 1.** `php maws.php make test:core/System/Helpers/Path/Path.php` читает атрибуты, видит
`Subject(Path, 'new')` и четыре случая, пишет файл:

```php
$run = new Maws\System\Test\Runner('core/System/Helpers/Path/Path.php');

$run->subject('Maws\\System\\Helpers\\Path\\Path', 'new');

$run->gives('join', ['a', 'b', 'c'], 'a/b/c');
$run->gives('join', ['/a/', '/b'], '/a/b');
$run->gives('normalize', ['/a/./b/../c//'], '/a/c');
$run->fails('normalize', ['../123'], 'Maws\\System\\Helpers\\Path\\Exception\\PathFailure');

$run->finish();
```

`Purpose`, `Returns`, `Throws`, `Effect` в файл не попали — они для человека.

**Шаг 2.** Файл запускается. `Runner` открывает базу, фиксирует UTC, печатает шапку. Для каждого случая:
песочница (пустая — фикстуры нет), сброс состояния, `Path::normalize` вызывается статически (корень не
строится, `before` нет), результат сравнивается.

**Шаг 3.** Отчёт (контракт здесь взят сокращённо — у настоящего `Path` 42 случая, см. 10.1):

```
MAWS — прогон контракта
Источник: core/System/Helpers/Path/Path.php
Получатель: Maws\System\Helpers\Path\Path

  [ok]   Path::join(["a", "b", "c"]) → "a/b/c"
  [ok]   Path::join(["/a/", "/b"]) → "/a/b"
  [ok]   Path::normalize(["/a/./b/../c//"]) → "/a/c"
  [ok]   Path::normalize(["../123"]) → отказ PathFailure

Итог: 4 проверок, 4 прошло, 0 провалено
```

**Шаг 4.** Команда выходит с кодом 0. Если бы `normalize('../123')` вернул `'../123'` вместо отказа,
четвёртая строка стала бы `[fail]` с текстом «исключения не было, ожидалось …PathFailure», а код
возврата — 1.

## 14. Ловушки

1. **Атрибут без `use` — отказ генератора, а не тишина.** Если в файле написать `#[Fails(...)]` без
   `use Maws\System\Contract\Fails;`, PHP ищет `Ваш\Пространство\Имен\Fails`, не находит — и
   `getAttributes(Fails::class)` не возвращает ничего. Случай исчез бы молча. Поэтому генератор судит
   **имена**: разрешает каждый атрибут файла по `use` и пространству имён и отказывает до записи теста:

   ```
   Атрибут Fails (строка 19) не разрешился: Ваш\Пространство\Имен\Fails — такого класса нет.
   Добавь use Maws\System\Contract\Fails; — или исправь имя.
   Тест не создан.
   ```

   Тем же правилом ловится **опечатка в имени**: `#[Fail]` вместо `#[Fails]` — это `Ваш\Пространство\
   Имен\Fail`, класса нет, и в ответе подсказка:

   ```
   Атрибут Fail (строка 19) не разрешился: Ваш\Пространство\Имен\Fail — такого класса нет.
   Похоже на Fails — добавь use Maws\System\Contract\Fails; или исправь имя.
   Тест не создан.
   ```

   Опечатка опаснее забытого `use`: счёт «объявлено против собрано» её не видит (0 = 0), и до этого
   правила файл проходил зелёным с потерянным случаем.

   ```php
   use Maws\System\Contract\{Effect, Fails, Gives, Purpose, Returns, Subject};

   #[Fails(['../123'], PathFailure::class)]   // теперь это Maws\System\Contract\Fails
   ```

   Групповая форма разбирается, а не пропускается: она в контрактах самая частая, и без разбора
   опечатка в таком файле не судилась бы вовсе. Второй счёт ловит то, чего не видно по имени, —
   атрибут не на методе (свойство, конструктор): «Объявлено случаев Fails: 1 (строки 12), собрано 0».
2. **`#[Subject(` должен начинаться с начала строки**, иначе `maws test` не увидит файл вовсе (а
   `make test:` увидит — он читает отражением). Отступ в четыре пробела делает контракт невидимым для
   пакетного прогона.
3. **Сравнение строгое.** `1` ≠ `'1'`, `null` ≠ `false`, порядок ключей в массивах важен. Ожидание
   надо писать того же типа, что возвращает метод.
4. **Объект в ожидании не проверить.** `===` с объектом в атрибуте не сработает, а `literal()` вообще
   превратит объект в `null`. Для «того же объекта» есть `Token::SUBJECT`, для `PDOStatement` —
   `Token::STATEMENT`.

   ```php
   #[Gives([], Token::SUBJECT)]   // «вернулся тот же объект» — так можно
   #[Gives([], new Foo())]        // так нельзя: в атрибуте только константы, объект станет null
   ```

5. **Путь в ожидании — только через `@sandbox`.** Реальный временный каталог в атрибут не записать:
   он свой у каждого прогона.

   ```php
   #[Gives(['read.txt'], '@sandbox/read.txt')]               // так: развернётся в путь песочницы
   #[Gives(['read.txt'], '/tmp/maws-tests-123/1/read.txt')]  // так нельзя: каталог свой у каждого прогона
   ```
6. **`before` у статического метода — ошибка.** Не «игнорируется», а `TestMisuse`: объявление
   противоречит сигнатуре.
7. **`Changes` требует корня.** Для статического метода проверки `then` разрешаются от `null` и падают.
8. **Пустая фикстура наследует, а не очищает.** `#[Fixture(files: [])]` не делает песочницу пустой.
9. **Фикстура липкая.** Поставили на метод — она действует на все следующие, пока не объявят другую.
10. **Повторный `#[Fixture]` на одном элементе — ошибка PHP** в момент генерации («must not be
    repeated»), а не вежливое сообщение.
11. **Тест перезаписывается.** Любая правка в `app/Tests/**` исчезнет при следующем `make test:`.
12. **`app/Tests/**` не версионируется.** На чистом чекауте прогон создаёт дерево сам; нужен только
    записываемый каталог.
13. **База нужна даже чистым функциям.** `Runner` открывает соединение в конструкторе, поэтому
    `maws test` без PostgreSQL не пройдёт ни один контракт, включая `Path`.
14. **`maws test` не смотрит в `app/**`.** Контракты сайта (воркспейсы, инструменты) прогоняются только
    явным `make test:<файл>`.
15. **`Responds` требует `ResponseSent`.** Метод, который напечатал тело и вернул управление, — провал,
    даже если тело совпало.
16. **Вывод места не попадает в отчёт.** `echo` внутри метода не видно в консоли; его читает только
    `responds`. Отлаживать через `echo` в проверяемом коде бесполезно.
17. **Код ответа сбрасывается на 200 перед каждым случаем.** Случай, выставивший 404, не «протечёт» в
    следующий — но и рассчитывать на код от предыдущего нельзя.
18. **Пустой контракт — не успех.** Ноль случаев даёт код 1, но сообщение зависит от того, кто
    отказывает: генератор не создаёт тест — «В контракте нет проверок (Gives/Has/Fails/Changes/Responds)»;
    `Runner`, если случаев не оказалось в готовом тесте, печатает «Проверок нет.» (§10.1).
19. **Предупреждения PHP не глушатся и попадают в отчёт.** Например, `Warning: Undefined property: …`
    при неверном `path` печатается прямо между строками `[ok]`. Если в выводе появилось `Warning` или
    `Notice` — это не косметика: рядом почти всегда стоит `[fail]`.

## 15. Чек-лист при работе с контрактом

1. `#[Subject]` стоит первым атрибутом класса, **с начала строки**, с правильной фабрикой.
2. Все используемые атрибуты импортированы (`use Maws\System\Contract\{…}`).
3. На каждый метод — `Purpose`; на параметры — `Param`; на возврат — `Returns` (кроме `void`); на
   отказы — `Throws`; на внешние эффекты — `Effect` (явно, включая `NONE`).
4. Случаи покрывают: обычный успех (`Gives`), границы (`Gives`), отказы (`Fails`), мутации (`Changes`),
   самостоятельный ответ (`Responds`) — то, что у метода есть.
5. Ожидания того же типа, что возвращает метод; массивы — с тем же порядком ключей.
6. Пути в ожидании — только `@sandbox`/`@sandbox/…`.
7. `before` — только для нестатических методов.
8. Запустить `maws make test:<файл>`: отказ генератора — это недосчитанный случай (опечатка, забытый
   `use`, атрибут не на методе); «Проверок в контракте» называет собранное — сверьте с тем, что писали.
9. Перед коммитом — `maws test` (весь `core/**`) и `maws style`.

## 16. Шпаргалка

```php
#[Subject(Класс::class, 'new' | 'метод' | 'Scaffold::метод', [аргументы], 'путь')]
#[Fixture(files: ['файл' => 'содержимое'])]          // класс или метод; липкая
#[Purpose('зачем одной фразой')]                      // класс и метод
#[Param('имя', 'тип', 'уточнение')]                   // по разу на параметр
#[Returns('тип', 'уточнение')]                        // не для void
#[Throws(Класс::class, 'когда')]                      // по разу на отказ
#[Effect(Effect::NONE | DB_READ | FS_WRITE | …)]

#[Gives([аргументы], ожидание, before: [[путь, аргументы, имя]])]
#[Fails([аргументы], Класс::class, before: […])]
#[Changes([аргументы], [[путь, аргументы, ожидание]], before: […])]
#[Responds([аргументы], 'тело', статус, before: […])]
```

Токены: `@sandbox`, `@sandbox/файл`, `@subject`, `@world`, `@screen`, `@statement` (только ожидание),
`@имя` (привязка из `before`).

Команды:

```bash
php maws.php make test:core/System/Helpers/Path/Path.php   # один контракт: создать и прогнать
php maws.php test                                          # все контракты core/**
```
