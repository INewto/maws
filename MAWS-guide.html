MAWS — руководство разработчика

Это руководство о том, как пользоваться фреймворком: как создать страницу, место, инструмент, агента, как обращаться к базе, как выводить разметку и чем помогают штатные хелперы. Устройство ядра здесь не разбирается — только те его требования, которые вам придётся соблюдать, и короткое «почему», когда без него легко сделать неправильно. Главное из этих требований — доступ: инструмент видит только своё место и только объявленные им таблицы (§1.1).

1. Что такое MAWS

MAWS — PHP-фреймворк, в котором структура приложения выражена метафорой человеческого тела: голова прокладывает маршрут, ноги идут к месту, руки берут его инструменты, экран рисует сцену.

Практическое следствие одно, но важное: нельзя получить данные чужого модуля, просто вызвав его класс. Нужно дойти до места, войти в него и взять инструмент. Фреймворк проверяет каждый шаг во время исполнения, поэтому «случайно обратиться не туда» не получится — вы получите понятную ошибку.

1.1 Инструмент — это единица работы и единица доступа

Инструмент — класс, который делает одну вещь: читает новости, кладёт товар в корзину, считает статистику. Он лежит в каталоге своего места, и два его файла решают, что ему можно:

app/World/Public/Places/Home/Tools/ExampleTool/
  ExampleTool.php   class ExampleTool extends Tool — что инструмент умеет
  dbase.json        какие таблицы ему разрешены
  System/           репозиторий и рендер; создаёт make tool

Место публикует свои инструменты в settings.json — и там же перечисляет, инструменты каких чужих мест ему нужны. Так выглядит файл места Public/Home после make build:

json
{
  "tools": {
    "list": ["ExampleTool", "ExampleTool_1"],
    "needs": { "Public/SecondPlace": ["ExampleTool"] }
  }
}

Все конфиги фреймворка — settings.json, dbase.json, dbaccess.json, config.json — читаются как JSON5. Значит, в них можно писать комментарии // и /* */ и оставлять запятую после последнего элемента: файл, который вы правите руками, объясняет себя сам.

json5
// Инструменты места и нужды в чужих.
{
  "tools": {
    "list": ["ExampleTool", "ExampleTool_1"],          // своё
    "needs": { "Public/SecondPlace": ["ExampleTool"] } // чужое: Направление/Место → имена
  }
}

Строгим JSON такой файл уже не является: сторонние редакторы и линтеры могут ругаться на комментарии. Данные извне — тело HTTP-ответа, ответ модели, колонки базы — разбираются по-прежнему строгим json_decode: послабление сделано для файлов, которые правит человек, а не для потока.

Отсюда две независимые границы, и обе проверяются в момент вызова, а не на глаз:

граница чем задана отказ
между местами needs в settings.json AccessNotDeclared
между таблицами dbase.json инструмента DbaseDenied

Вторая граница — та, которую легко не заметить: у инструмента нет доступа ко всей базе. Он видит ровно те таблицы, что перечислены в его dbase.json:

json
{ "tables": ["public.test_table"] }

Проверяется это не по тексту SQL, а по плану запроса: фреймворк спрашивает у PostgreSQL EXPLAIN (VERBOSE, FORMAT JSON) и сверяет таблицы из плана с объявлением. Поэтому JOIN, подзапрос, UNION и алиасы не помогают: план назовёт все таблицы, которых коснулся запрос. Таблицы нет в объявлении → DbaseDenied ещё до выполнения.

Отсюда же запрет на запросы без плана: TRUNCATE, DROP, ALTER, CREATE INDEX через all/one/run не пройдут — у них плана нет, и сверять нечего (DbaseMisuse). Отдельных методов под них нет: операции со схемой — дело миграций (§9.3). Запрос, который вообще не трогает таблиц (SELECT 1), тоже отвергается — DbasePlanless: доказать нечего, значит и разрешать нечего.

Два запрета не заменяют друг друга: место проверяется по needs, таблица — по плану запроса. Обойти один, не нарушив другой, не получится.

Четыре части:

Часть Что это
World карта мест: направления и места
Man тот, кто исполняет запрос: ходит, входит, берёт
Screen вывод: сцены и страницы ошибок
Ai фоновые процессы (агенты), у которых нет ни тела, ни места

Требование Значение
PHP 8.1 и выше
Расширение pdo_pgsql, mbstring, json; gd — только для Image и Upload
База PostgreSQL (единственный поддерживаемый движок)
Зависимости composer install

PostgreSQL обязателен не из вкусовщины: защита доступа к таблицам опирается на план запроса, а план с именами таблиц строит только он.

Установка:

bash
composer install

Настройки — app/config.php. Обязательных констант одиннадцать, их и проверяет maws doctor: CORE_DIR, APP_DIR, WORLD_DIR, SCREEN_DIR, AI_DIR, LOGS_FILE, MIGRATIONS_DIR, DBASE_DSN, DBASE_USER, LANGUAGE, DEV. Двенадцатая — DBASE_PASSWORD — в проверку не входит: пустой пароль законен. Какая страница главная, здесь не задаётся — это флаг main в таблице areas.

  config.php                настройки: база, язык сайта, режим DEV
  World/Public/Places/      места направления Public
  World/Public/Places/Home/ место Home: Workspace.php, settings.json, Tools/
  World/Public/Places/SecondPlace/  второе место: свой инструмент, в него нуждается Home
  Screen/config.json        какое направление какой сценой показывать
  Screen/Scenes/            шаблоны сцен: {Сцена}/{Язык}/index.tpl.php
  Ai/                       агенты
  Tests/                    сгенерированные прогоны контрактов
public/index.php            единственная точка входа сайта

Направления и места в файлах не перечисляются: они живут в таблицах directions и places, а каталог места — только код этого места.

Важно: app/** — ваш код, и он автозагружается: App\ → app/, имя класса повторяет путь. app/World/Public/Places/Home/Workspace.php — это App\World\Public\Places\Home\Workspace, и подключать файл руками не нужно нигде: ни в воркспейсе, ни в инструменте, ни в агенте. Граница «фреймворк / ваш код» видна по пространству имён: Maws\ — ядро, App\ — ваш. Совпадение пути и namespace проверяет make build: файл, объявивший чужой класс, он назовёт по имени.

4. Маршруты: как работает URL

Одна точка входа public/index.php, один параметр:

https://сайт/index.php?way=<раздел>/<страница>

Регистр. В адресе — только строчные буквы. Сегмент сверяется с колонкой areas.url, а не с именем раздела и не с именем места: раздел может называться одним, жить по другому адресу и открывать третье место. Имена каталогов мест и классов пишутся с большой — Home, а не home; дефис в адресе возможен, в имени каталога — нет.

Разбор идёт по дереву areas, а не по places и не по directions:

шаг что происходит
1 адрес режется на сегменты и приводится к строчным
2 берётся главный раздел — areas.main = true; он должен быть ровно один
3 ведущие сегменты, совпадающие с адресом главной, снимаются — все
4 если адрес изменился (регистр или снятая главная) — 301 на канонический, один переход
5 оставшиеся сегменты спускаются по дереву: areas.parent_id → areas.url
6 раздел найден → открывается место из areas.place_id
7 сегмент не нашёлся → 404
адрес что откроется
/ или ?way= главный раздел (areas.main) и его место — Public/Home
?way=home 301 → /: «home» — человеческое имя главной
?way=<раздел> раздел верхнего уровня → место из areas.place_id
?way=<раздел>/<страница> вложенный раздел → место из areas.place_id
?way=Home 301 → /: регистр приводится тем же ответом
?way=home/home 301 → / — снимаются все ведущие
?way=public/<раздел> 404: направление в адресе не участвует
?way=<страница> 404: спуск идёт от корня, без родителя раздел не находится
?way=<раздел>/nope 404

Вложенность живёт только в базе — в areas.parent_id. Файловая система плоская: место лежит в app/World/{Направление}/Places/{Место}, а не внутри каталога родительского раздела. Поэтому way() — по-прежнему Направление/Место с больших букв, и сцена, воркспейс и имя класса считаются по месту, а не по адресу.

Адрес и место — разные вещи: дерево areas задаёт адреса, places — код мест. Раздел ведёт в место, но имён у места два: places.name (для way()) и areas.url (для адреса). Раздел с одним адресом может открывать место с другим именем — это норма, а не ошибка.

directions остаётся границей доверия: место одного направления не может взять инструменты другого. В адресе направление не участвует.

Что происходит дальше: адрес → раздел → Place → человек идёт к месту → входит → рабочее пространство места (Workspace.php) берёт инструменты и возвращает разметку → экран показывает её в сцене направления.

5. Место: создание

Место — это модуль (домен). Одно место = один каталог:

app/World/Public/Places/Home/
  Workspace.php     что делает страница этого места
  settings.json     какие инструменты место публикует и в каких чужих нуждается
  Tools/            инструменты места

Создать командой:

bash
php maws.php make place

Команда спросит по порядку: направление места (меню directions) и название места. Затем создаст каталог, Workspace.php, settings.json, Tools/ и вставит строку в places. Если файла {Напр}Workspaces.php ещё нет, он будет создан.

Раздел не спрашивается: место от раздела не зависит — оно принадлежит направлению. В дерево сайта место ставит make area, и он же назначает адрес: areas.url раздела — то, что попадёт в адрес. Поэтому имя места и адрес, по которому оно откроется, друг с другом не связаны: адрес задаёт раздел.

Если строка в places уже есть, а каталога нет, команда восстановит недостающие файлы в ту же строку и раздел не тронет.

Workspace.php — единственное место, где собирается страница:

php
namespace App\World\Public\Places\Home;

use App\World\Public\Places\PublicWorkspaces;

class Workspace extends PublicWorkspaces
{
    public function startWork()
    {
        $way = $this->place->way();

        $this->man->body->legs->walk($way);                  // дойти
        $pass  = $this->man->enterPlace($way);               // войти
        $tools = $this->man->body->hands->takeTools($pass);  // взять инструменты

        return $tools->ExampleTool->serve();                 // отдать разметку
    }
}

Конструктор пространства принимает три аргумента — $place, $man и $area, — и все три лежат в свойствах базового класса: $this->place, $this->man, $this->area.

$area — объект Maws\World\System\Area, то есть раздел, по которому пришли в это место. Оттуда берётся всё, что странице нужно знать про сам раздел:

Метод Что отдаёт
id() id строки в areas
name() название раздела для посетителя
url() адрес раздела
placeId() id места, в которое раздел ведёт
parent() id родительского раздела; 0 — верхний уровень
isMain() true, если это главная страница
fields() все колонки раздела плоским списком «имя колонки → значение»
php
$areaId = $this->area->id();                            // 3
$title  = $this->area->fields()['title'] ?? '';

fields() отдаёт и шапку страницы: title, description, keywords и og_* — это колонки раздела, поэтому собирать шапку второй раз в коде не нужно, экран получает её сам (§10). Третий аргумент в сигнатуре конструктора необязателен (null), но в запросе он есть всегда: голова передаёт ровно тот раздел, который нашёл роутинг.

Имя файла — это имя класса, а путь от app/ — его пространство имён: Workspace.php в app/World/Public/Places/Home/ даёт App\World\Public\Places\Home\Workspace. Ничего подключать руками не нужно, класс найдёт автозагрузка.

startWork() возвращает строку HTML — её и покажет экран. Никаких echo и header(): вывод собирает фреймворк.

settings.json места Public/SecondPlace после make build:

json
{
  "tools": {
    "list": ["ExampleTool"]
  }
}
  • list — инструменты, которые место публикует.
  • needs — в каких чужих местах место нуждается и какие их инструменты берёт. Ключа нет, пока нужд нет: needs пишется только у того, кто берёт чужое. Пример — Public/Home, который берёт инструмент у Public/SecondPlace (§7).

Правило: нужда возможна только внутри своего направления — место одного направления не может взять инструмент другого. Это не ограничение на будущее, а граница доверия: у направлений разные права, и в запрос подключается только {Напр}Workspaces.php своего направления, файла чужого в нём просто нет.

Третье поле, необязательное, — cache: можно ли кэшировать страницу этого места и на сколько. Нет ключа — страница не кэшируется вовсе (так живут все места, пока вы не решите иначе). Разбор — в §10.3.

6. Инструмент: создание

Инструмент — компонент места, который умеет отдать кусок разметки.

bash
php maws.php make tool

Команда спросит направление, место, название инструмента и язык шаблона, затем «Будет ли использоваться база данных?». Если да — попросит схему и таблицы (по одной, exit для завершения). Создаст:

Tools/ExampleTool/
  ExampleTool.php            класс инструмента
  dbase.json                 какие таблицы разрешены
  System/Repository.php      ваш репозиторий поверх Dbase
  System/Page.php            рендер
  System/Templates/ru/       шаблоны языка (ru — язык, который спросили при создании)

и допишет имя инструмента в settings.json места (в list).

Класс инструмента:

php
namespace App\World\Public\Places\Home\Tools\ExampleTool;

use App\World\Public\Places\Home\Tools\ExampleTool\System\Page;
use App\World\Public\Places\Home\Tools\ExampleTool\System\Repository;
use Maws\World\System\Tool;

class ExampleTool extends Tool
{
    public function serve(): string
    {
        $rows = (new Repository($this->db))->all();

        return (new Page())->index($rows);
    }
}
  • Имя класса — имя файла: ExampleTool.php объявляет ExampleTool. Пространство имён — путь от app/: app/World/Public/Places/Home/Tools/ExampleTool/ExampleTool.php → App\World\Public\Places\Home\Tools\ExampleTool. Файл, который объявит другое имя или другой namespace, не загрузится — make build назовёт его поимённо.
  • Наследник Tool, обязательный метод — serve(): string.
  • $this->db — база с правами этого инструмента; другой базы у вас нет.
  • Своего конструктора быть не может: Tool::__construct объявлен final и принимает имя инструмента и Dbase.

Репозиторий (System/Repository.php) — обычный класс, который получает Dbase и делает запросы:

php
namespace App\World\Public\Places\Home\Tools\ExampleTool\System;

use Maws\World\System\Dbase;

class Repository
{
    public function __construct(private Dbase $db)
    {
    }

    public function all(): array
    {
        return $this->db->all('SELECT id, name FROM public.test_table ORDER BY id');
    }
}

Рендер (System/Page.php) — наследник View; render() подключает шаблон и возвращает строку:

php
namespace App\World\Public\Places\Home\Tools\ExampleTool\System;

use Maws\Screen\System\View;

class Page extends View
{
    public function index(array $data): string
    {
        return $this->render($this->template(__DIR__ . '/Templates'), $data);
    }
}

Имена Repository и Page — не догма: это то, что создаёт make tool. Инструменту нужен класс, умеющий запросы, и класс, умеющий рендер; как они названы, решаете вы.

7. Связи между местами: list и needs

make build собирает в направлении два места. Public/Home публикует два своих инструмента и берёт один чужой — это и есть needs:

json
{
  "tools": {
    "list": ["ExampleTool", "ExampleTool_1"],
    "needs": { "Public/SecondPlace": ["ExampleTool"] }
  }
}

Public/SecondPlace публикует один и ни в чьих не нуждается:

json
{ "tools": { "list": ["ExampleTool"] } }

needs объявляет потребитель, а не поставщик: место само говорит, что берёт и у кого. Выдаётся пересечение — того, что просят, и того, что опубликовано. У SecondPlace инструмент один, поэтому Home получает ровно его; если бы поставщик публиковал два, а в нужде был назван один, пришёл бы один: подмножество считает объявление потребителя, а не добрая воля поставщика. Обе стороны должны сойтись — потребитель объявил нужду, поставщик объявил инструмент.

Место, которого в нуждах нет вовсе, получает не пустой список, а отказ AccessNotDeclared: «доступа нет» и «ничего не нужно» — разные вещи, и вторая выглядела бы как успешная выдача.

Права выдаёт первое место, в которое человек вошёл за запрос, а не то, где он стоит сейчас. Своё место видно целиком — это его собственные инструменты, объявлять их не нужно. Каждое следующее место открывается только тем, что объявило первое:

php
$own = $this->place->way();                                  // своё место
$this->man->body->legs->walk($own);
$ownTools = $this->man->body->hands->takeTools($this->man->enterPlace($own));

$other = 'Public/SecondPlace';                               // соседнее место того же направления
$this->man->body->legs->walk($other);
$otherTools = $this->man->body->hands->takeTools($this->man->enterPlace($other));

// $otherTools — только объявленное в needs: ['ExampleTool']

Если бы Home нужды не объявил, takeTools во втором месте отказал бы AccessNotDeclared. А если человек пришёл сразу в SecondPlace, оно для него первое, и его инструменты выдаются целиком.

Имена у мест могут совпадать: ExampleTool есть и у Home, и у SecondPlace, но это разные классы — каталог места входит в пространство имён. Нужда называет инструмент по имени, а берётся он из каталога того места, у которого просили.

8. Порядок допуска: дойти, войти, взять

Порядок обязателен и проверяется на каждом шаге:

Шаг Вызов Если нарушить
1. Дойти $man->body->legs->walk($way) —
2. Войти $man->enterPlace($way) — вернёт PlacePass не дошли → EnterWithoutWalk
3. Взять $man->body->hands->takeTools($pass) не вошли → TakeWithoutEnter

Ещё четыре правила:

  • В одно место нельзя войти дважды за запрос → EnterVisitedPlace. Поэтому граф обхода модулей ациклический: цепочка A → B → A не соберётся.
  • Пропуск (PlacePass) не заменяет проверку места: takeTools смотрит, где вы находитесь сейчас.
  • Место входа — исключение: в него вы уже «дома», шаги 1–2 для него не нужны (и не проверяются).
  • Права выдаёт первое место: инструменты второго и следующих мест выдаются только по needs первого (§7), а своё место человек получает целиком.

Ошибки этого слоя:

Исключение Когда
EnterWithoutWalk вошли в место, до которого не дошли
EnterVisitedPlace второе посещение того же места за запрос
AccessNotDeclared первое место не объявило нужду в этом месте (§7)
TakeWithoutEnter берёте инструменты, не находясь в месте
AccessNotDeclared место не объявлено в needs потребителя
ToolMissing инструмент объявлен, но файла или класса нет
ContractUnreadable / ContractBroken settings.json не читается / битый

9. База данных

9.1 Как объявить права

Рядом с инструментом лежит dbase.json:

json5
// Таблицы, к которым инструменту разрешено ходить.
// Список сверяется с планом запроса, а не с текстом SQL.
{
  "tables": ["public.test_table"]
}

Правила записи:

  • всегда «схема.таблица», разбор по первой точке;
  • регистр не важен (Public.Test_Table = public.test_table);
  • только те таблицы, которые инструменту действительно нужны;
  • формат — JSON5, поэтому комментарии разрешены; пустой список [] означает «к базе не хожу».

Если таблица не объявлена, запрос не выполнится — вы получите DbaseDenied ещё до обращения к серверу.

9.2 Три метода чтения и записи

Каждый из них сначала сверяет таблицы из плана запроса с правами инструмента и только потом выполняет. Параметры передаются вторым аргументом — именованные :name или позиционные ?; подстановка значений в текст SQL не поддерживается.

all(string $sql, array $params = []): array — все строки; пустой массив, если ничего не нашлось.

php
$this->db->all('SELECT id, name FROM public.test_table ORDER BY id');
// [['id' => 1, 'name' => 'Первый'], ['id' => 2, 'name' => 'Второй'], ['id' => 3, 'name' => 'Третий']]

$this->db->all('SELECT id, name FROM public.test_table WHERE id > :id', ['id' => 100]);   // []

one(string $sql, array $params = []): ?array — первая строка или null, если строк нет.

php
$this->db->one('SELECT * FROM public.test_table WHERE id = :id', ['id' => 1]);
// ['id' => 1, 'name' => 'Первый']

$this->db->one('SELECT * FROM public.test_table WHERE id = :id', ['id' => 100]);   // null

run(string $sql, array $params = []): int — выполняет запрос и отдаёт число затронутых строк.

php
$this->db->run('UPDATE public.test_table SET name = :n WHERE id = :id', ['n' => 'renamed', 'id' => 1]);   // 1
$this->db->run('DELETE FROM public.test_table WHERE id = :id', ['id' => 100]);                      // 0

lastInsertId(): ?string — значение последней последовательности, тронутой в этом соединении. На PostgreSQL это lastval(), а не «id той строки, которую вставил ты»: у таблицы без последовательности значение остаётся от прошлой вставки. Надёжный способ узнать id — INSERT … RETURNING id через one().

php
$this->db->lastInsertId();   // null, если в соединении ещё не было вставки в таблицу с последовательностью

9.3 Инструкции без плана

TRUNCATE, ALTER, CREATE INDEX, DROP через all/one/run не пройдут: у них нет плана запроса, и сверять нечего — DbaseMisuse по первому слову, до поездки к серверу. Отдельных методов под них нет. Это операции со схемой, а схему меняют миграции (db/migrations), не инструмент: объявить таблицу в dbase.json — значит разрешить с её данными работать, а TRUNCATE и DROP стирают не данные, а саму таблицу вместе со связями.

selectUnplanned(string $sql): PDOStatement — выполняет select, у которого плана с таблицами нет, — в транзакции только для чтения. Для запросов, которые таблиц не касаются: now(), to_char(now(), 'DD.MM.YY'), current_user.

php
$this->db->selectUnplanned('SELECT 1')->fetchColumn();              // 1
$this->db->selectUnplanned("SELECT to_char(now(), 'DD.MM.YY')");    // сегодняшняя дата

План видит только имена функций и их аргументы, а что у функции внутри — нет. query_to_xml('SELECT … FROM public.areas', …) даёт план из одного узла Result, и по плану он неотличим от to_char(now(), …). Поэтому у двери три проверки, и идут они по возрастанию цены:

  1. Одна инструкция и ни одной таблицы в плане — ; и SELECT * FROM public.test_table отвергаются до поездки к серверу, как и в all/one/run.
  2. Запрещённые функции — query_to_xml, table_to_xml, pg_read_file, pg_ls_dir, lo_import, dblink, set_config и подобные: они читают файлы, чужие таблицы или исполняют SQL из строки, а план этого не показывает. Отказ — DbaseMisuse, до выполнения.
  3. Сверка по факту. То, что не назвал ни план, ни список, — своя функция, читающая чужую таблицу, — ловится после выполнения: pg_stat_xact_user_tables показывает, какие таблицы тронуты в этой транзакции. Тронута не объявленная — откат и DbaseDenied, результат не отдаётся.

Отсюда и формулировка: для первых двух проверок запрос не выполнится, для третьей — выполнится, но результата не будет. Записать дверь не может ни в одном случае: транзакция только для чтения.

9.4 Транзакции

Каждый запрос сверяется и выполняется в своей транзакции. Когда нужна одна на несколько запросов, её открывают руками — и тогда порядок вызовов проверяется: DbaseMisuse, а не тихий false.

beginTransaction(): void — открывает транзакцию. Вложенный begin — DbaseMisuse: транзакция уже открыта.

php
$this->db->beginTransaction();
$this->db->beginTransaction();   // DbaseMisuse: вложенный begin

commit(): void — фиксирует открытую транзакцию. Без открытой — DbaseMisuse.

php
$this->db->commit();   // DbaseMisuse: commit без открытой транзакции

rollBack(): void — откатывает открытую транзакцию. Без открытой — DbaseMisuse.

php
$this->db->rollBack();   // DbaseMisuse: rollBack без открытой транзакции

inTransaction(): bool — открыта ли транзакция сейчас.

php
$this->db->inTransaction();   // false — до begin
$this->db->beginTransaction();
$this->db->inTransaction();   // true

Вместе это выглядит так:

php
$this->db->beginTransaction();
try {
    $this->db->run('UPDATE public.test_table SET name = :n WHERE id = :id', ['n' => 'renamed', 'id' => 1]);
    $this->db->commit();
} catch (Throwable $e) {
    $this->db->rollBack();
    throw $e;
}

9.5 Чего нельзя

  • Нельзя запросить таблицу, которой нет в dbase.json — DbaseDenied.
  • Нельзя выполнить запрос без плана через all/one/run — DbaseMisuse. Это не придирка: по плану фреймворк узнаёт, какие таблицы вы трогаете.
  • Нельзя обойти сверку текстом SQL: алиасы, JOIN, подзапросы и UNION тоже проверяются — план называет настоящие имена таблиц.
  • Нельзя собрать Dbase без прав: конструктор требует DbaseRights, а тот читается только из файла.

Бестабличный select (SELECT 1) — отдельный метод selectUnplanned($sql), он выполняется в транзакции только для чтения. Там, где план слеп (функция читает таблицу у себя внутри), сверка идёт по факту — по счётчикам обращений транзакции (§9.3), так что и через функцию чужая таблица не открывается.

Сверка и выполнение идут в одной транзакции, и это не про атомарность. EXPLAIN берёт ACCESS SHARE на таблицы плана и держит до COMMIT, поэтому ALTER и DROP этих таблиц ждут, и запрос на выполнении разбирается по той же схеме, что и проверялся: подменить таблицу между проверкой и выполнением нечем. Своя транзакция не открывается, если транзакция уже открыта вами, — там блокировки и так живут до её конца. Цена — две лишние поездки к серверу на каждый запрос (BEGIN и COMMIT).

9.6 Списки: страницы

all() отдаёт все строки. Для каталога это значит «все товары сразу», поэтому списки листают пагинатором — он считает всего строк, зажимает номер и берёт только нужную страницу:

php
use Maws\System\Helpers\Input\Input;
use Maws\System\Helpers\Pager\Pager;

$sql  = 'SELECT id, name FROM public.test_table ORDER BY id';
$page = Pager::over($this->db)->perPage(20)->at(Input::from($_GET)->int('page') ?: 1)->fetch($sql);

foreach ($page->rows() as $row) { /* ... */ }

Что отдаёт Page — страница из готовых строк и чисел: Page::of($rows, $total, $perPage, $number). Дальше в примерах — Page::of([], 12, 5, 2): строк в ней нет, всего 12, по 5 на страницу, это вторая.

rows(): array — строки этой страницы.

php
$page->rows();   // [] — у собранной вручную страницы строк нет; у настоящей — строки выборки

total(): int — сколько всего строк при тех же условиях.

php
$page->total();   // 12

perPage(): int — размер страницы, тот, что задал инструмент.

php
$page->perPage();   // 5

number(): int — номер страницы; при выборке он зажимается сверху: ?page=99 на трёх страницах даст третью. Меньше единицы номер не бывает — at(0) отвергается PagerMisuse.

php
$page->number();   // 2

pages(): int — сколько страниц всего; у пустой выборки — ноль.

php
$page->pages();   // 3 — 12 строк по 5 это три страницы

offset(): int — сколько строк пропущено до этой страницы.

php
$page->offset();   // 5 — вторая страница начинается с шестой строки

has(int $number): bool — есть ли такая страница: номер в диапазоне от первой до последней.

php
$page->has(3);   // true
$page->has(4);   // false — страниц всего три

next(): ?int — следующая страница или null, если это последняя.

php
$page->next();   // 3

previous(): ?int — предыдущая страница или null, если это первая.

php
$page->previous();   // 1

Правила простые:

  • размер страницы задаёт инструмент (perPage(20)), умолчания нет: это политика сайта, а не фреймворка;
  • LIMIT/OFFSET в свой SQL не пишите — их добавляет пагинатор, а запрос с ними получит отказ;
  • номер страницы читается из адреса через Input::int('page'), false превращается в первую страницу;
  • запрос, план которого пуст (WHERE false, SELECT 1), страж не пропустит — это его правило, пагинатор его не обходит. Для «заведомо пустой» выборки берите фильтр по колонке (WHERE id = -1).

Ссылки на страницы — обычные: ?way=<раздел>&page=2. Готового построителя ссылок нет намеренно: адрес списка знает место, а не хелпер.

10. Вывод: сцены и View

Сцена выбирается по направлению, а не по месту: Public/Home → Public → сцена Default. У места своей сцены нет и заводить её не нужно — все места направления показываются одним макетом.

app/Screen/config.json:

json
{"Default":"Default","Public":"Default","Error":"Error"}

Default — сцена по умолчанию, ключ обязателен. Остальные ключи — направления. Ключ на каждое новое направление дописывает make direction вместе со своей сценой, руками этот файл править не нужно (§14).

Своя разметка инструмента собирается в шаблоне:

Tools/ExampleTool/System/Templates/ru/index.tpl.php
php
<!-- шаблон получает данные из view -->
<ul>
<?php foreach ($data as $row): ?>
    <li><?= Html::escape($row['name']) ?></li>
<?php endforeach; ?>
</ul>

Экранирование — всегда Html::escape() (или <?= htmlspecialchars(...) ?> с теми же флагами, но хелпер надёжнее: флаги заданы в одном месте).

Страницы ошибок: 404 показывается сценой Error/404, остальные сбои — сценой Error. Текст ошибки выводится только при DEV = true.

Шапка страницы лежит не в шаблоне и не в воркспейсе, а в строке раздела areas: title, description, keywords и og_* — колонки, которые заводит миграция 0001. Собирает её голова: Area::fields() отдаёт строку раздела плоским списком «имя колонки → значение», Head::pageMeta() возвращает ровно этот список, а руки передают его экрану вместе с данными места. В шаблоне сцены это $meta:

php
<title><?= htmlspecialchars($meta['title'] ?? '') ?></title>
<meta name="description" content="<?= htmlspecialchars($meta['description'] ?? '') ?>">

Место о шапке не знает и знать не должно: заполняется она в разделе, а не в коде. У show404 и redirect шапки нет — печатать её негде.

10.1 Отправить человека на другой адрес

Страницу можно не показывать, а перенаправить человека — например, после обработки формы:

php
$this->man->body->hands->useScreenInterface(null, 'redirect', '/?way=');

// код ответа — пара «адрес + код»; 303 после POST: браузер обязан перейти методом GET
$this->man->body->hands->useScreenInterface(
    null,
    'redirect',
    ['url' => '/?way=', 'status' => 303]
);
  • первый аргумент — null: сцена не выбирается, показывать нечего;
  • третий аргумент — адрес, а не данные для сцены: строка или пара ['url' => адрес, 'status' => код];
  • строка — это 301 (постоянный перенос): адреса в MAWS канонические, и главная, снятая с адреса, уезжает именно так;
  • разрешены 301, 302 и 303; всё остальное, пустой адрес и данные не той формы — отказ TransferBroken, а не молчаливый перенос с кодом 200.

Вызов завершает процесс, поэтому код после него не выполнится. Отдельного $hands->redirect() нет намеренно: руки не зовут экран напрямую, они нажимают кнопку на пульте, а redirect — третья кнопка после showPage и show404.

Для форм — 303, а не 301: 301 браузер вправе закэшировать, и повторная отправка формы поведёт себя непредсказуемо. 302 — когда адрес временный, но метод менять не нужно. 307/308 не поддерживаются: они нужны там, где важно сохранить метод, а это уже не «кнопка после формы».

10.2 Ответ без сцены

Иногда сцена не нужна вовсе: эндпоинт для fetch, выгрузка файла, страница без шапки и подвала. Место отвечает само — код, тип и тело одной строкой:

php
use Maws\System\Helpers\Response\Response;

// внутри startWork()
Response::send('<h1>Ответ места</h1>');               // 200, text/html
Response::send('<h1>Нет такой страницы</h1>', 404);   // код — вторым аргументом
Response::json(['ok' => true]);                       // 200, application/json
Response::json(['error' => 'нет такого'], 422);       // код — вторым аргументом

Строка уходит как есть; массив или объект Response::send кодирует в JSON сам и ставит application/json, если тип не задан третьим аргументом. Оба метода не возвращают управление: печатают тело и бросают ResponseSent. Сцена после них не рисуется, обвязки нет.

Внутри — ровно то, что раньше писали руками:

php
http_response_code(200);
header('Content-Type: text/html; charset=utf-8');
echo '<h1>Ответ места</h1>';
throw new ResponseSent();

Руками стоит писать только если нужен заголовок, которого нет в двух методах (например, Content-Disposition для выгрузки). Тогда use Maws\System\Exception\ResponseSent; и тот же порядок.

throw, а не exit. exit не поймать ни входу, ни тесту: maws make test: умирал вместе с процессом, не печатал «Итог» и выходил с кодом 0 — тест выглядел пройденным, хотя не выполнялся. С ResponseSent вход просто заканчивает работу, а прогон показывает красный с объяснением «место ответило само». И exit пропустил бы finally: уборка после ответа не выполнилась бы вовсе.

Уборка — обычная. ResponseSent разматывает стек как любое исключение: finally выполняется, деструкторы тоже.

php
try {
    Response::send($csv);
} finally {
    fclose($handle);   // выполнится: тело отправлено, стек разматывается
}

Ловить ResponseSent в коде сайта не надо: это дело точки входа (public/index.php). Если поймать его раньше и не пробросить, тело уже ушло, а вход продолжит рисовать сцену — в одном ответе окажется два тела.

Три вещи, на которых спотыкаются:

  • header() до первого байта вывода. Если что-то уже напечатано, Response::send бросит ResponseMisuse и назовёт файл со строкой, где начался вывод: вывод уже начался в …:42. Уберите echo/print перед ответом, а не после.
  • Код ответа — только 100–599. Response::send('…', 700) — ResponseMisuse, а не молчаливая подмена на 500.
  • Данные не возвращаются, поэтому объявление места меняется: #[Returns] и #[Changes] снимаются, вместо них #[Throws(ResponseSent::class, '…')] и #[Responds([], '<h1>…</h1>')]. Подробнее — в §15, «Тесты контрактов».

Страница без обвязки делается так же: печатаете документ целиком (<!DOCTYPE html>…) и бросаете ResponseSent. Сцена в этом не участвует.

10.3 Кэш страницы

По умолчанию страница не кэшируется: уходит Cache-Control: no-store. Умолчание выбрано так нарочно — в шапке бывает имя человека, счётчик корзины, токен формы, и общий кэш раздал бы это первому встречному.

Если страница одинакова для всех, место объявляет политику в settings.json:

json
{
  "tools": { "list": ["ExampleTool"], "needs": {} },
  "cache": { "ttl": 60, "scope": "private" }
}

ключа cache нет Cache-Control: no-store
{"cache": {"ttl": 0}} private, no-cache + ETag
{"cache": {"ttl": 60}} private, max-age=60 + ETag
{"cache": {"ttl": 60, "scope": "public"}} public, max-age=60 + ETag
  • ttl — сколько секунд ответ считается свежим. Обязателен, если cache объявлен: {"cache": {}} — отказ, а не «ноль по умолчанию».
  • scope — "private" (по умолчанию) или "public". private — копию хранит только браузер посетителя; public — любой общий кэш, и он вправе отдать копию другим людям.

Больше ничего делать не нужно: ETag считается по готовому телу, повторный запрос с тем же телом получает 304 без тела, HEAD отдаёт заголовки без тела. Это работает само, как только объявлен cache.

Что означает ttl на самом деле. Внутри max-age сервер не спрашивают вовсе: ни шаблона, ни запроса к базе. Значит "ttl": 3600 на странице с ценой — это обещание показывать цену, которой может быть час. Если цену поменяли через полчаса, посетитель со свежей копией увидит старую: проверить некому, браузер не придёт. Отсюда:

Страница Разумное значение
каталог, статья, «о нас» — редко меняется {"ttl": 60, "scope": "public"}
цена, остатки — важна свежесть {"ttl": 0} — браузер спрашивает каждый раз, но при том же теле получает 304
корзина, личный кабинет ключа cache нет

ttl: 0 — это не «не кэшировать»: копия хранится, но каждый раз сверяется. Экономится трафик, а не работа сервера (страница всё равно собирается, чтобы посчитать ETag). Работу сервера экономит только ttl больше нуля, потому что при свежей копии запроса нет.

public — обещание, а не ускорение. Ставить его можно, только если в теле нет ничего личного. Фреймворк подстраховывает: если ответ ставит печенье (Set-Cookie), public молча понижается до private — иначе идентификатор сессии уехал бы в общий кэш. Побочное следствие: самый первый ответ новому посетителю в общий кэш не попадёт, на повторных заходах — попадёт.

Опечатка — отказ, а не тихое поведение. Неизвестный ключ внутри cache, ttl строкой или отрицательный, scope не из двух значений — CacheMisuse (500, текст виден при DEV). Молча проигнорированное "scop": "public" выглядело бы как «работает», а на деле не включало бы общий кэш.

Кэш и ошибки не смешиваются. Страницы 404 и 500 всегда no-store, политика места к ним не применяется. Ответ места через Response::send/json (§10.2) — тоже всегда no-store: он собран под конкретный запрос и политику не спрашивает.

Чего в настройке нет. Vary не закладывался: в MAWS адрес и есть состояние, ?way=… уже входит в ключ кэша, поэтому варианты, которым нужен общий кэш, кладите в адрес, а не в заголовок. Last-Modified не ставится: время изменения данных неизвестно, а время файла шаблона о них ничего не говорит. Кэша данных (запомнить результат тяжёлого запроса) нет — это отдельное решение со своим вопросом «что делает кэш устаревшим».

Язык из печенья — не для общего кэша. Если посетитель выбрал язык (site_language, §10.4), ответ собран под него, и public понижается до private — как при Set-Cookie. Копия в общем кэше ушла бы человеку с другим языком. Нужен общий кэш на несколько языков — язык должен быть в адресе.

Ловушка на стороне сервера. Сжатие ответа вправе обойтись с ETag по-своему — снять его или ослабить до W/: это решает конфиг той прослойки, что стоит перед приложением (Apache с mod_deflate, nginx с gzip, CDN — что у вас), а не фреймворк. Если ETag «не приходит» или приходит слабым, смотрите сначала настройку сжатия у себя: приложение заголовок ставит, а дальше его судьба не в его руках.

Как проверить.

bash
curl -D - "<адрес>?way="                                    # Cache-Control и ETag
curl -D - -H 'If-None-Match: "<ETag>"' "<адрес>?way="    # 304, тело пустое
curl -I "<адрес>?way="                                      # заголовки без тела

10.4 Язык сайта

Язык — один на запрос и на всё сразу: сцена и шаблон инструмента берутся из каталогов с одним и тем же именем, поэтому страница не соберётся «наполовину по-английски».

Откуда берётся. Константа LANGUAGE в app/config.php — язык по умолчанию. Печенье site_language перекрывает её для конкретного посетителя; ставит его ваш код, когда человек выбирает язык:

php
setcookie('site_language', 'en', ['path' => '/', 'httponly' => true, 'samesite' => 'Lax']);

Принимаются только две строчные латинские буквы. EN, english и ../x языком не считаются — остаётся язык по умолчанию. Это не придирка: код становится именем каталога, и ../x увёл бы чтение шаблона из каталога сцены.

Где лежат шаблоны.

app/Screen/Scenes/Default/ru/index.tpl.php                       сцена
app/Screen/Scenes/Error/ru/404/index.tpl.php                     страница 404
app/World/.../Tools/ExampleTool/System/Templates/ru/index.tpl.php     шаблон инструмента

Как получить путь в Page:

php
return $this->render($this->template(__DIR__ . '/Templates'), $data);

template() сам подставит каталог языка. Не склеивайте путь руками: правило выбора одно на весь сайт, и второй его экземпляр рано или поздно разойдётся с первым.

Нет перевода — берётся язык по умолчанию. Посетитель с en увидит ru, если каталога en нет: чужое печенье не роняет сайт пятисоткой. Обратная сторона названа честно: неполный перевод даёт на одной странице два языка — держите каталоги полными.

Новый язык — это каталог. Скопировать ru в en, перевести файлы, поставить site_language=en. Ни реестра языков, ни настройки в settings.json нет. make direction и make tool спрашивают язык при создании («Укажите язык направления…», «Укажите язык инструмента…») и кладут шаблон сразу в его каталог — константу править не нужно.

10.5 Вход и выход: grant и revoke

Авторизации в ядре нет и не будет: как называется таблица с людьми, что считается ролью и по какому правилу пускать — знает только сайт. Ядро отвечает за то, что забывают: сессия не должна сменить «кто вошёл», не сменив идентификатор.

Вход — один вызов. Пару логин/пароль проверяет ваш код; в Session::grant() приходит уже проверенный субъект:

php
$found = $check($login, $password);        // ['id' => 42, 'claims' => ['roles' => ['admin']]] | null

if ($found === null) {
    return $tools->Login->serve('Неверный логин или пароль');   // один текст на оба случая
}

Session::grant($found['id'], $found['claims']);

grant() делает два шага, которые порознь забывают делать вместе: меняет идентификатор сессии (session_regenerate_id(true) — старый файл удаляется сразу) и кладёт субъект в зарезервированный слот. Порознь получается фиксация сессии: идентификатор, навязанный до входа, остаётся идентификатором вошедшего. Заодно гасится токен формы — он был известен до входа, и форма с этим токеном прошла бы проверку уже после него.

claims — массив без структуры: роли, имя, что удобно. Ядро его хранит и не толкует.

Кто вошёл:

php
Session::instance()->subject();   // 42 | null
Session::instance()->claims();    // ['roles' => ['admin']] | []

Выход — revoke(), а не close(): close() уничтожает сессию целиком, а корзина гостя должна пережить выход. revoke() гасит слот и токен и снова меняет идентификатор.

php
Session::revoke();

Оба зовутся до первого вывода — как и open(): они меняют печенье. После вывода — SessionMisuse. Запись в слот мимо grant() закрыта: set('.auth', …) откажет.

Пароль сверяйте Hash::verify(), а не сравнением строк. «Помнить меня» — это кука, которую ставит ваш код (Cookie и Hash::sign), в ядре её нет: срок жизни и правила отзыва у сайтов разные.

10.6 Формы и боты: трекер и проверка

Крабик (Crabic) — это антибот-защита ваших форм. Крабик ловит и ест мелкую рыбёшку (простых спам-ботов). Если же к вам пожалует большой серьёзный хищник (целенаправленно написанный бот под систему MAWS), то Крабик с ним не справится и убежит. Потому что он просто крабик.

Форма, открытая в интернете, получает мусор пачками. Отличить живого человека от скрипта можно по двум вещам, которых у скрипта нет: он не проживает время и не повторяет движение. Проверка Crabic строится ровно на этом.

Что нужно в разметке. Форма помечается атрибутом data-crabic, в неё кладутся скрытое поле и скрипт:

php
<form method="post" data-crabic>
    <input type="hidden" name="crabic" value="">
    …
    <button type="submit">Отправить</button>
</form>

<noscript>
    <p>Форма работает только с включённым JavaScript: без него сервер не получит сводку действий.</p>
</noscript>

<script src="/js/crabic.js" data-img="true" defer></script>

Токена формы здесь нет и быть не должно: Крабик судит поведение, а не подлинность формы. Если месту нужен и токен, его проверяют до вызова инструмента и отдельно от Крабика — две независимые проверки, каждая о своём (§12.14).

Поле crabic заполняет скрипт перед отправкой; человек его не видит и заполнить не может. Пустое поле сервер считает ботом — поэтому <noscript> обязателен: иначе человек с выключенным JS увидит работающую на вид форму, которая молча не проходит.

Картинку ставить в разметку не нужно: скрипт сам вставляет /images/maws/crabic.png туда, где стоит его тег. Это метка «JavaScript выполнился» — без него её на странице нет. Показ управляется атрибутом data-img на том же теге: "true" и отсутствие атрибута картинку включают, "false" — выключают. Выключенная метка ничего не отменяет: проверка работает, просто страница обходится без картинки.

Что нужно на сервере. Один вызов в начале обработки — и всё:

php
// инструмент-приёмник: один адрес на пачки и на отправку формы
$chewed = Crabic::chew(['name', 'note']);   // true — разжевал, это бот

Первым аргументом — имена полей формы: по ним Крабик узнаёт отправку. Пусто — отправкой считается любой POST без тела JSON, это случай формы из одной кнопки. Пачку трекера Крабик принимает сам и отвечает на неё 204, так что до кода ниже такой запрос не доходит вовсе. На отрисовке страницы он начинает дорожку заново — поэтому chew зовут на каждом запросе к странице с формой, а не только на отправке.

php
if ($chewed) {
    return $page->form($_POST);   // форма снова, ввод не потерян
}

dbase.json инструмента объявлять ничего не нужно: склад отпечатков и журнал отказов ведёт ядро и ходит в них своими правами. Права места — про таблицы места.

Что значит отказ. Причину Крабик наружу не отдаёт: тому, кто отправил форму, она не нужна, а тому, кто подбирает обход, это подсказка. Причина ложится в журнал public.chews — reason и chewed_at, строка на каждый отказ, живёт сутки и чистится сама. Журнал читает тот, кто ведёт сайт: по нему видно, отсекается бот или живой человек, и по нему же настраивается порог.

reason Что случилось
empty поля нет, оно пустое или в сводке ни одного действия — страницы не касались
format сводка не разбирается или не того вида
order сервер не помнит, что отрисовывал эту страницу — сводка не с этой
young страница открыта меньше секунды назад — время считает сервер
time заявлено больше времени, чем прошло с открытия страницы
motion траектория нарисована по линейке
repeat такая же траектория уже приходила

Отказ — не приговор навсегда и не блокировка. Покажите форму снова с тем, что человек уже напечатал: отрисовка заново ставит отметку времени, и пока человек читает сообщение и правит, его собственное время идёт в его пользу. Именно поэтому склад живёт сутки и чистится сам: это не список забаненных.

Чего делать не надо. Ставить sleep() в отказе — он заряжает рабочий процесс сервера, а не бота. Блокировать по адресу — отказ получит сосед по NAT, законно отправивший форму в то же окно. Считать поводом пустую сводку в API — проверка для HTML-форм, а не для машинных адресов.

Пороги. Crabic::chew(['name', 'note'], ['min' => 1, 'ttl' => 86400]): сколько секунд страница обязана прожить до отправки и сколько секунд живут отпечаток и запись журнала. Возраст меряется только часами сервера: секунда — это увидеть страницу, довести указатель до кнопки и нажать, быстрее человек не успевает, а браузер получает страницу позже отрисовки, так что запас здесь у человека, а не у бота. Число присланных пачек порогом не бывает: пачек может не быть вовсе — форму из одной кнопки отправляют сразу, как до неё дошли.

Границы у порогов есть, и они молчаливые. ttl зажимается в отрезок от минуты до года (max(60, min($ttl, 31536000))): 'ttl' => 10 даст 60 секунд, 'ttl' => 0 — тоже 60, а не «не хранить». min не бывает отрицательным — меньше нуля считается нулём. Зажим не сообщает о себе ничем: это защита от опечатки в конфиге, а не проверка ввода, поэтому значения вне отрезка стоит считать своей ошибкой, а не «округлением».

11. Ошибки

Два рода сбоя, и их нельзя путать:

Род Что значит Базовый класс
Показать код правильный, условия плохие (нет места, нет прав) MawsException, несёт HTTP-статус
Исправить код написан неправильно (опечатка в объявлении) MawsMisuse, всегда 500

Третий исход сбоем не является: место ответило само (§10.2). Его несёт ResponseSent, вход ловит его пустой веткой, и на страницу он не попадает.

Своё исключение «показать»:

php
use Maws\System\Exception\MawsException;

class ExampleBusy extends MawsException
{
    public function __construct()
    {
        parent::__construct('Раздел занят обновлением');
    }

    public function status(): int
    {
        return 409;
    }
}

Что произойдёт: статус уйдёт в ответ, страницу выберет screenErrorInterface($status), текст появится только в DEV. Сбои рода «исправить» и любые Throwable попадают в журнал: имя из LOGS_FILE плюс дата текущих суток, то есть logs/maws-2026-10-29.log.

Правило: не ловите исключения там, где можно дать им дойти до входа — вход уже умеет и статус выставить, и страницу показать.

Показать страницу ошибки можно и вручную — прямо из рабочего пространства:

php
$this->man->body->hands->useScreenErrorInterface('404', 'товар не найден');

Код ответа выставит сам экран, поэтому '404' и 404 равнозначны: строку он приводит к числу. По коду выбирается страница: 404 — своя, любой другой код — общая сцена Error. Код вне диапазона 100–599 считается ошибкой вызывающего и превращается в 500. Вызов завершает процесс, так что код после него не выполнится.

Отказ по частоте: 429

Ограничения частоты в ядре нет — это решение, а не пробел. Счётчик принадлежит API места: там есть ключ (ключ API, адрес, метод), там клиент читает код ответа, и там 429 со Retry-After — это ответ, а не страница. На обычной странице в ключ нечего положить и кодом нечего ответить: человеку показывают страницу.

Поэтому частоту считает место, которое отдаёт JSON: своим хранилищем (файл, таблица — что под рукой), своим порогом, своим ответом. Порог — свойство места, а не фреймворка: «шестьдесят в минуту» для каталога и для входа в админку — разные числа, и знает их только сайт.

Одно правило общее: Retry-After ставится до броска. Исключение несёт статус, но не заголовки, поэтому header() идёт раньше throw — после него заголовок уже не уедет.

12. Хелперы

Хелперы — готовые инструменты для типовых задач: ввод, текст, числа, деньги, даты, файлы, пути, разметка, HTTP, JSON, CSV, печенья, токены, токен форм, хэши, картинки, загрузка файлов, исходящий ответ, страницы выборки. Все они лежат в Maws\System\Helpers\* и не требуют настройки — кроме тех, где политика зависит от сайта (Money, Date): там конфиг обязателен, умолчаний нет. Pager разобран рядом с базой — §9.6: без Dbase он не работает.

Общее правило: хелпер не угадывает. Если данные не того вида — он вернёт false (читатели) или бросит исключение *Misuse (операции). Молчаливых подстановок нет.

Как читать раздел. У каждого метода — сигнатура с типами и умолчаниями, одно предложение о том, что он делает, и пример. Значения в комментариях — настоящие: они взяты из контрактов core/** или посчитаны по их правилам, выдуманных для красоты нет. Где умолчания нет — это сказано словом «нет»: политику задаёт сайт.

Хелпер — необязательная часть. Каталог core/System/Helpers/<Имя>/ удаляется целиком (класс и его Exception/), и ядро продолжает работать: ни один файл ядра не обращается к хелперам. Нужен только один — остальные можно снести. Обратное неверно: хелпер вправе звать ядро.

12.1 Input — чтение присланных данных

Читатель, а не валидатор: нет поля или не тот вид — false, решает вызывающий.

Сборка.

php
Input::from(array $source): self
Параметр Тип По умолчанию Смысл
source array — (обязателен) набор, над которым читаем: $_POST, $_GET или любой массив
php
$in = Input::from($_POST);            // форма
$in = Input::from($_GET);             // строка запроса
$in = Input::from(['count' => '3']);  // что угодно: источник не важен

Дальше — по методу на поле. В примерах набор такой:

php
$in = Input::from([
    'product' => 'first',
    'count'   => '3',
    'price'   => '1.50',
    'tags'    => ['a', 'b'],
    'blank'   => '',
    'zero'    => '012',
    'whole'   => 5,
]);

string($key): string|false — значение строкой; не строка или пустая строка — false.

php
$in->string('product');   // 'first'
$in->string('count');     // '3' — пришло строкой и осталось строкой
$in->string('blank');     // false — поле есть, но пустое
$in->string('tags');      // false — это массив, а не строка
$in->string('missing');   // false — поля нет

int($key): int|false — целое; неразбираемое — false.

php
$in->int('count');        // 3
$in->int('whole');        // 5 — пришло числом, числом и осталось
$in->int('zero');         // false — '012' не целое: ведущий ноль
$in->int('price');        // false — '1.50' не целое

float($key): float|false — дробное; неразбираемое — false.

php
$in->float('price');      // 1.5
$in->float('count');      // 3.0 — целое тоже годится
$in->float('product');    // false

oneOf($key, array $allowed): string|false — значение, если оно из перечня; иначе false. Пустой перечень — отказ InputMisuse: сверять не с чем.

php
$in->oneOf('product', ['second', 'first']);  // 'first'
$in->oneOf('product', ['second']);            // false — значение не из перечня
$in->oneOf('missing', ['second', 'first']);  // false — поля нет
$in->oneOf('product', []);                  // InputMisuse: перечень пуст

array($key): array|false — присланный набор как массив; не массив — false.

php
$in->array('tags');       // ['a', 'b']
$in->array('product');    // false — это строка

has($key): bool — есть ли поле, независимо от значения.

php
$in->has('blank');        // true — поле есть, хоть и пустое
$in->has('missing');      // false

all(): array — весь набор в том виде, в каком пришёл.

php
$in->all();               // ['product' => 'first', 'count' => '3', …]

12.2 Text — текст по знакам, а не по байтам

length($value): int — число знаков: кириллица и эмодзи считаются по одному.

php
Text::length('Привет');   // 6
Text::length('Ёж');       // 2
Text::length('');         // 0

limit($value, $length, $end = '…'): string — обрезает до $length знаков и приписывает хвост только если действительно обрезал. $length меньше единицы — TextMisuse.

php
Text::limit('Привет мир', 6);         // 'Привет…'
Text::limit('Привет', 6);             // 'Привет' — обрезать нечего, хвоста нет
Text::limit('Привет мир', 6, '...');  // 'Привет...' — свой хвост
Text::limit('Привет', 0);             // TextMisuse: обрезать не до чего

upper($value) / lower($value) / title($value): string — регистр; title поднимает первую букву каждого слова.

php
Text::upper('Привет');        // 'ПРИВЕТ'
Text::lower('ПРИВЕТ');        // 'привет'
Text::title('иван петров');   // 'Иван Петров'

squish($value): string — снимает пробелы по краям и сжимает повторные внутри — включая переводы строк и табы — в один пробел.

php
Text::squish('  Привет   мир  ');   // 'Привет мир'
Text::squish("Привет\n\tмир");      // 'Привет мир'

slug($value): string — адресная часть: кириллица транслитерируется, слова соединяются дефисами, лишние дефисы по краям снимаются.

php
Text::slug('Привет мир');        // 'privet-mir'
Text::slug('Ёлка, ёж и мёд');    // 'elka-ez-i-med'
Text::slug('  --Уже--слаг--  '); // 'uze-slag'

plural($count, array $forms): string — русская форма слова по числу. Форм ровно три и именно в порядке «одна / две / пять»; другое число форм — TextMisuse.

php
Text::plural(1, ['товар', 'товара', 'товаров']);    // 'товар'
Text::plural(2, ['товар', 'товара', 'товаров']);    // 'товара'
Text::plural(5, ['товар', 'товара', 'товаров']);    // 'товаров'
Text::plural(21, ['товар', 'товара', 'товаров']);   // 'товар' — исключение из «11–14»
Text::plural(11, ['товар', 'товара', 'товаров']);   // 'товаров'
Text::plural(1, ['товар', 'товара']);               // TextMisuse: форм должно быть три

12.3 Num — числа

format($value, $decimals = 0, $decimal = ',', $thousands = ' '): string — число с разделителями разрядов и заданным числом знаков после запятой. Отрицательное число знаков или одинаковые разделители дробной части и разрядов — NumMisuse: такую запись потом не разобрать.

php
Num::format(1234.5, 2);             // '1 234,50'
Num::format(1234.5, 0);             // '1 235' — округление
Num::format(-1234.5, 2);            // '-1 234,50'
Num::format(1234, 0, ',', '');      // '1234' — без разделителей разрядов
Num::format(1234.5, 2, '.', ',');   // '1,234.50' — английская запись
Num::format(1234.5, -1);            // NumMisuse
Num::format(1234.5, 2, ',', ',');   // NumMisuse: разделители совпали

parse($value): float|false — обратный разбор: пробелы (в том числе неразрывный и узкий) и запятая понимаются, всё остальное — false.

php
Num::parse('1 234,56');   // 1234.56
Num::parse('1234');       // 1234.0
Num::parse('-0,5');       // -0.5
Num::parse(' 12,5 ');     // 12.5 — пробелы по краям не мешают
Num::parse('');           // false
Num::parse('abc');        // false
Num::parse('1e3');        // false — экспонента не принимается
Num::parse('12,');        // false — запятая без дробной части
Num::parse('1.234,5');    // false — два вида разделителей сразу

clamp($value, $min, $max): float|int — подтягивает число к границам. $min больше $max — NumMisuse.

php
Num::clamp(5, 0, 10);     // 5
Num::clamp(15, 0, 10);    // 10
Num::clamp(-5, 0, 10);    // 0
Num::clamp(1.5, 0, 1);    // 1
Num::clamp(5, 10, 0);     // NumMisuse: границы перевёрнуты

toWords($value, $lang): string — целое число словами; $lang — 'rus' или 'en'. Не целое, больше 18 цифр или неизвестный язык — NumMisuse.

php
Num::toWords('21', 'rus');      // 'двадцать один'
Num::toWords('1000', 'rus');    // 'одна тысяча' — женский род у тысяч
Num::toWords('3221', 'rus');    // 'три тысячи двести двадцать один'
Num::toWords('21', 'en');       // 'twenty-one'
Num::toWords('0', 'en');        // 'zero'

12.4 Money — суммы

Сумма — целое число минимальных единиц: копеек, центов. Дробных чисел в деньгах нет, иначе копейка теряется на округлении. 1234,56 ₽ — это 123456.

Умолчаний нет: какие валюты есть у сайта, как каждая пишется и называется — знает только сайт. Политика — набор «код валюты → описание», в описании девять полей, все обязательны:

Поле Тип Смысл
symbol string знак валюты; пустая строка — если знака нет
minor int 0…6 сколько знаков после запятой: 2 у рубля, 0 у иены
after bool знак после числа (1 234,56 ₽) или перед ($1,234.56)
space bool пробел между числом и знаком
decimal string знак дробной части
thousands string знак разрядов; пустая строка — без разделения
lang 'rus' | 'en' язык, которым сумма называется словами
unit список из 3 строк формы названия: одна, две, много
subunit список из 3 строк то же для копеек, центов

Лишнее поле, пропущенное поле, minor вне 0…6, совпавшие decimal и thousands, lang не из списка, меньше или больше трёх форм в unit — MoneyMisuse при сборке, а не при работе.

with(MoneySettings $settings): self — собирает читателя сумм по уже готовой политике: пригодится, когда политика пришла из другого места, а не из массива.

php
$settings = MoneySettings::fromArray([...]);
$money = Money::with($settings);
$money->format(100, 'RUB');   // '1,00 ₽'

fromArray(array $config): self — собирает читателя сумм из набора «код валюты → описание» и проверяет каждое поле каждой валюты.

php
$money = Money::fromArray([
    'RUB' => [
        'symbol' => '₽', 'minor' => 2, 'after' => true, 'space' => true,
        'decimal' => ',', 'thousands' => ' ', 'lang' => 'rus',
        'unit' => ['рубль', 'рубля', 'рублей'],
        'subunit' => ['копейка', 'копейки', 'копеек'],
    ],
    'USD' => [
        'symbol' => '$', 'minor' => 2, 'after' => false, 'space' => false,
        'decimal' => '.', 'thousands' => ',', 'lang' => 'en',
        'unit' => ['dollar', 'dollars', 'dollars'],
        'subunit' => ['cent', 'cents', 'cents'],
    ],
    'JPY' => [
        'symbol' => '¥', 'minor' => 0, 'after' => false, 'space' => false,
        'decimal' => '.', 'thousands' => ',', 'lang' => 'en',
        'unit' => ['yen', 'yen', 'yen'],
        'subunit' => ['sen', 'sen', 'sen'],
    ],
]);

Money::fromArray([]);   // MoneyMisuse: в конфиге нет ни одной валюты

fromFile(string $path): self — читает ту же политику из JSON-файла: валюты сайта можно держать рядом с сайтом, а не в коде. Путь — свой у каждого сайта; содержимое файла — ровно тот набор, что выше.

php
// config/money.json
// { "RUB": { "symbol": "₽", "minor": 2, ... } }

$money = Money::fromFile('config/money.json');
Money::fromFile('нет-такого-конфига-денег.json');   // MoneyMisuse: файл не читается

format(int $amount, string $currency): string — показывает сумму из минимальных единиц: разряды, знак дробной части и место знака валюты — так, как описана валюта.

php
$money->format(123456, 'RUB');    // '1 234,56 ₽'
$money->format(5, 'RUB');         // '0,05 ₽'
$money->format(0, 'RUB');         // '0,00 ₽'
$money->format(-123456, 'RUB');   // '-1 234,56 ₽'
$money->format(123456, 'USD');    // '$1,234.56'
$money->format(123456, 'JPY');    // '¥123,456' — у иены нет дробной части
$money->format(0, 'JPY');         // '¥0'
$money->format(100, 'EUR');       // MoneyMisuse: валюты нет в политике

toMinor(string $text, string $currency): int|false — обратный разбор: запись человека становится суммой в минимальных единицах. Знак валюты, пробелы по краям и разделители разрядов понимаются по политике; лишние знаки после запятой — не округление, а false.

php
$money->toMinor('1 234,56 ₽', 'RUB');   // 123456 — знак валюты не мешает
$money->toMinor('1234,56', 'RUB');      // 123456 — без разрядов и без знака
$money->toMinor('1 234,5', 'RUB');      // 123450 — один знак дополнился нулём
$money->toMinor('-1 234,56', 'RUB');    // -123456
$money->toMinor('$1,234.56', 'USD');    // 123456
$money->toMinor('1 234,567', 'RUB');    // false — третий знак терять нельзя
$money->toMinor('1 234,56', 'JPY');     // false — у иены дробной части нет
$money->toMinor('abc', 'RUB');          // false
$money->toMinor('', 'RUB');             // false
$money->toMinor('1', 'EUR');            // MoneyMisuse — это ошибка политики, а не ввода

Разница важна: false — «человек написал непонятно», MoneyMisuse — «сайт не описал валюту». Первое показывают в форме, второе чинят в конфиге.

toWords(int $amount, string $currency): string — называет сумму словами, с названием валюты и копейками. Копейки называются всегда, даже нулевые, если валюта их имеет: так пишут в документах.

php
$money->toWords(123456, 'RUB');   // 'одна тысяча двести тридцать четыре рубля 56 копеек'
$money->toWords(100, 'RUB');      // 'один рубль 00 копеек'
$money->toWords(0, 'RUB');        // 'ноль рублей 00 копеек'
$money->toWords(-150, 'RUB');     // 'минус один рубль 50 копеек'
$money->toWords(123456, 'USD');   // 'one thousand two hundred thirty-four dollars 56 cents'
$money->toWords(123456, 'JPY');   // 'one hundred twenty-three thousand four hundred fifty-six yen'

Политика читается обратно двумя способами: currency($code): array отдаёт описание одной валюты (неизвестный код — MoneyMisuse), toArray(): array — весь набор в том же виде, в каком его задали.

12.5 Date — даты по политике

Момент времени — целое число секунд Unix. Пояс берётся у сервера, а не из политики: часовой пояс сайта задаёт окружение, и второй источник правды тут не нужен. Ключ timeZone в конфиге — ошибка.

Примеры ниже сняты при поясе UTC: utimestamp() и format() считают в поясе сервера, поэтому на сервере в другом поясе эти числа и записи с часами сдвинутся ровно на его смещение.

Политика — набор из семи ключей, все обязательны:

Ключ Тип Смысл
format string вид записи по умолчанию, строка для date(): 'd.m.Y'
parseFormats непустой список строк какие записи принимает разбор — по порядку, до первого совпадения
thresholds набор из 4 целых секунды: justNow (что считать «только что»), minutes, hours, days — до какого размера идти минутами, часами, днями. Растут строго: justNow < minutes < hours < days
now string что сказать о только что случившемся
ago string шаблон прошедшего, обязательно с {n} и {unit}
in string шаблон будущего, те же {n} и {unit}
units набор из 3 списков по 3 формы слова для minute, hour, day: одна, две, много

Пропущенный ключ, лишний ключ, неподходящее значение, пороги не по возрастанию, шаблон без {n} — DateMisuse при сборке.

with(DateSettings $settings): self — собирает читателя дат по уже готовой политике.

php
$settings = DateSettings::fromArray([...]);
$date = Date::with($settings);
$date->format(1792108800);   // '16.10.2026'

fromArray(array $config): self — собирает читателя дат из конфига, каким его пишут в файле или в коде сайта, и проверяет каждый ключ.

php
$config = [
    'format' => 'd.m.Y',
    'parseFormats' => ['d.m.Y', 'Y-m-d', 'Y-m-d H:i:s'],
    'thresholds' => ['justNow' => 60, 'minutes' => 3600, 'hours' => 86400, 'days' => 604800],
    'now' => 'только что',
    'ago' => '{n} {unit} назад',
    'in' => 'через {n} {unit}',
    'units' => [
        'minute' => ['минуту', 'минуты', 'минут'],
        'hour' => ['час', 'часа', 'часов'],
        'day' => ['день', 'дня', 'дней'],
    ],
];

$date = Date::fromArray($config);

Date::fromArray([]);                                 // DateMisuse: нет ни одного ключа
Date::fromArray(['timeZone' => 'UTC'] + $config);    // DateMisuse: лишний ключ — пояс задаёт сервер
Date::fromArray(['ago' => '{n} назад'] + $config);   // DateMisuse: в шаблоне нет {unit}

fromFile(string $path): self — читает ту же политику из JSON-файла. Путь — свой у каждого сайта; содержимое — ровно набор выше.

php
// config/date.json
// { "format": "d.m.Y", "parseFormats": ["d.m.Y", "Y-m-d"], ... }

$date = Date::fromFile('config/date.json');
Date::fromFile('нет-такого-конфига-дат.json');   // DateMisuse: файл не читается

format(int $timestamp, ?string $format = null): string — записывает момент по виду из политики или по указанному виду, в поясе сервера.

php
$date->format(0);                     // '01.01.1970'
$date->format(0, 'Y-m-d H:i:s');      // '1970-01-01 00:00:00'
$date->format(1792108800);            // '16.10.2026'

human(int $timestamp, ?int $now = null): string — говорит, сколько прошло или сколько осталось, словами и по порогам; за последним порогом отдаёт обычную запись. $now — от чего считать, null — текущее время.

php
$date->human(1000, 1030);      // 'только что' — 30 секунд меньше порога justNow
$date->human(1000, 1060);      // '1 минуту назад'
$date->human(1000, 1120);      // '2 минуты назад'
$date->human(1000, 1300);      // '5 минут назад'
$date->human(1000, 4600);      // '1 час назад'
$date->human(1000, 8200);      // '2 часа назад'
$date->human(1000, 19000);     // '5 часов назад'
$date->human(1000, 87400);     // '1 день назад'
$date->human(1000, 173800);    // '2 дня назад'
$date->human(1000, 433000);    // '5 дней назад'
$date->human(1000, 700000);    // '01.01.1970' — за порогом days обычная запись
$date->human(1000, 700);       // 'через 5 минут' — момент в будущем

human считает длительность, а не календарь: «вчера» требует календаря и пояса, поэтому такого слова там нет. Пять дней — это 432000 секунд, а не «пять календарных дат».

utimestamp(string $value): int|false — разбирает запись в момент времени: перебирает parseFormats по порядку. Пробельные знаки по краям не мешают, внутри — значимы.

php
$date->utimestamp('16.10.2026');            // 1792108800
$date->utimestamp(' 16.10.2026 ');          // 1792108800 — края обрезаны
$date->utimestamp("\u{00A0}2026-10-16\t");  // 1792108800 — неразрывный пробел и табуляция тоже края
$date->utimestamp('2026-10-16');            // 1792108800
$date->utimestamp('2026-10-16 21:14:03');   // 1792185243
$date->utimestamp('32.01.2026');            // false — 32 января не существует
$date->utimestamp('16.10.2026 xxx');        // false — хвост не разобран
$date->utimestamp('abc');                   // false
$date->utimestamp('');                      // false

Разбор отвергает всё, что разобралось с оговоркой: иначе 32 января молча стало бы 1 февраля. Политика читается обратно методом toArray() у DateSettings — тем же набором, каким её задали.

12.6 File — файлы внутри одного корня

Корень задаётся при сборке, пути — только относительные. Абсолютный путь и выход за корень — отказ, в том числе через ссылку.

in(string $root): self — собирает читателя над каталогом: дальше все пути считаются от него. Пустой корень — FileMisuse: нечего ограничивать.

php
$files = File::in(__DIR__ . '/uploads');
File::in('');   // FileMisuse: корень не может быть пустым

read(string $path): string|false — читает файл целиком. Файла нет — false, а не исключение: «нет файла» бывает обычным делом, и решает это вызвавший. Файл есть, но не читается — FileFailure: это сбой, а не отсутствие данных.

php
$files->read('read.txt');          // 'привет'
$files->read('./read.txt');        // 'привет'
$files->read('sub/../read.txt');   // 'привет' — .. схлопывается внутри корня
$files->read('nope.txt');          // false
$files->read('../read.txt');       // FileMisuse: выход за корень
$files->read('/etc/passwd');       // FileMisuse: путь абсолютный

write(string $path, string $content): void — записывает файл целиком, затирая прежнее содержимое, и создаёт его при необходимости. Сбой записи — исключение, а не false: молча не записанные данные вызывающий не заметит, а потеря уже случилась. Недостающий каталог не создаётся скрыто — для этого есть ensureDir.

php
$files->write('new.txt', 'привет');
$files->read('new.txt');              // 'привет'
$files->write('nope/new.txt', 'привет');   // FileFailure: каталога нет

append(string $path, string $content): void — дописывает в конец файла, создавая его при необходимости.

php
$files->append('read.txt', ' мир');
$files->read('read.txt');   // 'привет мир'

exists(string $path): bool — отвечает, есть ли такой файл или каталог.

php
$files->exists('read.txt');   // true
$files->exists('nope.txt');   // false

size(string $path): int|false — размер файла в байтах; не файл — false. Байты, не знаки: 'привет' — 12 байт.

php
$files->size('read.txt');   // 12
$files->size('nope.txt');   // false

modified(string $path): int|false — время последнего изменения меткой времени Unix; не файл — false.

php
$files->modified('read.txt');   // метка времени Unix, когда файл меняли
$files->modified('nope.txt');   // false

names(string $dir = ''): array — перечисляет, что лежит в каталоге, по алфавиту. Служебные . и .. в список не попадают: вызывающему они не нужны, а их присутствие — источник ошибок. Пустой путь — сам корень. Это не каталог — FileFailure.

php
$files->names();            // ['read.txt']
$files->names('read.txt');  // FileFailure: не каталог

ensureDir(string $dir): void — создаёт каталог со всеми недостающими родителями. Уже существующий каталог — не ошибка: вызов можно повторять.

php
$files->ensureDir('sub/dir');
$files->exists('sub/dir');   // true
$files->ensureDir('sub/dir'); // тишина: каталог уже есть

delete(string $path): void — удаляет файл. Отсутствие файла — FileFailure, а не тихий успех: иначе опечатка в пути выглядела бы как выполненное удаление. Каталог вместо файла — FileMisuse: удаление каталогов не входит в этот метод.

php
$files->delete('read.txt');
$files->exists('read.txt');   // false
$files->delete('nope.txt');   // FileFailure: файла нет

copy(string $from, string $to): void — копирует файл внутри корня.

php
$files->copy('read.txt', 'copy.txt');
$files->read('copy.txt');   // 'привет'

move(string $from, string $to): void — переносит файл внутри корня. Если переименование невозможно (разные диски), файл копируется и исходный удаляется — иначе перенос между диском сайта и временным каталогом молча не работал бы.

php
$files->move('read.txt', 'moved.txt');
$files->read('moved.txt');     // 'привет'
$files->exists('read.txt');    // false

Выход проверяется дважды — строкой и файловой системой. Сначала Path::normalize схлопывает .. и отказывает, когда схлопывать некуда. Потом путь разрешается (realpath) и сравнивается с разрешённым корнем. Вторая проверка нужна из-за ссылок: симлинк внутри корня, ведущий наружу, строкой выглядит обычным путём, а читает чужой файл. Разрешение заодно снимает разницу регистра на Windows — C:/ROOT и C:/Root сходятся сами, потому что realpath возвращает имя, лежащее на диске.

Ссылка, ведущая за корень, отвергается и там, где операция безобидна: delete('link') и exists('link') вернут FileMisuse, а не догадку. Проверка идёт по разрешённому пути; если между проверкой и чтением кто-то с правом записи в корень подменит каталог ссылкой, это гонка — File защищает от присланного пути, а не от чужого процесса.

12.7 Path — пути строками

Разделитель всегда прямой слэш: PHP понимает его и на Windows, а обратный слэш остаётся только на входе. Path работает со строками и файловую систему не спрашивает — разрешать ссылки умеет File.

join(string ...$parts): string — склеивает части, не оставляя двойных разделителей на стыках. Части не перекрывают друг друга: склейка — это склейка, а не разрешение пути.

php
Path::join('a', 'b', 'c');     // 'a/b/c'
Path::join('/a/', '/b');       // '/a/b' — двойного слэша нет
Path::join('/', 'a');          // '/a'
Path::join('', 'a');           // 'a' — пустая часть пропускается
Path::join('a', '');           // 'a'
Path::join('app', 'World', 'Public');   // 'app/World/Public'

normalize(string $path): string — приводит путь к одному виду: обратный слэш становится прямым, . и пустые сегменты уходят, .. схлопывается с предыдущим сегментом. Путь, который выходит за свой корень, — отказ: .. некуда схлопывать.

php
Path::normalize('/a/./b/../c//');            // '/a/c'
Path::normalize('C:\\a\\.\\b');              // 'C:/a/b'
Path::normalize('\\\\server\\share\\a\\..\\b');   // '//server/share/b' — UNC-путь
Path::normalize('/');                        // '/'
Path::normalize('a/..');                     // '.'
Path::normalize('');                         // ''
Path::normalize('C:./a');                    // 'a'
Path::normalize('../123');                   // PathFailure: выходить некуда
Path::normalize('a/../../b');                // PathFailure

Выход за корень — отказ, а не молчаливая правка. normalize схлопывает .. только с тем сегментом, который уже есть. Если схлопывать не с чем — .. стоит в начале, — нормализовать нечего, и метод бросает PathFailure, а не возвращает ../123 как нормализованный путь. Иначе проверка «путь внутри каталога» получала бы готовую дыру: ../123 выглядит прилично, а ведёт наружу.

Диск — префикс, а не сегмент: всё до первого слэша считается префиксом. C:/a остаётся C:/a — слэш за диском есть, значит путь от корня диска. C:./a — путь от текущего каталога на диске, и приклеенный через слэш диск превратил бы его в C:/a, то есть в другой путь; поэтому диск без слэша за собой отрезается, а остаток считается относительным.

isAbsolute(string $path): bool — отвечает, начинается ли путь от корня, а не от текущего каталога. Диск со слэшем — абсолютный, диск без слэша — нет.

php
Path::isAbsolute('/a');      // true
Path::isAbsolute('C:\\a');   // true
Path::isAbsolute('C:/a');    // true
Path::isAbsolute('C:a');     // false — от текущего каталога на диске
Path::isAbsolute('a/b');     // false

base(string $path): string — последний сегмент пути: имя файла или каталога вместе с расширением. Путь кончается корнем — пустая строка.

php
Path::base('/a/b.txt');   // 'b.txt'
Path::base('a/b/');       // 'b' — слэш на конце не мешает
Path::base('/');          // ''

dirname(string $path): string — каталог, в котором лежит путь, без последнего сегмента.

php
Path::dirname('/a/b.txt');   // '/a'
Path::dirname('/a');         // '/'
Path::dirname('b.txt');      // '' — каталога в пути нет

extension(string $path): string — расширение без точки. Точка в начале имени расширением не считается: .gitignore — имя целиком.

php
Path::extension('/a/b.tar.gz');   // 'gz' — только последнее расширение
Path::extension('/a/b');          // ''
Path::extension('/a/.gitignore'); // ''

withoutExtension(string $path): string — путь без расширения; остальное имя сохраняется как было, включая разделители.

php
Path::withoutExtension('/a/b.tar.gz');      // '/a/b.tar'
Path::withoutExtension('/a/b');             // '/a/b'
Path::withoutExtension('C:\\a\\.gitignore');   // 'C:\\a\\.gitignore' — расширения нет

inside(string $path, string $root): bool — лежит ли путь внутри каталога или совпадает с ним. Сравниваются сегменты после нормализации, а не начало строки: иначе /root2 считался бы лежащим внутри /root. На Windows регистр не различается — как и в самой файловой системе. Корень . — текущий каталог: внутри него лежит любой относительный путь.

php
Path::inside('/root/a/b', '/root');   // true
Path::inside('/root', '/root');       // true — совпадение считается
Path::inside('/root/../etc', '/root');   // false
Path::inside('/root2/a', '/root');    // false — префиксом не обмануть
Path::inside('C:/Root/a', 'C:/Root'); // true
Path::inside('C:/Root2/a', 'C:/Root');   // false
Path::inside('/root/a', '');          // false — пустой корень ничего не ограничивает
Path::inside('a.txt', '.');           // true
Path::inside('a/b', './');            // true
Path::inside('/a', '.');              // false — абсолютный путь не внутри текущего каталога
Path::inside('../a', '/root');        // PathFailure: путь выходит за свой корень

inside нормализует оба аргумента, поэтому отказ приходит и от неё: путь, который некуда нормализовать, не может лежать внутри каталога. File ловит этот отказ и переводит в свой FileMisuse — у него выход за корень объявлен как ошибка вызова.

inside — строковая операция: realpath не зовётся, поэтому симлинк, ведущий наружу, для неё «внутри» — ссылки разрешает File, у которого есть диск.

12.8 Html — безопасная разметка

Одно место, где значение становится безопасной разметкой. Флаги и кодировка заданы здесь, поэтому по вызовам они разойтись не могут: ENT_QUOTES экранирует обе кавычки, ENT_HTML5 берёт таблицу HTML5, ENT_SUBSTITUTE не даёт негодной кодировке превратиться в пустую строку, кодировка — UTF-8.

escape(string $value): string — экранирует значение для вывода: и в текст между тегами, и в значение атрибута.

php
Html::escape('<b>Привет</b>');     // '&lt;b&gt;Привет&lt;/b&gt;'
Html::escape('a & b');             // 'a &amp; b'
Html::escape('a "b" \'c\'');       // 'a &quot;b&quot; &apos;c&apos;' — обе кавычки
Html::escape('');                  // ''

unescape(string $value): string — возвращает экранированное значение обратно: для сравнения и повторной записи.

php
Html::unescape('&lt;b&gt;Привет&lt;/b&gt;');   // '<b>Привет</b>'
Html::unescape('&quot;a&quot; &apos;b&apos; &amp;');   // '"a" \'b\' &'
Html::unescape('просто текст');                // 'просто текст'

strip(string $value, string $allowed = ''): string — снимает теги, оставляя только их содержимое. $allowed — теги, которые надо оставить, записью strip_tags: '<b><i>'; пусто — снять все.

php
Html::strip('<b>a</b><i>b</i>');          // 'ab'
Html::strip('<b>a</b><i>b</i>', '<b>');   // '<b>a</b>b' — <b> оставлен, <i> снят
Html::strip('a < b');                     // 'a < b' — одинокая скобка не тег
Html::strip('');                          // ''

strip оставляет разрешённые теги целиком, вместе с их атрибутами: это снятие тегов, а не очистка разметки. Если значение пришло от человека, его место — в escape, а не в strip.

12.9 Http — запросы к чужим сервисам

Два способа: сразу (Http::get(...)) или цепочкой (Http::withToken(...)->acceptJson()->get(...)). Три умолчания: тело уходит как JSON, кириллица и слэши в нём не экранируются; ответы 4xx и 5xx — это ответ, а не исключение (отказом их делает Response::throw()); исключения Guzzle наружу не выходят — транспортный сбой становится HttpUnreachable.

Сразу: get, head, post, put, patch, delete

Метод Сигнатура Что уходит на ту сторону
get get(string $url, array $query = []): Response параметры в адресе
head head(string $url, array $query = []): Response ничего: только заголовки, без тела
post post(string $url, array $data = []): Response данные в теле, по умолчанию JSON
put put(string $url, array $data = []): Response данные в теле
patch patch(string $url, array $data = []): Response данные в теле
delete delete(string $url, array $data = []): Response данные в теле
php
Http::get('https://api.example.com/users', ['page' => 2]);
Http::head('https://api.example.com/users');
Http::post('https://api.example.com/users', ['name' => 'Аня']);
Http::put('https://api.example.com/users/7', ['name' => 'Аня']);
Http::patch('https://api.example.com/users/7', ['name' => 'Аня']);
Http::delete('https://api.example.com/users/7');

Каждый вызов уходит в сеть немедленно и возвращает Response. Параметры get и head попадают в адрес, данные остальных — в тело.

Начало цепочки — 16 методов. Каждый возвращает PendingRequest: тот же запрос, но ещё не отправленный. Шаги складываются, порядок между ними не важен.

withHeaders(array $headers): PendingRequest — добавляет заголовки «имя → значение»; одноимённые заменяются.

php
Http::withHeaders(['Accept-Language' => 'ru'])->get('https://api.example.com/users');
Http::withHeaders(['X-One' => '1'])->withHeaders(['X-Two' => '2'])->get('https://api.example.com/users');
// уйдут оба заголовка: X-One и X-Two

withToken(string $token, string $type = 'Bearer'): PendingRequest — ставит заголовок Authorization с токеном; вид токена по умолчанию — Bearer.

php
Http::withToken($token)->get('https://api.example.com/me');
Http::withToken($token, 'Basic')->get('https://api.example.com/me');

withBasicAuth(string $user, string $password): PendingRequest — пара логин-пароль для проверки подлинности.

php
Http::withBasicAuth('robot', $password)->get('https://api.example.com/me');

withQueryParameters(array $query): PendingRequest — постоянные параметры адреса: добавляются к параметрам самого вызова, одноимённые заменяются.

php
Http::withQueryParameters(['lang' => 'ru'])->get('https://api.example.com/users', ['page' => 2]);
// адрес: https://api.example.com/users?lang=ru&page=2

withUserAgent(string $agent): PendingRequest — представляется чужому сервису заданным именем клиента.

php
Http::withUserAgent('MawsSite/1.0')->get('https://api.example.com/users');

withCookies(array $cookies, string $domain): PendingRequest — отправляет заранее заданные печенья указанному домену.

php
Http::withCookies(['sid' => $sid], 'api.example.com')->get('https://api.example.com/me');

withBody(string $body, string $contentType = 'application/octet-stream'): PendingRequest — тело строкой как есть: готовый JSON, XML, двоичные данные. После него данные вторым аргументом отправки не принимаются — это HttpMisuse, а не молча отброшенные данные.

php
Http::withBody('{"name":"Аня"}', 'application/json')->post('https://api.example.com/users');
Http::withBody($binary)->post('https://api.example.com/upload');   // вид содержимого — octet-stream

acceptJson(): PendingRequest — просит у чужой стороны ответ в JSON (Accept: application/json).

php
Http::acceptJson()->get('https://api.example.com/users');

asJson(): PendingRequest — отправляет данные как JSON. Это умолчание; вызов нужен для читаемости цепочки.

php
Http::asJson()->post('https://api.example.com/users', ['name' => 'Аня']);

asForm(): PendingRequest — отправляет данные как форму, а не как JSON.

php
Http::asForm()->post('https://api.example.com/login', ['user' => 'robot', 'password' => $password]);

timeout(int $seconds): PendingRequest — сколько ждать ответ; 0 — без таймаута. Отрицательное число — HttpMisuse.

php
Http::timeout(5)->get('https://api.example.com/users');
Http::timeout(-1);   // HttpMisuse: таймаут не может быть отрицательным

connectTimeout(int $seconds): PendingRequest — сколько ждать установки соединения; 0 — без таймаута. Отрицательное — HttpMisuse.

php
Http::connectTimeout(2)->timeout(10)->get('https://api.example.com/users');

withoutRedirecting(): PendingRequest — не ходить по перенаправлениям: ответ 3xx вернётся как есть.

php
$res = Http::withoutRedirecting()->get('https://api.example.com/old');
$res->redirect();   // true, если сервис ответил 3xx

maxRedirects(int $redirects): PendingRequest — сколько перенаправлений разрешено. Отрицательное число — HttpMisuse.

php
Http::maxRedirects(3)->get('https://api.example.com/old');
Http::maxRedirects(-1);   // HttpMisuse

retry(int $times, int $sleepMs = 0, ?callable $when = null): PendingRequest — повторяет запрос при сбое. Без своего решения повторяются транспортный сбой и ответы 5xx; своё решение получает номер попытки, ответ и ошибку. Отрицательные числа — HttpMisuse.

php
Http::retry(3, 200)->get('https://api.example.com/users');   // до трёх повторов, пауза 200 мс

Http::retry(2, 0, fn (int $attempts, $response, $error): bool => $response?->getStatusCode() === 503)
    ->get('https://api.example.com/users');                  // повторять только на 503

withOptions(array $options): PendingRequest — сырые настройки Guzzle поверх набранных: выход для того, что хелпер не выражает.

php
Http::withOptions(['curl' => [CURLOPT_IPRESOLVE => CURL_IPRESOLVE_V4]])->get('https://api.example.com/users');

Чем цепочка заканчивается — те же шесть методов, что и у прямых вызовов, с теми же сигнатурами: get($url, array $query = []), head($url, array $query = []), post($url, array $data = []), put, patch, delete. Набранное в цепочке к этому моменту уже учтено.

send(string $method, string $url, array $data = [], array $query = []): Response — отправляет набранный запрос произвольным методом HTTP.

php
$res = Http::withToken($token)
    ->acceptJson()
    ->timeout(5)
    ->get('https://api.example.com/users', ['page' => 2]);

Http::withToken($token)->send('OPTIONS', 'https://api.example.com/users');

Ответ: Http\Response — обёртка вокруг PSR-7, а не вокруг Guzzle: движок можно заменить, не трогая этот класс. Строгость в одну сторону — промолчать нельзя: тело, которое не разбирается как JSON, и отсутствующий ключ — отказ, а не тихий null, иначе «сервер отдал HTML вместо JSON» выглядело бы как «поле пустое».

fixture(int $status = 200, string $body = '', array $headers = []): Response — собирает ответ из частей, без сети: тот же объект, что приходит от запроса. Нужен контракту и ручной сборке.

php
use Maws\System\Helpers\Http\Response as Answer;

$res = Answer::fixture(200, '{"user":{"name":"Аня"},"tags":["a","b"]}', ['X-Trace' => 'abc']);

Дальше в примерах — этот $res.

status(): int — код ответа. reason(): string — пояснение к коду словами сервера.

php
$res->status();   // 200
$res->reason();   // 'OK'

body(): string — тело строкой, как пришло.

php
$res->body();   // '{"user":{"name":"Аня"},"tags":["a","b"]}'

header(string $name): string — значение заголовка одной строкой; заголовка нет — пустая строка.

php
$res->header('X-Trace');   // 'abc'
$res->header('nope');      // ''

headers(): array — все заголовки: имя → список значений.

php
$res->headers();   // ['X-Trace' => ['abc']]

method(): string и url(): string — метод и адрес запроса, на который пришёл ответ. Пусто, если ответ собран не запросом.

php
$res->method();   // '' — ответ собран вручную
$res->url();      // ''

successful(): bool — код 2xx. ok(): bool — ровно 200. redirect(): bool — 3xx. clientError(): bool — 4xx. serverError(): bool — 5xx. failed(): bool — 4xx или 5xx.

php
$res->successful();    // true
$res->ok();            // true
$res->redirect();      // false
$res->clientError();   // false
$res->serverError();   // false
$res->failed();        // false

throw(): static — превращает отказ в исключение HttpFailed: единственный способ узнать об отказе, не проверяя код. По умолчанию отказ исключением не становится. Успешный ответ возвращается тем же объектом.

php
Http::get('https://api.example.com/users')->throw();   // HttpFailed, если ответ 4xx или 5xx

json(?string $key = null, mixed $default = null): mixed — разобранное тело. Без ключа — всё целиком; ключ — точечный путь вида 'user.name'. Ключа нет и запасное значение не задано — HttpMisuse; заданное null отличается от незаданного, поэтому json('nope', null) вернёт null молча.

php
$res->json('user.name');     // 'Аня'
$res->json('tags');          // ['a', 'b']
$res->json('nope', 'запас'); // 'запас'
$res->json('nope', null);    // null — запасное значение задано явно
$res->json('nope');          // HttpMisuse: в ответе нет ключа
$res->json();                // ['user' => ['name' => 'Аня'], 'tags' => ['a', 'b']]

object(): object — тело объектом: удобно, когда JSON — структура, а не список. Тело не объект — HttpMisuse.

php
$res->object()->user->name;   // 'Аня'

toPsrResponse(): ResponseInterface — исходный ответ по стандарту PSR-7.

php
$res->toPsrResponse()->getStatusCode();   // 200

handlerStats(): array — данные передачи: время, адрес, повторы. Пусто, если ответ собран не запросом.

php
$res->handlerStats();   // [] — у собранного вручную ответа данных передачи нет

12.10 Json — без молчаливых ошибок

JSON — единственный формат, где PHP молчит об ошибке: разбор отдаёт null, будто данные есть, а NaN и битая кодировка превращаются в 0 или в null. Здесь оба умолчания закрыты: не разобралось — отказ, не закодировалось — отказ. Кириллица и слэши пишутся как есть, чтобы тело можно было читать глазами; дробь с нулевой дробной частью остаётся дробью, иначе тип числа зависел бы от настройки serialize_precision хоста.

encode(mixed $value, bool $pretty = false): string — записывает значение строкой JSON. $pretty — с отступами и переводами строк, для чтения человеком. Не кодируется: NaN, бесконечность, не UTF-8, рекурсия — JsonMisuse.

php
Json::encode(['a' => 'Аня']);                   // '{"a":"Аня"}' — кириллица как есть
Json::encode(['url' => 'http://example.test/a/b']);   // '{"url":"http://example.test/a/b"}' — слэши как есть
Json::encode([]);                               // '[]'
Json::encode([1, 2]);                           // '[1,2]'
Json::encode(null);                             // 'null'
Json::encode(1.0);                              // '1.0' — дробь осталась дробью
Json::encode([1.0, 2]);                         // '[1.0,2]'
Json::encode(['a' => 1], true);                 // "{\n    \"a\": 1\n}" — с отступами
Json::encode(NAN);                              // JsonMisuse: не кодируется

decode(string $json, bool $assoc = true): mixed — разбирает строку JSON. $assoc — true: объекты становятся массивами; false: объектами, тогда пустой объект отличим от пустого списка. Пустая строка и мусор — JsonMisuse, а не null: «данных нет» и «данные не разобрались» обязаны различаться.

php
Json::decode('{"a":1}');             // ['a' => 1]
Json::decode('{"a":{"b":[1,2]}}');   // ['a' => ['b' => [1, 2]]]
Json::decode('[]');                  // []
Json::decode('"текст"');             // 'текст'
Json::decode('123');                 // 123
Json::decode('true');                // true
Json::decode('null');                // null
Json::decode('{}', false);           // объект, а не пустой массив
Json::decode('{');                   // JsonMisuse: строка не разбирается
Json::decode('');                    // JsonMisuse: пустая строка — не JSON
Json::decode('{"a":}');              // JsonMisuse

12.11 Csv — таблицы для Excel

Обмен таблицами с Excel и подобными: строки и клетки, где всё — текст. Три вещи, на которых CSV обычно ломается, решены явно: разделитель объявляется (в русском Excel это точка с запятой), метка BOM при чтении снимается и ставится при записи по просьбе, конец строки — CRLF, как в RFC 4180. Значения не угадываются: '007' остаётся '007', '1,50' — текстом.

encode(array $rows, string $delimiter = ',', bool $bom = false): string — пишет таблицу строкой. Клетка с разделителем, кавычкой или переводом строки берётся в кавычки, внутренние кавычки удваиваются. Строки — списки клеток; если строки-словари, первая задаёт заголовок, а набор колонок в остальных обязан совпасть — иначе клетка потерялась бы молча. $bom ставит метку UTF-8: без неё Excel показывает кириллицу мусором. Разделитель — ровно один знак, не кавычка и не перевод строки.

php
Csv::encode([['a', 'b'], ['1', '2']]);                 // "a,b\r\n1,2\r\n"
Csv::encode([['а, б', 'с']]);                          // "\"а, б\",с\r\n" — запятая в клетке
Csv::encode([['он сказал "да"']]);                     // "\"он сказал \"\"да\"\"\"\r\n"
Csv::encode([['первая', 'вторая']], ';');              // "первая;вторая\r\n"
Csv::encode([['id', 'имя'], ['1', 'Аня']], ',', true); // "\xEF\xBB\xBFid,имя\r\n1,Аня\r\n" — с BOM
Csv::encode([['a' => '1', 'b' => '2'], ['a' => '3', 'b' => '4']]);   // "a,b\r\n1,2\r\n3,4\r\n"
Csv::encode([]);                                       // ''
Csv::encode([['a' => '1'], ['b' => '2']]);             // CsvMisuse: набор колонок разный
Csv::encode([['a', 'b'], ['a' => '1', 'b' => '2']]);   // CsvMisuse: список и словарь в одной таблице
Csv::encode([['a']], '');                              // CsvMisuse: разделитель не один знак
Csv::encode([['a']], '"');                             // CsvMisuse: кавычка — разметка, не разделитель

decode(string $csv, string $delimiter = ',', string $encoding = 'UTF-8'): array — читает таблицу как есть: список строк, все клетки — строки. Пустые строки пропускаются — это не данные; BOM снимается; кодировка объявляется, а не угадывается, потому что угадывание портит кириллицу молча. Наружу текст всегда в UTF-8.

php
Csv::decode("a,b\r\n1,2\r\n");                        // [['a', 'b'], ['1', '2']]
Csv::decode("a;b\r\n1;2\r\n", ';');                   // [['a', 'b'], ['1', '2']]
Csv::decode("\xEF\xBB\xBFid,имя\r\n1,Аня\r\n");       // [['id', 'имя'], ['1', 'Аня']] — BOM снят
Csv::decode("a,b\r\n\r\n1,2\r\n");                    // [['a', 'b'], ['1', '2']] — пустая строка пропущена
Csv::decode("\"а, б\",с\r\n");                        // [['а, б', 'с']]
Csv::decode("\"первая\r\nвторая\",x\r\n");            // [["первая\r\nвторая", 'x']] — перевод строки в клетке
Csv::decode('');                                      // []
Csv::decode("\xE8\xEC\xFF\r\n\xC0\xED\xFF\r\n", ',', 'Windows-1251');   // [['имя'], ['Аня']]
Csv::decode("\xB1");                                  // CsvMisuse: не в объявленной кодировке
Csv::decode('a,b', ',, ');                            // CsvMisuse: разделитель не один знак

table(string $csv, string $delimiter = ',', string $encoding = 'UTF-8'): array — читает таблицу с заголовком: первая строка — имена колонок, дальше строки-словари. Заголовок с повтором или без имени — отказ, как и строка другой ширины: иначе значение привязалось бы не к той колонке, а заметить это было бы нечем.

php
Csv::table("id,имя\r\n1,Аня\r\n2,Ёж\r\n");
// [['id' => '1', 'имя' => 'Аня'], ['id' => '2', 'имя' => 'Ёж']]

Csv::table("id;имя\r\n1;Аня\r\n", ';');   // [['id' => '1', 'имя' => 'Аня']]
Csv::table('');                           // []
Csv::table("id,id\r\n1,2\r\n");           // CsvMisuse: две колонки с одним именем
Csv::table("id,\r\n1,2\r\n");             // CsvMisuse: колонка без имени
Csv::table("id,имя\r\n1\r\n");            // CsvMisuse: клеток меньше, чем в заголовке
Csv::table("id,имя\r\n1,Аня,лишнее\r\n"); // CsvMisuse: клеток больше

Для русского Excel — разделитель ; и bom: true, иначе кириллица покажется мусором. При чтении такого файла обратно разделитель надо назвать тем же: Csv::table($csv, ';').

12.12 Cookie — заголовок Set-Cookie

Собирает строку Set-Cookie так, чтобы браузер её принял, а не выбросил молча: имя сверяется с правилами RFC 6265, значение кодируется, SameSite=None без Secure отвергается, а префиксы __Host- и __Secure- получают свои обязательные условия. Само печенье не отправляется: хелпер отдаёт заголовок, потому что отправка зависит от того, как устроен ответ сайта.

create(string $name, string $value, ?int $expires = null, string $path = '/', ?string $domain = null, bool $secure = true, bool $httpOnly = true, ?string $sameSite = 'Lax'): string

Параметр Тип По умолчанию Смысл
$name string — имя по RFC 6265: латиница, цифры и !#$%&'*+-.^_`|~
$value string — значение как есть; кодируется само, поэтому читать его надо как обычное значение из $_COOKIE
$expires ?int null метка времени, когда печенье истечёт; null — до закрытия браузера
$path string '/' путь, на котором печенье видно; начинается со слэша
$domain ?string null хост, которому печенье принадлежит; null — только текущий
$secure bool true только по https; на боевом сайте обязан быть включён
$httpOnly bool true скрыть от JavaScript — тогда украденный скрипт печенье не прочитает
$sameSite ?string 'Lax' Lax, Strict или None; null — не указывать вовсе

Secure по умолчанию включён: без него печенье уходит и по http, то есть его можно перехватить, а заметить это в работе сайта нечем — локальная разработка без TLS снимает его явно. SameSite=None требует Secure; __Secure- требует Secure; __Host- требует Secure, Path=/ и отсутствия Domain. Нарушение — CookieMisuse.

php
Cookie::create('sid', 'abc');
// 'sid=abc; Path=/; Secure; HttpOnly; SameSite=Lax'

Cookie::create('sid', 'abc', 1445412480);
// 'sid=abc; Expires=Wed, 21 Oct 2015 07:28:00 GMT; Path=/; Secure; HttpOnly; SameSite=Lax'

Cookie::create('sid', 'Аня');
// 'sid=%D0%90%D0%BD%D1%8F; Path=/; Secure; HttpOnly; SameSite=Lax' — значение закодировано

Cookie::create('sid', 'a b;c');
// 'sid=a%20b%3Bc; Path=/; Secure; HttpOnly; SameSite=Lax'

Cookie::create('sid', 'abc', null, '/', 'example.test');
// 'sid=abc; Path=/; Domain=example.test; Secure; HttpOnly; SameSite=Lax'

Cookie::create('sid', 'abc', null, '/', null, false, false, null);
// 'sid=abc; Path=/' — ни Secure, ни HttpOnly, ни SameSite

Cookie::create('sid', 'abc', null, '/', null, true, true, 'strict');
// 'sid=abc; Path=/; Secure; HttpOnly; SameSite=Strict' — регистр приведён

Cookie::create('__Host-sid', 'abc');
// '__Host-sid=abc; Path=/; Secure; HttpOnly; SameSite=Lax'

Cookie::create('__Host-sid', 'abc', null, '/', 'example.test');   // CookieMisuse: __Host- с Domain
Cookie::create('__Host-sid', 'abc', null, '/app');                // CookieMisuse: __Host- только с Path=/
Cookie::create('__Secure-sid', 'abc', null, '/', null, false);    // CookieMisuse: __Secure- требует Secure
Cookie::create('sid name', 'abc');                                // CookieMisuse: имя не по RFC
Cookie::create('', 'abc');                                        // CookieMisuse: имя пустое
Cookie::create('sid', 'abc', null, 'app');                        // CookieMisuse: путь без слэша
Cookie::create('sid', 'abc', null, '/', null, false, true, 'None');   // CookieMisuse: None без Secure
Cookie::create('sid', 'abc', null, '/', null, true, true, 'Laxa');    // CookieMisuse: нет такого SameSite

forget(string $name, string $path = '/', ?string $domain = null, bool $secure = true): string — собирает Set-Cookie, который стирает печенье: пустое значение и срок в 1970 году. Имя, путь и домен обязаны совпасть с исходными — браузер ищет печенье по ним, и промах оставляет старое на месте.

php
Cookie::forget('sid');
// 'sid=; Expires=Thu, 01 Jan 1970 00:00:00 GMT; Path=/; Secure; HttpOnly; SameSite=Lax'

Cookie::forget('sid', '/app', 'example.test');
// 'sid=; Expires=Thu, 01 Jan 1970 00:00:00 GMT; Path=/app; Domain=example.test; Secure; HttpOnly; SameSite=Lax'

Cookie::forget('sid name');   // CookieMisuse: имя не по RFC

12.13 Token — непредсказуемые строки

Непредсказуемая строка, которую предъявляют вместо пароля: метка формы против подделки запроса, идентификатор сессии, ссылка сброса пароля, ключ доступа. Случайность только криптографическая — угадываемый токен перестаёт быть токеном, поэтому rand, mt_rand, uniqid и время по назначению не годятся. Три вида записи: для адреса, для хранения, для человека.

url(int $bytes): string — токен для адреса: годится в ссылку и в имя параметра без кодирования — ни плюсов, ни слэшей, ни знаков выравнивания. Знаки A-Z a-z 0-9 - _, на каждые 16 байт — 22 знака. Меньше 16 байт — TokenMisuse: такой токен подбирается.

php
Token::url(16);   // 22 знака из A-Z a-z 0-9 - _
Token::url(32);   // 43 знака
Token::url(15);   // TokenMisuse: случайности меньше 16 байт
Token::url(0);    // TokenMisuse
Token::url(-1);   // TokenMisuse

hex(int $bytes): string — токен для хранения и сравнения: только 0-9 и a-f, ровно два знака на байт — длина сразу говорит, сколько в нём случайности. На 16 байт — 32 знака.

php
Token::hex(16);   // 32 знака: 0-9 и a-f
Token::hex(32);   // 64 знака
Token::hex(15);   // TokenMisuse

digits(int $digits): string — код для человека: только цифры, чтобы его можно было продиктовать голосом и перепечатать с бумаги. Первая цифра не ноль — иначе код, сохранённый числом, теряет знак и принимает более короткий ввод. Меньше шести цифр — TokenMisuse.

php
Token::digits(6);   // 6 цифр, первая — от 1 до 9
Token::digits(10);  // 10 цифр
Token::digits(5);   // TokenMisuse: короче шести подбирается
Token::digits(0);   // TokenMisuse

same(string $expected, string $given): bool — сверяет предъявленный токен с сохранённым за постоянное время, чтобы по времени ответа нельзя было подбирать знак за знаком. Пустая строка не совпадает ни с чем, включая пустую: незаполненная метка не должна проходить проверку.

php
Token::same('abc', 'abc');   // true
Token::same('abc', 'abd');   // false
Token::same('abc', 'ab');    // false — совпадение только целиком
Token::same('', '');         // false
Token::same('abc', '');      // false

Минимумы (16 байт, 6 цифр) — часть обещания «неподбираемый», а не настройка. Источник случайности недоступен — TokenFailure: это сбой окружения, а не ошибка вызова.

12.14 Csrf — токен форм

Защита от чужой формы: токен заводится на сессию и сверяется при отправке. Сессию открывает вход (Session::open() в public/index.php), хелперу остаётся её хранилище.

field(): string — имя поля формы, в котором едет токен. Одно на весь фреймворк: шаблон и проверка не могут разойтись в написании.

php
Csrf::field();   // '_csrf' — подчёркивание впереди, чтобы не спутать с чужим полем token

token(): string — отдаёт токен форм, заводя его при первом обращении и сохраняя на всю сессию: две открытые вкладки не мешают друг другу.

php
Csrf::token();   // 64 знака: 0-9 и a-f — 32 байта случайности

verify(array $source): bool — проверяет отправленные поля целиком: сам берёт токен из формы и сравнивает с тем, что лежит в сессии. Один вызов вместо трёх строк, в которых забывают половину. Токен не заводит: проверка ничего не меняет, и сессия без токена даёт отказ, а не новый токен.

php
Csrf::verify($_POST);   // true — токен в форме есть и совпал с сессионным

check(?string $given, ?string $stored): bool — чистое сравнение за постоянное время: нужно, когда токен пришёл не полем формы — заголовком или в теле JSON. Пустое с пустым не совпадает: иначе форма без токена и сессия без токена «сходились» бы, то есть защита пропускала бы ровно тот случай, ради которого стоит.

php
Csrf::check('abc', 'abc');   // true
Csrf::check('abc', 'abd');   // false
Csrf::check('', '');         // false
Csrf::check(null, null);     // false
Csrf::check('abc', null);    // false

rotate(): void — забывает прежний токен и заводит новый. Нужен там, где меняются права: иначе токен, украденный до входа, остаётся годным после него.

php
Csrf::rotate();   // следующий token() отдаст другой токен

Вход (Session::grant()) гасит токен сам: токен, известный до входа, не должен пережить вход. После grant() первый же token() заведёт новый.

В форму — скрытое поле, в обработчик — проверка до любой записи в базу:

php
// разметка
<input type="hidden" name="<?= Csrf::field() ?>" value="<?= Csrf::token() ?>">

// место, до записи
if (!Csrf::verify($_POST)) {
    return 'Страница была открыта давно — проверьте данные и отправьте ещё раз';
}

Проверку выбирает разработчик. Ядро не отказывает POST-у без токена и не смотрит, есть ли в форме поле: положили поле — проверьте его, не положили — проверять нечего. Принудительный режим ломал бы законные случаи: страница в публичном кэше не может нести токен (он был бы общим для всех посетителей), у посетителя с заблокированными печеньями сессия новая на каждый запрос, а фоновая отправка (тело JSON, полей формы нет) пришла бы без токена.

verify() не заводит токен: сессия без токена даёт отказ, а не новый. check() остаётся для случая, когда токен пришёл не полем формы — заголовком или в теле JSON.

Просроченная форма — ветка, а не 403. Посетитель ничего не нарушил; покажите ту же форму с объяснением. 403 здесь неверен ещё и потому, что показать его нечем: Error — страница «500».

rotate() — после смены прав. Вход, выход, смена пароля: токен, украденный до входа, иначе остаётся годным после него.

12.15 Hash — три разные двери

Три разные вещи, которые нельзя путать: хеш пароля медленный, с солью, при каждом вызове другой и проверяется только сверкой; контрольная сумма быстрая и повторяемая — годится лишь для «данные не изменились»; подпись с ключом доказывает, что данные пришли от того, у кого ключ. Отсюда три двери, и общего «просто хешируй» нет.

password(string $password): string — хеширует пароль для хранения: медленно и с солью, поэтому одинаковые пароли дают разные строки. Проверять только через verify — сравнивать строки бессмысленно. Bcrypt смотрит на первые 72 байта: это его предел, а не наш; нулевой байт он не принимает вовсе.

php
Hash::password('секрет');   // строка вида '$2y$10$…' — своя при каждом вызове

verify(string $password, string $hash): bool — отвечает, тот ли это пароль, за постоянное время. Испорченное или пустое значение в базе — это «не тот», а не сбой: вход должен отказать, а не упасть. Пароль с нулевым байтом не совпадает ни с чем: такой нечем было сохранить, а bcrypt молча обрезал бы его по нулю и принял чужой хвост.

php
Hash::verify('секрет', '$2y$10$VnNbMM4lfyYMt8xcfYB2UOjgeMdCMwDJJK0KbEbgfkjGFF8nUPRcO');   // true
Hash::verify('Секрет', '$2y$10$VnNbMM4lfyYMt8xcfYB2UOjgeMdCMwDJJK0KbEbgfkjGFF8nUPRcO');   // false
Hash::verify('секрет', '');        // false — в базе пусто
Hash::verify('секрет', 'не хеш');  // false — в базе мусор

needsRehash(string $hash): bool — отвечает, устарела ли сохранённая строка: сменился алгоритм или его стоимость — значит при следующем входе пароль надо перехешировать, иначе защита останется на уровне, выбранном годы назад.

php
Hash::needsRehash('$2y$10$VnNbMM4lfyYMt8xcfYB2UOjgeMdCMwDJJK0KbEbgfkjGFF8nUPRcO');   // false
Hash::needsRehash('не хеш');   // true — пересчитать текущим способом

digest(string $value, string $algo = 'sha256'): string — контрольная сумма: быстро и повторяемо, чтобы сравнить «до» и «после». Для паролей не годится — там password; и секретов она не скрывает, а только опознаёт содержимое. Алгоритм — имя из hash_algos(), неизвестное — HashMisuse.

php
Hash::digest('abc');   // 'ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad'
Hash::digest('');      // 'e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855'
Hash::digest('привет', 'md5');   // '608333adc72f545078ede3aad71bfe74'
Hash::digest('abc', 'nope');     // HashMisuse: алгоритма нет

sign(string $value, string $key, string $algo = 'sha256'): string — подписывает данные ключом: подпись может повторить только тот, у кого тот же ключ, поэтому она отличает «пришло от своего» от «пришло от кого угодно». Пустой ключ не ключ — это ошибка, а не настройка.

php
Hash::sign('данные', 'ключ');   // '735e97ea09bca778813114ffb283c41115d47dabf70d31e857b29f089cd7a3b2'
Hash::sign('данные', 'ключ', 'md5');   // '6585d1de097be89b632ecb5ac4274560'
Hash::sign('данные', '');              // HashMisuse: подпись без ключа ничего не доказывает
Hash::sign('данные', 'ключ', 'nope');  // HashMisuse: алгоритма нет

same(string $expected, string $given): bool — сверяет сумму или подпись за постоянное время, чтобы по времени ответа нельзя было подбирать знак за знаком. Пустая строка не совпадает ни с чем, включая пустую: непосчитанное не должно сходить за совпавшее.

php
Hash::same('abc', 'abc');   // true
Hash::same('abc', 'abd');   // false
Hash::same('', '');         // false

Не путайте двери: digest — «данные не изменились», sign — «пришло от того, у кого ключ», password — «это тот пароль». Для пароля digest не годится.

12.16 Image — картинка как значение

Байты на входе, байты на выходе; файлов не трогает — читать и писать их умеет File. Две операции закрывают почти всё, что нужно сайту: fit вписывает в рамку, не растягивая маленькое, cover заполняет рамку с обрезкой по центру, как аватарка. Прозрачность сохраняется, потому что иначе у PNG она стала бы чёрной.

fromString(string $bytes): static|false — читает картинку из байтов. Не картинка, пустые байты или формат, которого GD не знает, — false: это ответ о данных, а не сбой, и вызывающий обязан его проверить.

php
Image::fromString($bytes);                     // картинка, если в байтах изображение
Image::fromString("\xB1\xB2\xB3");             // false
Image::fromString('');                         // false
Image::fromString('это текст, а не картинка'); // false

width(): int и height(): int — ширина и высота в точках. format(): string — вид, в котором картинка пришла: png, jpeg, gif, webp, avif или bmp. По нему toBytes без аргумента выбирает запись.

php
$image = Image::fromString($bytes);   // картинка 4×2 в GIF

$image->width();    // 4
$image->height();   // 2
$image->format();   // 'gif'

fit(int $width, int $height): static — вписывает картинку в рамку, сохраняя пропорции. Маленькую не растягивает: увеличенная миниатюра всегда мутнее исходника, поэтому рамка — предел, а не цель. Сторона рамки меньше единицы — ImageMisuse. Возвращает эту же картинку, цепочка продолжается.

php
Image::fromString($bytes)->fit(2, 2);     // было 4×2, стало 2×1 — вписалась по ширине
Image::fromString($bytes)->fit(10, 10);   // осталась 4×2: маленькую не растягиваем
Image::fromString($bytes)->fit(2, 1);     // 2×1 — пропорции те же
Image::fromString($bytes)->fit(0, 2);     // ImageMisuse: сторона рамки меньше единицы

cover(int $width, int $height): static — заполняет рамку целиком, обрезая лишнее по центру. Маленькую растягивает: cover обещает ровно такой размер, а не «не больше». Сторона меньше единицы — ImageMisuse.

php
Image::fromString($bytes)->cover(2, 2);     // 2×2 — обрезала по центру
Image::fromString($bytes)->cover(1, 1);     // 1×1
Image::fromString($bytes)->cover(8, 8);     // 8×8 — растянула
Image::fromString($bytes)->cover(-1, -1);   // ImageMisuse

toBytes(?string $format = null, int $quality = 90): string — записывает картинку байтами. Без вида берётся тот, в котором она пришла. $quality — от 0 до 100 для jpeg, webp и avif; png и gif пишутся без потерь. У jpeg и bmp прозрачности нет, поэтому прозрачные места заливаются белым — иначе они стали бы чёрными. Вид не из списка или качество вне 0…100 — ImageMisuse; эта сборка GD такой вид не умеет — ImageFailure.

php
$image->toBytes();            // байты в исходном виде — здесь GIF
$image->toBytes('webp', 80);  // байты WebP с качеством 80
$image->toBytes('jpeg');      // качество по умолчанию — 90, прозрачное станет белым
$image->toBytes('tiff');      // ImageMisuse: такой вид не пишется
$image->toBytes('png', 101);  // ImageMisuse: качество вне 0…100

12.17 Upload — файл из формы

Принимает присланный файл и кладёт его в каталог под новым именем. Исходное имя не используется никогда: имя собирается из случайных байтов, а расширение берётся из присланного и только из разрешённых. Поэтому shell.php.jpg становится безобидным a1b2….jpg, а ../ в имени ничего не значит. Содержимое сверяется с расширением: имя файла — это заявление посетителя, а не факт.

accepts(string $name, array $types): bool — отвечает, годится ли расширение присланного имени. Содержимое здесь не смотрится: имя о нём ничего не говорит, для этого есть fits. Список приводится к одному виду — строчными и без точки, поэтому 'JPG', '.jpg' и 'jpg' значат одно и то же. Пустой список или расширение вне стандартного — UploadMisuse, а не «пропустить всё».

php
Upload::accepts('shell.php.png', ['png']);    // true — смотрится последнее расширение
Upload::accepts('photo.JPG', ['.jpg']);       // true — регистр и точка не мешают
Upload::accepts('note.txt', ['jpg', 'png']);  // false
Upload::accepts('noext', ['jpg']);            // false — расширения нет
Upload::accepts('.gitignore', ['jpg']);       // false — точка в начале имени не расширение
Upload::accepts('a.png', []);                 // UploadMisuse: пустой список
Upload::accepts('a.svg', ['svg']);            // UploadMisuse: svg нет в стандартном списке

fits(string $extension, string $detected): bool — сверяет определённый по содержимому тип с тем, что обещает расширение. Параметры вида ; charset=utf-8 и регистр не мешают.

php
Upload::fits('png', 'IMAGE/PNG');                   // true
Upload::fits('txt', 'text/plain; charset=utf-8');   // true
Upload::fits('docx', 'application/zip');            // true — так часть сборок видит OOXML
Upload::fits('png', 'text/x-php');                  // false — в png лежит PHP
Upload::fits('png', '');                            // false — тип не определён
Upload::fits('svg', 'image/svg+xml');               // UploadMisuse: расширения нет в списке

tooBig(int $size, int $maxBytes): bool — отвечает, больше ли файл объявленного предела. Ровно предел годится: «до стольких-то байт» включает само число, а не заканчивается перед ним. Ноль значит «своего предела нет»: размер держит php.ini, и хелпер в это не вмешивается. Отрицательный предел — UploadMisuse: это опечатка, а не запрет загрузок.

php
Upload::tooBig(1000, 1000);   // false — ровно предел ещё годится
Upload::tooBig(1001, 1000);   // true
Upload::tooBig(1000, 0);      // false — предела нет
Upload::tooBig(0, 0);         // false
Upload::tooBig(0, -1);        // UploadMisuse

refusal(int $error): ?array — переводит код отказа загрузки из $_FILES[...][error] в ответ для посетителя. null — «виноват не файл»: либо файл принят, либо сломалось окружение, и тогда вызывающий получает исключение от upload.

php
Upload::refusal(UPLOAD_ERR_NO_FILE);
// ['status' => 'error', 'message' => 'файл не выбран', 'name' => null]

Upload::refusal(UPLOAD_ERR_INI_SIZE);
// ['status' => 'error', 'message' => 'файл больше допустимого размера', 'name' => null]

Upload::refusal(UPLOAD_ERR_FORM_SIZE);
// ['status' => 'error', 'message' => 'файл больше допустимого размера', 'name' => null]

Upload::refusal(UPLOAD_ERR_PARTIAL);
// ['status' => 'error', 'message' => 'файл пришёл не полностью — отправку оборвали', 'name' => null]

Upload::refusal(UPLOAD_ERR_CANT_WRITE);   // null — сломалось окружение, а не файл
Upload::refusal(UPLOAD_ERR_OK);           // null — файл принят

upload(string $field, string $dir, array $types = [], int $maxBytes = 0): array — переносит присланный файл в каталог и отдаёт ответ: имя сохранённого файла или причину отказа словами.

Параметр Тип По умолчанию Смысл
$field string — имя поля формы — ключ в $_FILES
$dir string — каталог, куда положить файл; должен уже существовать
$types array [] разрешённые расширения без точки; пустой список — отказ, а не «пропускать всё»
$maxBytes int 0 предел в байтах; 0 — только upload_max_filesize из php.ini
php
// app/config.php — путь к каталогу, который вы создали сами
const UPLOADS_DIR = __DIR__ . '/../public/uploads';

// место
$result = Upload::upload('photo', UPLOADS_DIR, ['jpg', 'png'], 2 * 1024 * 1024);

if ($result['status'] === Upload::OK) {
    $name = $result['name'];    // '9f3c…a1.jpg' — его и храните в базе
} else {
    echo $result['message'];    // 'содержимое файла не соответствует расширению'
}

Ответ — всегда массив из трёх ключей: status (Upload::OK / Upload::ERROR), message (что сказать человеку; при успехе пустая строка) и name (новое имя файла или null).

Отказ по вине файла — ответ, а не исключение. Нет файла, слишком большой, тип не тот, содержимое не соответствует расширению — сайт показывает message рядом с формой. Исключение только там, где посетителю сказать нечего: UploadFailure (PHP не принял файл, не перенести, не определить тип) и UploadMisuse (пустой список расширений, каталога нет, поле пришло не из формы).

Что проверяется и в каком порядке: расширение — по списку разрешённых; размер — до чтения файла, потому что он дешевле; содержимое — через finfo и сверку с расширением. Имя файла — заявление посетителя, а не факт: photo.png с PHP внутри не пройдёт.

Список расширений закрыт — 14 штук: jpg, jpeg, png, gif, webp, pdf, txt, csv, zip, doc, docx, xls, xlsx, pptx. Чего в нём нет, того загрузка не примет, даже если попросить: иначе «разрешил doc» означало бы «разрешил что угодно под именем doc». svg нет намеренно — это XML со скриптами внутри, и открытый напрямую файл исполнит их на нашем же домене.

Каталог не создаётся молча. Нет каталога — UploadMisuse. Скрытое mkdir означало бы, что путь для записи появился там, где его никто не планировал.

Части без файла — accepts(), fits(), tooBig(), refusal() — чистые: строка или число на входе, да или нет на выходе. Поэтому они проверяются прогоном, а сам upload() — только живой формой: $_FILES и is_uploaded_file подделать нельзя.

12.18 Response — исходящий ответ

Отправляет ответ и заканчивает работу места: сцена после него не рисуется. Подробности и правила — §10.2.

send(mixed $data, int $status = 200, ?string $type = null): never — отправляет ответ: выставляет код и тип, печатает тело. Строка уходит как есть, массив или объект — в JSON. Тип по умолчанию: text/html; charset=utf-8 для строки и application/json; charset=utf-8 для остального. Код вне 100–599 или уже начатый вывод — ResponseMisuse; данные не кодируются в JSON — JsonMisuse. Возврата нет: метод всегда заканчивается ResponseSent, поэтому never.

php
Response::send('<h1>Ответ места</h1>');                  // тело как есть, тип text/html
Response::send('{"ok":true}', 200, 'application/json');  // тип задан явно
Response::send('тело', 700);   // ResponseMisuse: 700 — не код ответа
Response::send('тело', 99);    // ResponseMisuse: 99 — не код ответа

json(mixed $data, int $status = 200): never — отправляет JSON и завершает работу места: то же, что send с типом application/json, но короче на вызове.

php
Response::json(['ok' => true]);        // '{"ok":true}' с типом application/json
Response::json(['ok' => true], 201);   // тот же JSON с кодом 201

Оба ставят Cache-Control: no-store: ответ собран под конкретный запрос, политику места (§10.3) он не спрашивает и в кэш не попадает.

Не путать с Http\Response: тот разбирает ответ чужого сервиса, этот отправляет свой.

Кэш в этот список не входит. Cache и Policy — не хелперы, а часть ядра (core/System/Cache/): вызывать их не нужно, они включаются настройкой места в settings.json и работают сами — §10.3.

13. Агенты

Агент — фоновый процесс. У него нет ни тела, ни места: точка входа — сам файл агента, запускается как обычный скрипт.

Инструмент места живёт внутри запроса: человек дошёл, место взяло инструменты, serve() вернул строку. Агент живёт отдельно от сайта — ни маршрута, ни сцены, ни $_GET у него нет. Поэтому core/Ai/** не берёт ни одного типа из Maws\World, Maws\Man, Maws\Screen: агента можно унести в отдельный воркер и проверить без сайта. И поэтому же инструменты места агенту не видны — свои он объявляет сам, а к данным ходит через dbaccess.json и AiDbase.

13.1 Быстрый старт

bash
php maws.php make agent

Команда спрашивает тип — single (один агент), multi (несколько агентов в каталоге), supervisor (надзиратель, который запускает других). У multi и supervisor дальше спросит имя, у single не спросит: каталог app/Ai/Single один. Получаются три файла:

app/Ai/Single/Agent.php
app/Ai/Single/tools.json
app/Ai/Single/instruction.prompt.php

Запуск — обычный php-скрипт, без сервера и маршрута:

bash
php app/Ai/Single/Agent.php "bye"       # bye
php app/Ai/Single/Agent.php "привет"    # hello

Имя класса — имя файла, пространство имён — путь от app/: app/Ai/Single/Agent.php объявляет App\Ai\Single\Agent. У мульти-агента свой каталог: app/Ai/Multi/{Имя}/{Имя}.php → App\Ai\Multi\{Имя}\{Имя}.

13.2 Откуда берётся задача

Задача приходит одной строкой и уходит одной строкой:

php
public function work(string $task): string
{
    $call   = $this->callLLM($task);
    $result = $this->callTool($call['name'], $call['arguments']);

    return $result['content']['text'];
}

В демо задачу даёт аргумент командной строки, и процесс после неё остаётся жить:

php
if (basename($_SERVER['SCRIPT_FILENAME'] ?? '') === basename(__FILE__)) {
    $done = 0;

    while (1) {
        if ($done == 0) {
            echo (new Agent())->work($argv[1] ?? 'поздоровайся') . "\n";

            $done = 1;
        }
    }
}

Блок срабатывает только при прямом запуске файла: когда класс подключают через require из другого кода, он молчит. Цикл в демо холостой намеренно — задача одна, а процесс должен жить. В рабочем коде на его месте стоит блокирующее ожидание задачи у брокера (Redis, RabbitMQ — что выберет разработчик): процесс спит, пока задачи нет, и просыпается на новую.

work() — соглашение примеров и шаблонов make agent, а не метод базового класса. Maws\Ai\Ai даёт пять дверей, и ни одна из них не называется «задача»:

Метод Что делает
rights() права на таблицы из dbaccess.json
listTools() читает tools.json
callTool($name, $arguments) вызывает инструмент по имени
getToolsPromptXml() XML-описание инструментов для подсказки
getPrompt($data) собирает подсказку из instruction.prompt.php

Точку входа задачи автор выбирает сам: work, handle, run — как удобнее. От имени не зависит ничего, кроме того, кто её зовёт.

13.3 Как агент получает инструменты

Цепочка одна, и в ней четыре звена.

Объявление — tools.json в каталоге агента, формат MCP:

json
[
  {
    "name": "sayHello",
    "description": "Здоровается указанное число раз",
    "inputSchema": {
      "type": "object",
      "properties": { "amount": { "type": "integer" } },
      "required": ["amount"]
    }
  }
]

Реализация — метод с тем же именем. Он принимает массив аргументов и возвращает строку; конверт (content/isError) собирает фреймворк:

php
public function sayHello(array $arguments): string
{
    return implode(' ', array_fill(0, (int) $arguments['amount'], 'hello'));
}

Подсказка — конструктор агента собирает описание инструментов и подставляет его в шаблон:

php
public function __construct()
{
    $this->agentDir = __DIR__;
    $this->prompt   = $this->getPrompt(['toolsListXml' => $this->getToolsPromptXml()]);
}

getToolsPromptXml() отдаёт <available_tools> (имя, описание, схема) и <tool_calling_examples> — по примеру вызова на каждый инструмент. instruction.prompt.php — обычный PHP-шаблон, который получает этот XML и должен оставить строку $prompt:

php
$prompt = <<< END
<instruction>
Скажи hello один раз.
Для выполнения используй эти инструменты:

{$toolsListXml}
</instruction>
END;

Вызов — модель выбрала инструмент, агент зовёт его по имени:

php
$result = $agent->callTool('sayHello', ['amount' => 3]);

$result['isError'];            // false
$result['content']['text'];    // 'hello hello hello'

Перед вызовом аргументы сверяются со схемой: обязательные поля, типы (integer, number, string, boolean, array, object, null), enum, minimum, maximum. Ошибка вызова — нет такого инструмента, не тот тип, нет обязательного поля — это ответ для модели: isError => true и текст причины, исключения нет. Исключение — только сбой объявления или кода: tools.json не читается или инструмент объявлен, а метода с таким именем у агента нет.

Подсказку фреймворк только собирает: $this->prompt никуда не отправляется. Её читает callLLM() — тот метод, который решает, что делать с задачей.

13.4 Доступ к базе

Права лежат в dbaccess.json рядом с агентом:

json
{ "tables": ["public.test_table"] }
php
class Agent extends Ai
{
    public function demoRead(): void
    {
        $db = new AiDbase($this->rights(), DBASE_DSN, DBASE_USER, DBASE_PASSWORD);
        $rows = $db->all('SELECT id, name FROM public.test_table');
    }
}
  • $this->rights() — единственная дверь к правам; нет файла — AccessNotDeclared.
  • AiDbase повторяет Dbase: те же all/one/run, тот же selectUnplanned с чёрным списком функций и сверкой по факту (§9.3), та же проверка по плану.
  • Агент, который базы не касается, файла может не иметь.

13.5 Где подключается модель

Единственное место, которое меняется при подключении настоящей модели, — callLLM($task). В демо он зашит: просьба попрощаться — sayBye, остальное — sayHello.

php
public function callLLM($task = null)
{
    return str_contains((string) $task, 'bye')
        ? ['name' => 'sayBye', 'arguments' => ['amount' => 1]]
        : ['name' => 'sayHello', 'arguments' => ['amount' => 1]];
}

Вернуть нужно имя инструмента и аргументы: ['name' => …, 'arguments' => […]]. У надзирателя ответ — список таких вызовов, по одному на действие.

Подменена только модель. Всё остальное в демо настоящее: callTool() идёт через listTools(), разбор tools.json и проверку аргументов по inputSchema, а инструмент отвечает по-настоящему. Смысл двоякий: слой работает без внешних сервисов, и подключение модели не меняет архитектуру — правится один метод.

13.6 Агент зовёт агента

Сосед — такой же класс со своим tools.json, своей подсказкой и своими правами. Чтобы позвать его, достаточно объявить инструмент и сделать new в методе:

php
public function askAgent2(array $arguments): string
{
    return (new Agent2())->work((string) $arguments['task']);
}

Ни процесса, ни строки через консоль: задача приходит аргументом, ответ возвращается строкой. Чужие tools.json и dbaccess.json в этот вызов не попадают — каталог объявлений у каждого свой и снаружи закрыт.

Надзиратель устроен так же, только его инструменты — другие агенты. Supervisor объявляет подчинённых в своём tools.json ровно как инструменты:

json
{
  "name": "sayHelloAgent",
  "description": "Агент, который здоровается. Принимает задачу и отвечает приветствием",
  "inputSchema": {
    "type": "object",
    "properties": { "task": { "type": "string" } },
    "required": ["task"]
  }
}

Модель получает их через getToolsPromptXml() и по описанию решает, кого позвать и с какой задачей. Задачу «скажи привет и скажи пока» она разбирает на два вызова — каждому агенту своя задача, порядок тоже задаёт она:

bash
php app/Ai/Supervisor/Supervisor.php
# hello
# bye

Границы названы, чтобы их не искать в коде:

Проверить слой можно без модели:

14. CLI: справочник

Все команды запускаются из корня проекта: php maws.php <команда>.

Если запись на диск не удалась, команда не оставляет половину: строку в базе снимает, созданные каталоги убирает и печатает причину. Это make direction, make place, make tool и make agent — у них создание состоит из нескольких шагов, и «Готово» означает, что готово всё.

Команды, которые правят конфиг, собирают файл заново: make direction дописывает сцену в config.json, make tool — инструмент в settings.json места. Ваши комментарии в этих двух файлах при таком переписывании теряются, остаётся только шапка, которую команда ставит сама. В dbase.json и dbaccess.json комментарии живут, пока вы их не удалите: эти файлы команды не переписывают.

make direction

Спрашивает название направления и язык сцены («Укажите язык направления (например "ru" или "en")»). Создаёт строку в directions, app/World/{Напр}/Places/, файл {Напр}Workspaces.php, сцену Screen/Scenes/{Напр}/{Язык}/ и дописывает её в Screen/config.json.

Язык спрашивают, а не берут из константы: у направления может быть несколько сцен — по одной на язык, и вторая не должна требовать правки app/config.php.

Строка идёт первой, файлы — вторыми. Это точка отката: если каталог или сцена не создались, строка снимается, и направление не остаётся полуготовым. Обратный порядок оставил бы файлы, из-за которых повторный запуск сказал бы «уже существует», а строки бы так и не было.

Строка — то, что делает направление видимым: make place читает список направлений из базы. Поэтому команда, застав каталог без строки (направление когда-то завели файлами), заводит строку и говорит об этом; файлы и сцену она не трогает. Если на месте и каталог, и строка — отказ: второй строки не будет. Обратный перекос — строка есть, а каталога нет (его удалили руками) — тоже отказ: имя в directions не уникально, и вторая строка задвоила бы направление в меню.

Таблицу directions создаёт миграция, так что до make migrate команда откажет — заводить строку некуда.

make place

Спрашивает направление и название места. Создаёт:

{Напр}/Places/{Место}/Workspace.php
{Напр}/Places/{Место}/settings.json
{Напр}/Places/{Место}/Tools/

Вставляет строку в places. Если {Напр}Workspaces.php нет — создаст.

Раздел не спрашивается: место от раздела не зависит, оно принадлежит направлению. В дерево сайта место ставит make area — раздел наследует место и приносит свой url.

Место заведено, а каталога нет. Каталог могли удалить руками: строка в places осталась, страница не открывается, а завести место заново нельзя — имя занято строкой. Команда замечает строку и восстанавливает файлы в неё: Workspace.php и settings.json пишутся, только если их нет, а раздел не перепривязывается — у места он уже свой. Строка остаётся та же, дубля в меню не появляется.

Обратный перекос — каталог без строки — по-прежнему отказ: место не найдётся, пока в places нет строки.

make area

Спрашивает родительский раздел (или «верхний уровень»), url раздела, место, в которое раздел ведёт, и название раздела. Создаёт строку в areas: parent_id, url, place_id.

Место выбирается из готовых: раздел наследует место, а не заводит его. Файлов команда не трогает — у раздела своих файлов нет: каталог и Workspace.php принадлежат месту, их заводит make place. Мест нет вовсе — отказ, «Не найдено ни одного места в мире».

url раздела — то, что попадёт в адрес; он всегда строчный. Раздел с url, совпадающим у одного родителя, команда создать не даст.

make tool

Спрашивает направление, место, название инструмента, язык шаблона и «Будет ли использоваться база данных?». Если да — схему и таблицы (по одной, exit — закончить). Создаёт Tools/{Инстр}/ со всеми файлами и дописывает инструмент в settings.json места.

make agent

Спрашивает тип (single, multi, supervisor), затем имя — кроме single: у него каталог один. Создаёт Agent.php (или {Имя}.php), tools.json, instruction.prompt.php. Для supervisor дополнительно создаёт Ai/Supervisor/Supervisor.php.

make migration

bash
php maws.php make migration add_orders

Название — строчной латиницей, цифрами и подчёркиванием. Создаёт db/migrations/0001_add_orders.php (номер — следующий свободный) и строку журнала под неё. Миграция при этом не применяется: файл можно править сколько угодно, база меняется только в migrate.

Внутри файла — анонимный класс с up() и down(), только SQL:

php
use Maws\System\Migrations\Migration;

return new class () extends Migration {
    public function up(): array
    {
        return ['CREATE TABLE orders (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY)'];
    }

    public function down(): array
    {
        return ['DROP TABLE orders'];
    }
};

down() пишет автор, из снимка он не выводится. Пустой down() — отказ: миграцию нельзя будет откатить.

make migrate

Применяет все ожидающие миграции по порядку. Перед каждой снимается структура базы, после — снова; снимок ложится в журнал (scheme_before / scheme_after). Если SQL миграции не выполнился — MigrationBroken с номером оператора, и транзакция откатывает всё выполненное: изменения не фиксируются.

С именем применяется очередь до него включительно:

bash
php maws.php make migrate 0003_add_orders

Это парная команда к rollback <имя>. Перескочить предшественников нельзя: они меняют ту же схему, и снимок «до» у следующей миграции снят уже с их результата. Названная миграция уже применена — «применять нечего», без ошибки; такого имени нет в db/migrations — отказ.

Отдельный отказ — журнал не в порядке: в очереди есть миграция старше уже применённой (файл добавили задним числом). Её снимок «до» был бы снят с уже изменённой схемы, поэтому команда не применяет её молча в конец, а называет оба имени.

make rollback

bash
php maws.php make rollback 0001_add_orders

Имя называется явно: откатывать «последнюю» молча — значит менять базу догадкой. Команда выполняет down() и сверяет получившуюся структуру со снимком scheme_before — расхождение означает, что down() не возвращает базу туда, откуда up() её увёл. Если созданные миграцией таблицы уже чем-то наполнены, команда спросит до того, как они исчезнут: данные знает только down().

make build

Собирает каркас с нуля: применяет миграции, создаёт направление Public, два места — Home и SecondPlace — и три инструмента: ExampleTool и ExampleTool_1 у Home, ExampleTool у SecondPlace. Имена зашиты в константах, и записаны они так, как их вернул бы make tool: имя инструмента — имя класса, поэтому с заглавной буквы.

Страница после сборки уже работает: ExampleTool места Home читает test_table — её наполняет миграция — и печатает строки списком. С него и стоит начинать чтение: getTestData() берёт записи через Repository, showHTML() отдаёт их шаблону, serve() сводит одно с другим. Разметка здесь — один из выходов инструмента, а не обязанность: getTestData() о шаблоне ничего не знает.

ExampleTool_1 — обычная заготовка: ни таблиц, ни разметки строк, только свой шаблон. Странице он не нужен; он здесь, чтобы settings.json места показывал list из двух имён, а не из одного.

SecondPlace существует ради needs: у него свой инструмент, и Home объявляет нужду в нём. Без второго места нужду не на чем показать — в settings.json остался бы list без единого примера чужого инструмента, а needs пришлось бы выдумывать в документации. Раздела у SecondPlace нет: раздел задаёт адрес страницы, а нужда — разрешение на инструмент, в меню она не ведёт (§7).

Сборка не дополняет существующее: сначала проверяются все шаги, и если хоть что-то уже создано — она перечисляет найденное и выходит, ничего не тронув. Иначе «сборка» на живом проекте тихо перезаписала бы чужую сцену или настройки места.

make test:<файл>

bash
php maws.php make test:app/World/Public/Places/Home/Tools/ExampleTool/ExampleTool.php

Путь — от корня проекта. Тест ложится зеркально в app/Tests/** и запускается сразу. Нужна живая PostgreSQL. Код возврата: 0 — всё прошло, 1 — провал или «ничего не проверено».

У воркспейса случаев нет: startWork() отдаёт страницу целиком, и сверять её байт в байт значило бы заморозить шаблон в проверке. Такой файл объявляет получателя и назначение для читателя, а страницу смотрит живая проба — запрос к месту.

test

bash
php maws.php test

Прогоняет все контракты core/** — файлы, объявившие #[Subject] с начала строки. Каждый контракт идёт своим процессом, поэтому падение одного не мешает остальным. Шаблоны пропускаются: в них объявление написано для будущего класса, а не для существующего.

[ok]   core/Man/Head/Head.php — 10 проверок, 10 прошло, 0 провалено
[--]   core/Foo/Bar.php — объявлен, проверок нет
[!!]   core/Baz/Qux.php — 3 проверок, 2 прошло, 1 провалено

[ok] — всё прошло, [--] — контракт объявлен, но случаев нет (не провал, но и не успех), [!!] — провал, причины печатаются после списка. Код возврата 1, если есть хоть один [!!]. Нужна живая PostgreSQL.

bash

Первая команда на новой машине и первая после переезда на хостинг. Отвечает «что именно не работает»: версия PHP, расширения, константы app/config.php, права на logs/, db/migrations и временный каталог, доступность базы.

[ok]   PHP 8.1.33 — нужен 8.1 или новее
[!!]   расширение pdo_pgsql — без него нет соединения с базой
[ok]   расширение mbstring
[ok]   расширение json
[??]   расширение gd — хелперы Image и Upload не заработают

Порог версии PHP берётся из composer.json, а не из константы в коде: одно число в двух местах расходится. Права проверяются записью файла, а не is_writable(): бит «на запись» ничего не говорит о разделе, смонтированном только для чтения.

php
define('DOCTOR_CHECKS', [

]);

Объявленная проверка, которая не вызывается (опечатка в имени класса), — провал, а не пропуск: иначе она создаёт видимость, что этот случай кто-то стережёт.

15. Тесты контрактов

Методы ядра и инструментов описаны атрибутами. Тот же механизм доступен вам: объявили — прогоните.

Минимальный пример:

php
namespace App\World\Public\Places\Home\Tools\ExampleTool;

use Maws\System\Contract\{Fails, Gives, Purpose, Subject};

#[Subject(ExampleTool::class, 'Scaffold::tool', ['Public/Home', 'ExampleTool'])]
#[Purpose('Инструмент места: отдаёт список строк.')]
class ExampleTool extends Tool
{
    #[Purpose('Отдаёт разметку со списком.')]
    #[Gives([], '<ul>…</ul>')]
    public function serve(): string
    {
        // ...
    }
}

Прогон:

bash
php maws.php make test:app/World/Public/Places/Home/Tools/ExampleTool/ExampleTool.php

Что нужно знать:

  • #[Subject] обязателен, иначе тест не создастся.
  • #[Gives([аргументы], ожидаемое)] — успешный вызов, #[Fails([аргументы], Исключение::class)] — отказной, #[Changes([аргументы], проверки)] — мутирующий, #[Responds([аргументы], 'тело', код)] — «место ответило само» (см. ниже).
  • Для классов из app/** генератор подключает файл источника сам. Если файл лежит под app/World/{Напр}/, первым делом загружается база направления ({Напр}Workspaces.php) — require_once родителя в вашем файле не нужен.
  • Файлы песочницы (например, dbase.json) объявляются #[Fixture(files: ['dbase.json' => '…'])].
  • Смена песочницы на методе действует и на следующие методы — объявляйте её там, где она нужна.
  • Атрибут без use и атрибут с опечаткой в имени — это класс, которого нет: случай не попадёт в тест. Генератор ловит и то и другое сам и отказывает до записи теста («Атрибут Fail (строка 19) не разрешился… Похоже на Fails»), а строку «Проверок в контракте:» с числом рядом печатает для человека — по ней видно, что тест неожиданно похудел.
  • Прогон идёт в UTC (Runner::ZONE), даже если сервер живёт в другом поясе: ожидание для Date считайте по UTC, иначе на сервере в +3 оно разойдётся на три часа.

Место, которое отвечает само

У такого метода нет ни #[Gives], ни #[Changes]: он не возвращает значение, а печатает ответ (§10.2). Объявление выглядит так:

php
#[Throws(ResponseSent::class, 'ответ уходит из места, сцена не нужна')]
#[Responds([], '<h1>Ответ места</h1>')]
public function startWork()

#[Responds] — единственное, из чего генератор строит проверку: maws make test: создаст случай, который вызовет метод, дождётся ResponseSent, сверит напечатанное с телом байт в байт и проверит код ответа. Третий аргумент — код, по умолчанию 200:

php
#[Responds([], '<h1>Нет такой</h1>', 404)]   // метод должен ответить 404

#[Throws] — описание контракта для читателя, теста он не даёт. #[Fails([], ResponseSent::class)] для того же вызова ставить не надо: он проверяет лишь сам факт отказа, то есть слабее Responds.

#[Changes] у такого места снимается: случай зовёт метод и смотрит состояние после возврата, а возврата нет — тест упадёт с ResponseSent. Если состояние меняется до ответа, проверять его придётся отдельным случаем на другом методе.

Тело проверяется только так — отдельного «ручного» случая больше не нужно, всё выражается атрибутом и переживает перегенерацию теста.

Чего #[Responds] не проверяет: заголовки. В CLI их нет вовсе (headers_list() пуст), поэтому Content-Type остаётся на совести кода. Код ответа при этом проверяется — http_response_code() в CLI работает.
