# FORLLM.md — входной документ проекта MAWS

**Beta.** Фреймворк в разработке, версии 1.0 нет. Контракты, имена классов и раскладка каталогов
могут меняться без обратной совместимости: документ описывает **сегодняшнее состояние кода**, а не
обещание стабильности. Для продакшена — только после собственной проверки.

> Читать первым при работе с этим кодом. Здесь то, чего нет в самом коде: замысел, границы слоёв,
> конвенции, ловушки. Контракт каждого метода описан **атрибутами рядом с ним** (см. §12), а не здесь.

---

## 1. Замысел

PHP-каркас (пакет `maws/maws`), в котором структура приложения выражена **физической метафорой**, и
метафора — не украшение, а **механизм принуждения к дисциплине**.

Главное правило: **нельзя получить данные модуля, «просто вызвав» его.** Нужно физически «дойти» до
места, «войти» в него и «взять» инструмент — и на каждом шаге действуют проверки. Архитектурные
правила обеспечиваются **исполнением (runtime)**, а не соглашениями и не внешними линтерами. Прямого
`new` чужого класса в модели нет: ссылку на инструмент выдаёт только человек.

Это, по сути, **object-capability модель** («нет полномочий без ссылки») в антропоморфной одежде плюс
двусторонний декларативный контракт зависимостей.

Три опоры для стандартной разработки серверной логики и слой AI для фоновых процессов
агентской работы:

| Часть | Смысл |
|---|---|
| **Man** | опора: субъект исполнения запроса; тело с органами |
| **World** | опора: карта мест; реестр того, что существует |
| **Screen** | опора: слой вывода |
| **Ai** | слой: фоновые процессы агентской работы; ни тела, ни места — самостоятельный процесс |

**Раскладка сущности (правило):** главный класс — в корне (`<Сущность>/<Сущность>.php`), всё
прочее — под `System/` (`System/Exception/`, `System/Pass/`). Namespace повторяет путь
(`Maws\World\System\Exception`). То же правило распространено на места и инструменты: в
`Places/{Место}/` главный класс — `Workspace.php`, в `Tools/{Инстр}/` главный класс и `dbase.json` —
в корне, а `Repository.php`, `Page.php`, `Templates/` — под `System/`.

**Хелперы — исключение из правила:** `core/System/Helpers/<Имя>/` держит `<Имя>.php` и `Exception/`
**рядом**, без вложенного `System/`.

**Хелперы — самый большой раздел ядра, и он свой.** `core/System/Helpers/**` — 19 модулей. Это
штатные инструменты для приложений на ядре: ввод (`Input`), строки (`Text`), числа (`Num`),
деньги (`Money`), даты (`Date`), файлы (`File`, `Path`), разметка (`Html`), сеть (`Http`), данные
(`Json`, `Csv`), браузер (`Cookie`), токен форм (`Csrf`), секреты (`Token`, `Hash`), картинки (`Image`),
загрузка файлов (`Upload`), страницы выборки (`Pager`).
Классов больше, чем модулей: **24 против 19** — рядом с главным классом живут `DateSettings`,
`MoneySettings`, `PendingRequest` (`Http`), `Page` (`Pager`) и `Http/Response`. Каждый объявлен
`#[Subject]` и проверяется своим прогоном, поэтому «24 класса» и «19 модулей» — про разное.
Они лежат в своём
пространстве имён (`Maws\System\Helpers\*`), тянут только объявленные в `composer.json` зависимости
и живут по циклу выпуска самого проекта: правка здесь — обычная правка кода.

**Ядро на хелперы не опирается — ни один.** Любой каталог `core/System/Helpers/<Имя>/` удаляется
целиком (с классом и его `Exception/`), и ядро продолжает работать: ни `Screen`, ни `Head`, ни
`World`, ни `Session` не импортируют `Maws\System\Helpers\*`. Обратная зависимость разрешена и
нормальна: хелпер вправе звать ядро.

**Что ядру нужно, у ядра своё — отдельным кодом.** Общего кода с хелпером нет и быть не должно:
`Path::normalize` живёт в `core/System/Path.php` своей копией, правило имени печенья — в
`SessionSettings`. Повтор здесь дешевле связи: общий класс связал бы ядро с хелпером навсегда, и
удалить хелпер стало бы нельзя. DRY на этой границе не действует — это разные сроки жизни, а не
дублирование.

Границу стережёт прогон, а не обещание: `Layers::helperCalls()` (`core/System/Test/Layers.php`)
обходит `core/**` и перечисляет строки с `Maws\System\Helpers`; пустой список — граница держится.
Хелпер — дополнительное удобство для того, кто пишет приложение, а не часть механизма.

API хелпера выводится из **назначения**, а не из данных: у чужого разработчика свои таблицы и свои
типы, поэтому ни форма входа, ни пороги под текущую базу не подгоняются. Политику (слова и пороги)
задаёт разработчик конфигом, и умолчаний нет: отсутствующий ключ — отказ, а не тихая подстановка.
Часовой пояс в политику не входит: его задаёт сервер.

Каждый класс хелпера объявлен `#[Subject]` и проверяется `make test:`; вне контракта только классы
исключений — их проверяют `Fails` тех методов, что их бросают.

## 4. Поток запроса

`public/index.php` — composition root. Порядок:

1. `require app/config.php`, `require vendor/autoload.php`; заголовки безопасности (см. ниже
   «Заголовки безопасности»); `new Screen()` — экран создаётся во входе
   и **передаётся внутрь** (`Man → Body → Hands`).
2. `$url = $_GET['way'] ?? ''` — пустой адрес и есть главная страница: у неё `url` в `areas` пуст.
3. Базы направлений (`{Напр}Workspaces.php`) вход **не грузит**: их подключает `World`, когда находит
   место, — только нужное направление и уже внутри `try` (см. §15, пункт 8).
4. `try`:
   - `Session::open()` — сессия поднимается **до первого вывода**: позже браузер печенье уже
     не примет (см. ниже);
   - `new World()` — карта больше не файл: направления и места приходят из базы;
   - `new Man($world, $screen)` — `Body` собирает органы;
   - `head->getWorkspace($way)` — адрес → раздел → `Place`; ставит `currentPlace` и `currentArea`;
   - `legs->walk(head->currentPlace->way())` — ноги подошли, голова запомнила (`noticeNear`);
   - `$data = $man->body->head->initWorkspace()` — подключает `Workspace.php` места и зовёт `startWork()`;
   - `hands->useScreenInterface(head->currentPlace->way(), 'showPage', $data)` — вывод (завершает процесс).
5. Четыре `catch` — по одному на каждый род сбоя (см. §5) плюс конец ответа:
   `ResponseSent` → пустая ветка (место уже ответило); `MawsException` → статус из исключения;
   `MawsMisuse` → 500 + `Log::write($e, LOGS_FILE)`; `Throwable` → 500 + то же.

**Почему две ветки внутри каждого `catch`.** Человека может не быть: сбой при подключении
воркспейсов летит ещё до `new Man()`, `OrganAssembly` — при сборке органов, и тогда `$man` не присвоен. Рук, держащих пульт,
ещё нет — сбой показывает сам `$screen` (его создал вход). Операция одна, различается путь до неё.

**`Head::getWorkspace()` вызывается во входе отдельным шагом**, а не в конструкторе: так `PlaceNotFound`
(самый частый сбой, вызванный пользователем) случается, когда человек уже собран, и идёт обычным путём
через руки.

**Адрес канонизируется редиректом — за один переход.** Правило короткое: первый сегмент,
совпавший с главной, из адреса снимается, всё остальное остаётся как было. `?way=home` уводится на `/`,
`?way=home/<раздел>` — на `?way=<раздел>`, `?way=home/<раздел>/<страница>` — на
`?way=<раздел>/<страница>`. Если первый сегмент не главная — редиректа нет, адрес показывается как
есть (`?way=<раздел>`, `?way=<раздел>/<страница>`). Тем же ответом приводятся к строчным сегменты:
`?way=Home` → `/`, но двумя переходами это не делается — регистр и снятая главная уходят вместе
(замер: `?way=Home` и `?way=HOME` — один `301` сразу на `/`). Снимаются **все** ведущие сегменты
главной, поэтому и повтор идёт одним переходом (замер: `?way=home/home` — один `301` на `/`).
Цикл, а не одно снятие: адрес с повтором — тот же мусор, что и с одним сегментом, и уводить его
вторым переходом значило бы обещать один редирект, а делать два.
Дальше адрес решает дерево: спуск идёт от корня, поэтому адрес, начатый не с раздела верхнего
уровня, не находится — 404, хотя раздел с таким адресом в базе может и быть.

**Воркспейс получает ЧЕЛОВЕКА, а не голову — это требование метафоры.** Все три действия идут через
`$this->man`: ноги (`body->legs->walk`), сам человек (`enterPlace`), руки (`body->hands->takeTools`).
Передашь голову — воркспейс дотянется до ног и рук только транзитом (`$head->body->...`), а `enterPlace`
окажется не на месте, и от принуждения к полноте тела останется один орган-фасад.

**Шапка страницы идёт своим каналом: голова → руки → пульт → сцена.** Все колонки раздела
(`title`, `description`, `keywords`, `og_*` и любые будущие) принадлежат РАЗДЕЛУ, а сцена выбирается
по НАПРАВЛЕНИЮ, поэтому воркспейс их не возвращает: `$data` — разметка места, и `Returns('string')`
у всех воркспейсов не меняется. Руки в `useScreenInterface` для команды `showPage` берут
`head->pageMeta()` (это `Area::fields()`) и передают экрану; `Screen::sceneUp` кладёт их в шаблон
сцены переменной `$meta` — плоским списком «имя колонки → значение». Плоский нарочно: ядро не делит
колонки на группы и не знает их имён, поэтому новая колонка в `areas` появляется в `$meta` сама —
её печатает шаблон. Экран ничего не вычисляет и пустые значения не отбрасывает — печатать пустой тег
или пропустить, решает шаблон сцены.

**Тем же каналом идёт политика кэша** (§8.1): `head->cachePolicy()` → руки → экран → `Cache::send`.
Причина та же: кэш объявляет МЕСТО в `settings.json`, а не воркспейс, поэтому в `$data` политики нет
и `Returns` воркспейсов не меняется.

**Классическая последовательность внутри `startWork()`:**

```php
$way = $this->place->way();

$this->man->body->legs->walk($way);                        // 1. дойти
$pass  = $this->man->enterPlace($way);                     // 2. войти (вернёт пропуск)
$tools = $this->man->body->hands->takeTools($pass);        // 3. взять инструменты

return $tools->ExampleTool->serve();                       // 4. отдать данные
```

### Сессия и токен формы

`Session` — дверь, как `DbConnector`: одна на процесс, `open()` во входе, `instance()` дальше, `close()`
в конце. Открытие стоит первой строкой `try`, потому что `session_start()` обязан пройти **до первого
байта ответа**: иначе `Set-Cookie` уехать не может, и каждый запрос приходит с новой сессией. Дверь эту
ошибку не прячет, а называет — `headers_sent()` → `SessionMisuse` с файлом и строкой. Автостарта
нет: `instance()` до `open()` — тоже отказ.

Политика лежит в `core/System/Session/config.json`, рядом с классом: `open()` вызывается без аргументов
и читает его. В политике — только то, что действительно решает сайт: `name`, `lifetime`, `secure`,
`sameSite`. Остальное — не выбор, а условие работоспособности, поэтому зашито в двери: путь печенья
всегда `/` (сессия на подпути рвётся на любой ссылке мимо него), домен — текущий хост (расширение на
`.example.com` отдало бы сессию поддоменам), `HttpOnly` — всегда (идентификатор сессии JavaScript не
нужен никогда), каталог файлов — из `php.ini`, как часовой пояс. Набор обязателен целиком, лишний или
недостающий ключ — отказ (`SessionSettings`), то есть `"path": "/"` в файле — лишний ключ.
Имя печенья проверяет сам `SessionSettings` — по своему правилу RFC 6265, без хелпера `Cookie`: хелпер
обязан удаляться, не роняя ядро. `SameSite=None` требует `"secure": true` и отвергается ещё до старта:
при `null` схема может оказаться http, и браузер выбросит печенье. **`"secure": null` значит «по схеме запроса»** (`https` или порт
443) — файл политики один на все окружения, и решать за разработчика, по http он или https, он не может;
`true`/`false` — жёсткое решение, оно перебивает схему. С `null` всё, что Secure требует по условиям
браузера, отвергается: `SameSite=None` и имя с префиксом `__Host-`/`__Secure-`. Заголовку
`X-Forwarded-Proto` дверь не верит — за прокси, который обрывает TLS, сайт ставит `true` сам.
`lifetime > 0` поднимает `session.gc_maxlifetime`: иначе файл сессии умрёт по умолчанию php.ini
(24 минуты), а печенье останется. `use_strict_mode` и `use_only_cookies` дверь включает сама — это
не политика, а условие работоспособности. Идентификатор пересоздаёт не открытие, а вход — `grant()`,
и это единственное место, где он пересоздаётся. Путь к файлу можно передать (`open($file)`) — для прогона и пробника, которым нужно
заменить политику песочницей; в сайте так не делают. Каталог файлов сессии, если пробнику нужен свой,
ставится до `open()` обычным `ini_set('session.save_path', ...)` — так же, как это делает `php.ini`.

Хранилище — «ключ → значение»: `get/set/has/forget/pull`. Два ключа при этом зарезервированы:
`.auth` — слот вошедшего, и `.csrf` — ключ, под которым токен формы лежит **в сессии**. Имя поля
формы — другое: `_csrf`, его даёт `Csrf::field()`. Первый закрыт для записи: `set()`,
`forget()` и `pull()` на нём отказывают `SessionMisuse`, потому что слот ставит только `grant()`, а
гасит только `revoke()` — иначе вход обошёл бы смену идентификатора. Второй открыт: токеном владеет
хелпер `Csrf`, ядру нужно лишь имя, чтобы вход мог его погасить.

**Вход — одна дверь.** `grant($subject, array $claims = [])` делает два шага, которые порознь забывают
делать вместе: меняет идентификатор сессии (`session_regenerate_id(true)` — старый файл удаляется
сразу) и кладёт субъект в `.auth`. Порознь получается фиксация сессии: идентификатор, навязанный до
входа, остаётся идентификатором вошедшего. Заодно гасится токен формы — он был известен до входа
(например, тому, кто навязал идентификатор), и после входа форма с ним прошла бы проверку. `claims` —
массив без структуры: роли, имя, что угодно. Ядро его хранит и не толкует, поэтому слова «роль» в ядре
нет. Кого пускать и что считать правами — дело сайта: в `grant()` приходит уже проверенный субъект.
`subject()` отдаёт идентификатор или `null`, `claims()` — массив или пустой массив; по ним и решается,
гость перед нами или нет. `revoke()` — зеркало: гасит слот и токен и снова меняет идентификатор. Это
не `close()`: тот уничтожает сессию целиком, а корзина гостя должна пережить выход. Оба зовутся до
первого вывода — как и открытие, потому что меняют печенье; после вывода — `SessionMisuse`.

```php
// вход: проверка — замыкание сайта, хранилище — тоже сайта
$found = $check($login, $password);            // ['id' => 42, 'claims' => ['roles' => ['admin']]] | null
if ($found === null) {
    return $tools->Login->serve('Неверный логин или пароль');   // один текст на оба случая
}

Session::grant($found['id'], $found['claims']); // идентификатор сменился, слот поставлен, токен погашен

// выход
Session::revoke();                              // гость; корзина и прочие данные на месте
```

`close()` заканчивает сессию посетителя: стирает данные, уничтожает файл, стирает печенье теми же
путём и доменом, с какими его ставили, и забывает дверь — дальше `instance()` откажет. Зовётся там,
где заканчивается вход, и **до первого вывода**, как и открытие: печенье стирается заголовком. Гостю,
у которого сессии нет, `close()` не мешает — выход есть и у него.

Токен форм живёт в хелпере `Csrf`, а не в сессии: имя ключа (`Session::TOKEN`, значение `.csrf`) задаёт
ядро — вход обязан погасить токен, — а сам токен, его длина и сверка остаются хелперу. `token()`
заводит токен при первом обращении и держит до конца сессии — две открытые вкладки не мешают друг
другу. `check($given, $stored)` — чистое сравнение через `hash_equals`, и пустой токен не совпадает
с пустым; поэтому оно проверяется прогоном, а `token()`/`rotate()` — нет: им нужна живая сессия.

**Проверку выбирает разработчик.** Принудительного режима нет: ядро не отказывает POST-у без токена и
не смотрит, есть ли в форме поле. Правило двустороннее и держится на одной строке в воркспейсе —
положил поле, проверь его; не положил, значит и проверять нечего. Так и должно быть: страница в
публичном кэше не может нести токен (он был бы общим для всех посетителей), у посетителя с
заблокированными печеньями сессия новая на каждый запрос, а фоновая отправка трекера — POST с телом
JSON и без полей формы вовсе.

```php
// разметка формы: имя поля берётся у хелпера, а не набирается руками
<input type="hidden" name="<?= Csrf::field() ?>" value="<?= Csrf::token() ?>">

// место, до любой записи в базу
if (!Csrf::verify($_POST)) {
    return $tools->Form->serve('Страница была открыта давно — проверьте данные и отправьте ещё раз');
}
```

`field()` и `verify()` — пара: первое даёт имя поля шаблону, второе берёт токен из присланных полей и
сравнивает с сессионным. Разойтись в написании им нечем, а `verify()` не заводит токен: сессия без
токена даёт отказ, а не новый токен. `check($given, $stored)` остаётся для случаев, когда токен пришёл
не полем формы.

**Просроченная форма — ветка, а не сбой.** 403 был бы неверен дважды: посетитель ничего не нарушил,
и показать ему нечего — `Error/{Язык}/index.tpl.php` это страница «500, на сервере что-то сломалось».

### Проверка поведения формы: `Crabic`

> **Крабик (Crabic)** — это антибот-защита ваших форм. Крабик ловит и ест мелкую рыбёшку (простых
> спам-ботов). Если же к вам пожалует большой серьёзный хищник (целенаправленно написанный бот под
> систему MAWS), то Крабик с ним не справится и убежит. Потому что он просто крабик.

Строится на том, что человек не повторяет одно и то же движение дважды, а скрипт, отправивший запись
второй раз, повторяет её целиком.

**Протокол.** Скрипт `public/js/crabic.js` находит форму с атрибутом `data-crabic` и раз в три
секунды отправляет на тот же адрес пачку действий: точки указателя (время, x, y), число событий
указателя и нажатий клавиш. Событие — это движение, клик, колесо и касание: клик и тап тоже дают
точку, иначе отправка с телефона не оставила бы следа вовсе. Тело — JSON, поэтому пачка не
смешивается с отправкой формы. Сервер держит три последние пачки в сессии под ключом
`[useractions]`, отдельной дорожкой на каждую загрузку страницы: две вкладки с формой не мешают
друг другу. На отправке скрипт кладёт сводку текущей пачки в скрытое поле `crabic` — то же поле
служит ловушкой. Там, где стоит тег скрипта, он оставляет картинку `/images/maws/crabic.png`:
метка есть только на странице, где JavaScript действительно выполнился, и её место в разметке
видно глазами. Показ выключается атрибутом `data-img="false"` на самом теге: `"true"` и отсутствие
атрибута картинку включают, `"false"` — нет.

**Приговор.** Одна дверь — `Crabic::chew(['name', 'note'])`. Первый аргумент — имена полей формы: по
ним Крабик узнаёт отправку (пусто — отправкой считается любой POST без тела JSON). Возврат — только
решение: `true` — разжевал, это бот; `false` — жевать нечего: отправки не было или она похожа на
человеческую. Пачку трекера Крабик принимает сам и отвечает на неё `204`, так что до кода после вызова
такой запрос не доходит.

Причину отказа он наружу не отдаёт — она ложится в журнал `public.chews` (`0004`: `reason`,
`chewed_at`, живёт `ttl` и чистится сама). Читает журнал тот, кто ведёт сайт: по нему видно, отсекается
бот или живой человек.

| Причина | Что значит |
|---|---|
| `empty` | поля нет, оно пустое или в сводке ни одного действия — страницы не касались |
| `format` | сводка не разбирается или не того вида |
| `order` | в сессии нет отметки отрисовки — сводка не с этой страницы |
| `young` | страница моложе `min` секунд (по умолчанию одной) по часам сервера |
| `time` | заявлено больше времени, чем прошло с открытия страницы |
| `motion` | траектория нарисована по линейке |
| `repeat` | такой отпечаток уже приходил |

**Время — единственное, что нельзя подделать.** `at` каждой пачки ставит сервер, а время отрисовки
страницы он записал сам, в `[crabicstart]`. Честный клиент меряет от запуска скрипта, сервер — от
отрисовки, поэтому сумма заявленных длительностей всех звеньев и сводки не может быть больше, чем
`at - started`. Это тождество, а не порог: при любом кольце, включая пустое, оно выполняется само, а
лжёт только тот, кто приписал себе небывшее время. Запас `SLACK` (1.25) — на запасные часы браузера:
без `performance.now()` скрипт падает на `Date.now()`, а те могут прыгнуть.

**Число звеньев ничего не значит.** Кольцо — это данные, а не счётчик: одно звено, три и ни одного
судятся одинаково. Человек, открывший страницу с формой из одной кнопки, вправе отправить её сразу,
как дошёл до неё, — у него не будет ни одной пачки, и это не отказ. Поэтому в приговоре нет ни номера
пачки, ни счёта звеньев: они измеряли количество, а не поведение. Пропавшая по дороге пачка тоже
ничего не ломает — сумма считается по тому, что дошло.

**Секунда на страницу — цена, а не проверка.** Порог возраста всё-таки есть, но он один и меряется
часами сервера: `at - started >= min × 1000`. Секунда — это увидеть страницу, довести указатель до
кнопки и нажать; быстрее человек не успевает. Браузер получает страницу позже, чем сервер её
отрисовал, поэтому у человека здесь запас, а бот платит секундой на каждую отправку и обязан держать
сессию. Дальше секунды порог не поднимается: пять секунд отсекали бы законную отправку, а бота они
всё равно не остановят — он умеет ждать.

**Геометрия судится по каждому звену, какое есть.** Кривизна пути — длина пройденного к длине по
прямой, в промилле; ровно тысяча значит, что путь нарисован по линейке, чего рука не делает. Порог
в десять точек — не счётчик, а условие осмысленности: на двух точках любая линия прямая, и приговор
был бы ложным. Ни одного действия (ни точки, ни клавиши) — это `empty`: форму нельзя отправить, не
кликнув, не коснувшись и не нажав клавишу, значит клиента на странице не было.

Больше из геометрии не выжать. Бот не в браузере — он пишет JSON, и любое поле в нём выдумано.
Проверить, что клик попал в кнопку, сервер не может: разметки он не знает, а прямоугольник,
присланный клиентом, бот пришлёт свой. Поэтому геометрия поднимает цену подделки — надо нарисовать
путь, кончающийся кликом, — но не делает её невозможной. Неподделываемы только время прихода и
повтор.

**Повтор — единственное, что нельзя сгенерировать.** Отпечаток — хеш последовательности клеток сетки
(20 px, 100 мс); грубая сетка (40 px, 200 мс) ловит тот же путь с дрожанием. Склад —
`public.fingerprints` (`0003`), строка на последовательность: `hits > 1` значит повтор. Записывается
только то, где движения хватило хотя бы на четыре клетки: у двух людей, сдвинувших мышь на пиксель,
отпечаток совпал бы.

**Журнал — `public.chews` (`0004`).** Склад говорит «эта запись уже была», но не говорит, сколько
отправок отклонено и за что. Журнал говорит: `reason`, `chewed_at`, строка на каждый отказ, живёт `ttl`
и чистится при записи. Читает его тот, кто ведёт сайт, — по нему видно, отсекается бот или живой
человек, и по нему настраивается порог.

**Что делает сайт.** Отдаёт страницу с формой и `crabic.js` и зовёт `chew` на каждом запросе к этой
странице: пачку он принимает сам, отправку судит, отрисовку начинает заново. Объявлять права на склад
не нужно — Крабик ходит в базу своими правами ядра, а не правами места. Пороги — `min` (сколько секунд
страница обязана прожить) и `ttl` (сколько секунд живут отпечаток и запись журнала) — передаются
вторым аргументом. Границы у обоих молчаливые: `ttl` зажимается в отрезок от минуты до года, поэтому
`'ttl' => 0` даст 60 секунд, а не «не хранить», а `min` меньше нуля считается нулём. Зажим ничего о
себе не сообщает: это защита от опечатки в конфиге, а не проверка ввода.

**Почему ядро, а не хелпер.** Состояние живёт в `Session`, склад создан ядровой миграцией, половина
протокола — в `public/js`. Хелпер обязан удаляться целиком, не оставляя сирот, а ядро не может позвать
хелпер — значит проверку нельзя было бы встроить в руки. Контракт есть только у `Motion`: `Crabic`
работает с сессией и базой, а `#[Fixture]` умеет писать лишь файлы в песочницу, и зелёный контракт был
бы зелёным просто потому, что сессии нет.

### Заголовки безопасности

Ставятся во входе, до `try` и до первого вывода: они не зависят от страницы.

| Заголовок | Что закрывает |
|---|---|
| `X-Content-Type-Options: nosniff` | угадывание типа: загруженный «gif» с HTML внутри иначе выполнится как страница |
| `Referrer-Policy: strict-origin-when-cross-origin` | чужим сайтам уходит только домен: путь и параметры иногда и есть секрет |
| `X-Frame-Options: SAMEORIGIN` | вставку в чужой iframe — для старых браузеров |
| `Content-Security-Policy: frame-ancestors 'self'` | то же для остальных; политику скриптов сайт задаёт сам, вход её не навязывает |
| `Strict-Transport-Security: max-age=31536000` | первый же http-запрос после https — **только при https** |

Без `nosniff` браузер вправе решить, что файл с расширением `.gif` — на самом деле HTML, и показать
его как страницу: это и есть основа атаки «загрузи картинку».

`HSTS` — единственный из пяти, кто зависит от схемы запроса, и ставится только когда запрос пришёл по
https. По http он не просто бесполезен: браузер запомнил бы «только https» для домена, который https
ещё не умеет, и закрыл бы к нему доступ на год — без возможности отменить. Схему решает
`Session::overHttps()`, тот же, что выбирает `Secure` у печенья сессии: правило одно, иначе заголовок и
печенье разойдутся в том, что считать https. `includeSubDomains` не ставится: поддомен без TLS —
решение сайта, а не фреймворка, и отменить его браузер не даст. Редирект `http → https` и
канонический хост — тоже не фреймворк: это настройка сервера, и какой хост главный, знает только сайт.

### Журнал сбоев

`core/System/Log/Log.php` — файл **на сутки** и один короткий id на запрос: `Log::write($e, LOGS_FILE)`.
Из базового `logs/maws.log` выходит `logs/maws-2026-10-20.log`; каталога нет — журнал заводит его сам.
Имя решения не требует: ротация не нужна, вчерашний файл просто больше не открывается на запись.
Id (`8` hex-знаков, один на процесс) стоит в начале **каждой** строки trace: без него строки соседних
запросов перемешиваются, и по журналу не понять, где кончается один сбой. Разбиение на строки идёт по
`\r\n|\n|\r`, а не по `\R`: `\R` в PCRE считает переводом строки и байт `0x85`, а это второй байт
буквы «х» в UTF-8 — русский текст рвался бы посреди слова.

Пишут ветки `MawsMisuse` и `Throwable` — **безусловно**, `DEV` управляет только текстом на странице:
в бою посетитель видит «500», разработчик — запись с trace.
Поэтому ядро возвращает `bool`, а решение (та же форма с сообщением, сохранённые поля) остаётся за
местом. `Csrf::rotate()` зовут там, где меняются права: вход, выход, смена пароля.

## 5. Исключения: два рода сбоя и конец ответа

Две базы сбоя в `core/System/Exception/`, они **не пересекаются ни в одной точке**, плюс третье
семейство, которое сбоем не является:

| База | Род | Предок | Что несёт |
|---|---|---|---|
| `MawsException` | код правильный, условия плохие — **показать** | `\Exception` | `status()` (по умолчанию 500) — по нему экран выбирает страницу |
| `MawsMisuse` | код написан неправильно — **исправить** | `\LogicException` | ничего: сбой кода всегда 500 |
| `ResponseSent` | **не сбой**: ответ уже ушёл | `\RuntimeException` | ничего: тело напечатано или подавлено, заголовки выставлены |

`ResponseSent` намеренно не наследует ни одному роду: попади он в `catch (MawsException)`, поверх
готового ответа уехала бы страница 500. Ловят его первым — во входе (пустая ветка) и в контрактном
прогоне (красный с объяснением). Подробности — §8.

Контейнеры лежат рядом с сущностью, которая бросает. **Один класс — один файл.** Текущий состав:

| Контейнер | Файлов | Содержимое |
|---|---|---|
| `core/System/Exception/` | 5 | `MawsException`, `MawsMisuse`, `ResponseSent` + `LanguageMisuse` и своя копия `PathFailure` (ядру нельзя звать хелпер) |
| `core/Man/System/Exception/` | 5 | `ManMisuse` + `OrganAssembly`, `EnterWithoutWalk`, `EnterVisitedPlace`, `TakeWithoutEnter` |
| `core/World/System/Exception/` | 22 | `WorldException`, `WorldMisuse`, `ToolException` + 19 листьев (карта, место, контракты, `Dbase*`, `ToolMissing`, `WorkspaceNotDeclared`, `WorkspacesMissing`) |
| `core/Screen/System/Exception/` | 8 | `ScreenException`, `ScreenMisuse` + `ConfigUnreadable`, `ConfigBroken`, `SceneMissing`, `CommandNotDeclared`, `TemplateMissing`, `TransferBroken` |
| `core/Ai/System/Exception/` | 16 | `AiException`, `AiMisuse` + 14 листьев (контракт, схема, права, `AiDbase*`, `ToolNotImplemented`, `AgentDirMissing`) |

Правила:

- **Лист заводится тогда, когда обработчик обязан вести себя иначе**, а не когда отличается причина.
  Два повода под один маршрут — один класс, причина уходит строкой в аргумент.
- **Семейство — для ловли, лист — для маршрута.** Поймать все сбои мира можно `catch (WorldException)`,
  а страницу выбрать по `status()`.
- **Сбой объявления — сбой мира.** `settings.json` — объявление места о своих инструментах, поэтому
  его поломки (`ContractUnreadable`, `ContractBroken`) и отсутствие объявленного доступа
  (`AccessNotDeclared`) — `WorldException`, хотя бросаются из рук.
- **Загрузка — автозагрузкой по PSR-4.** Ни одного `require` в слое исключений.

## 6. Место, адрес и сцена — не путать

**Адрес из URL — не то же самое, что `way()`.** В URL (`?way=<раздел>/<страница>`) адрес строчный и может
быть глубоким; `way()` — всегда «Направление/Место» с больших букв и ровно две части. Разбирает URL
голова (`Head::getWorkspace`): спускается по дереву `areas`, берёт место последнего раздела и
запоминает его в `currentPlace`; дальше везде — `currentPlace`, `currentLocation`, ключи `needs`,
ключ сцены — живёт только `way()`.

Правила адреса: разделы — дерево `areas` (`parent_id`), место раздела — `places` (`direction_id`
даёт направление). Сегмент адреса — `areas.url` строчными. У главной `url` пуст, поэтому она
открывается по пустому адресу: `/` → `Public/Home`. Главная в адресе не пишется: `?way=home` → 301 на
`/`, `?way=home/<раздел>` → 301 на `?way=<раздел>`. Всё, что не главная, начинается с раздела верхнего
уровня: `?way=<раздел>/<страница>`; адрес, начатый не с него, не находится — 404, хотя раздел
с таким адресом в базе может и быть.

| таблица | колонки | что задаёт |
|---|---|---|
| `directions` | `id`, `name` | направления; сцена выбирается по направлению МЕСТА |
| `places` | `id`, `name`, `direction_id` | места; `direction_id` даёт направление, каталог и сцену |
| `areas` | `id`, `name`, `place_id`, `main`, `parent_id`, `title`, `url`, `description`, `keywords`, `og_*` | дерево разделов: адрес страницы, её место и метаданные |

**`Place` — объект-значение** (`core/World/System/Place.php`), приватный конструктор, единственный
вход `Place::fromRow($row, $root)` — строка `places` вместе с именем направления из `JOIN`; `$root` —
корень мира, к которому привязан каталог места. Что умеет: `fromRow(array $row, string $root)`, `id()`,
`direction()`, `name()`, `way()`, `dir()`, `workspaceClass()`, `toolClass(string $tool)`.

```php
$place = Place::fromRow(['id' => 1, 'name' => 'Home', 'direction' => 'Public'], $root);

$place->id();                  // 1
$place->direction();           // 'Public'
$place->name();                // 'Home'
$place->way();                 // 'Public/Home'
$place->dir();                 // '{корень мира}/Public/Places/Home'
$place->workspaceClass();      // 'App\World\Public\Places\Home\Workspace'
$place->toolClass('ExampleTool');   // 'App\World\Public\Places\Home\Tools\ExampleTool\ExampleTool'
```

`fromRow` берёт `id`, `name` и имя направления из колонки `direction`; колонки нет или она не того вида —
`PlaceNotFound`. `DirectionNotFound` бросают `find`/`place`, когда `direction_id` не находит строку
в `directions`: у самого `Place` направления уже есть.

> ### ⚠ Сцена выбирается по НАПРАВЛЕНИЮ, а не по месту
>
> **У места НЕТ своей сцены, и заводить её не нужно.** `Screen::getScene($screenType)` берёт часть
> адреса **до `/`**: `Public/Home` → `Public` → сцена `Default`.
>
> **`Default` — основной шаблон сайта.** В него встраиваются элементы мест; новому месту обычно
> достаётся именно он. Правило «одна сцена на направление» относится к **сцене** — макету страницы.
> Шаблон инструмента — другое: у инструмента свой (`Tools/ExampleTool/System/Templates/{Язык}/index.tpl.php`), и это
> норма, потому что инструмент отдаёт фрагмент через `View`, а не макет целиком.

Не путать: **`areas`** — дерево разделов сайта (адреса страниц) в базе; **`app/Screen/config.json`** —
маппинг «ключ → сцена». Это два разных вопроса: какой адрес открыт и каким макетом его печатать.
Первый отвечает база, второй — конфиг экрана.

## 7. Контракты: что место публикует и чем владеет

### 7.1 `settings.json` места — двусторонний контракт

```json5
// Что место публикует, в чём нуждается и как его страницу можно кэшировать.
{
  "tools": {
    "list": ["ExampleTool", "ExampleTool_1"],          // своё
    "needs": { "Public/SecondPlace": ["ExampleTool"] } // ключ — адрес места, значение — имена его инструментов
  }
  // , "cache": { "ttl": 60, "scope": "private" } // необязательно; нет ключа — страница не кэшируется
}
```

- `"list"` — что место **публикует** (Published Interface).
- `"needs"` — в каких чужих местах место **нуждается** и какие их инструменты берёт. Ключ — адрес
  «Направление/Место»; **нужда допустима только внутри своего направления**.
- `"cache"` — политика кэша ответа, см. §8.1. Разбирает её `Policy::fromDir()`, а не `Tools`: у кэша
  нет ни публикации, ни нужд, и общий разбор только связал бы две несвязанные вещи. `make tool`
  переписывает файл из массива, поэтому ключ `cache` переживает правку (теряются только комментарии).

Правило направления — не удобство, а **граница доверия**: направление разделяет мир на зоны с разными
правами, поэтому композиция между направлениями запрещена по замыслу, а не потому, что её пока не
бывает. Место одного направления не должно получить инструмент другого: это должно быть
**невозможно**, а не просто не встречаться, иначе граница держится договорённостью, а не кодом.
В каркасе направление одно — `Public`; проверка от их числа не зависит.

Читается единственным местом — `Tools::of($dir, $place)` (прогон 9/9): `list`, `needs`, `raw` и
`for` (что достанется просящему). Форма проверяется у **обеих** половин: нечитаемо →
`ContractUnreadable`, битый JSON5 или форма не та → `ContractBroken`, нужда вне направления — тоже
`ContractBroken`.

**Все конфиги — JSON5.** `settings.json`, `dbase.json`, `dbaccess.json`, `app/Screen/config.json`,
политика сессии читаются `\json5_decode` (`colinodell/json5`): комментарии `//` и `/* */`, запятая перед
закрывающей скобкой и одинарные кавычки — норма. Причина простая: это файлы, которые человек правит
руками, и пояснение рядом с ключом полезнее, чем ещё один документ.

Граница проведена по источнику данных, а не по вкусу: **всё, что пришло извне** (тело HTTP-ответа,
ответ модели, JSON в колонке базы, `Json::decode`), разбирается строгим `json_decode`. Там послабление
было бы дырой: `json_decode` перестал бы быть проверкой формата.

`\json5_decode` сначала пробует обычный разбор и берётся за JSON5 только при неудаче, поэтому валидный
JSON не подорожал. Ошибка разбора — `SyntaxError`, наследник `JsonException`: прежние `catch` ловят её
без правок.

Команды, переписывающие конфиг (`make direction` → `config.json`, `make tool` → `settings.json`),
собирают файл заново из массива, поэтому **комментарии в этих двух файлах не выживают** — остаётся
шапка, которую ставит сам писатель (`Support::SCREEN_HEADER`, `Support::SETTINGS_HEADER`). `dbase.json`
и `dbaccess.json` команды не переписывают: там комментарии живут.

`Hands::getToolsFor($place)` сводит мир и голову к `Tools` и ничего больше не разбирает. Права выдаёт
**первое** место, в которое человек вошёл (`head->visitedPlaces[0]`), а не текущее: своё место отдаётся
целиком (`raw()`), каждое следующее — только объявленным в `needs` первого, иначе `AccessNotDeclared`.
Пример: `Home` объявил нужду в `ExampleTool` у `Public/SecondPlace` и получает его; если бы поставщик
публиковал два имени, а в нужде стояло одно, пришло бы одно. Считать права по текущему месту нельзя:
`takeTools` требует, чтобы человек уже стоял там, чьи инструменты берёт, — «чужого» места для неё не
бывает, и нужда не проверялась бы никогда.

### 7.2 Цепочка обязательных условий для чужого инструмента

1. Строка места есть в `places`, и у неё есть направление в `directions` (`World::find`), иначе
   `PlaceNotFound` / `DirectionNotFound` (404). Адрес вида «Направление/Место» разбирает `World`,
   а не голова: голова разбирает адрес РАЗДЕЛА.
2. Ты **дошёл**: `Legs::walk($place)` зовёт `head->noticeNear()` — помнит голова, а не ноги.
3. Ты **вошёл**: `Man::enterPlace($place)` требует `nearPlace === $place` (нельзя телепортироваться),
   иначе `EnterWithoutWalk`; повторный вход → `EnterVisitedPlace`. Выставляет `currentLocation`,
   пишет в `visitedPlaces`, **возвращает `PlacePass`** (выписывает `Man`; чужой вызов ловит
   `OrganAssembly` — сдерживание, а не гарантия, §15.7).
4. Ты **находишься там же**: `Hands::takeTools(PlacePass)` требует `currentLocation === $place`,
   иначе `TakeWithoutEnter`. Пропуск доказывает «входил», но проверку места **не заменяет**.
5. Потребитель — **первое** место запроса (`visitedPlaces[0]`) — объявил нужду в `needs`; поставщик
   опубликовал инструмент в `list`.

**Место входа — исключение, и это правило, а не послабление.** Роутинг уже привёл человека в место
входа: он там по умолчанию, как проснувшийся дома. `Head::getWorkspace()` сразу выставляет `currentPlace`
и `currentLocation`, поэтому для места входа шаги 2–3 не нужны и не проверяются. Для всех прочих мест
цепочка обязательна.

`visitedPlaces` запрещает входить в одно место дважды за запрос → граф обхода модулей **ациклический
по построению**.

### 7.3 `dbase.json` инструмента — контракт доступа к данным

```json5
// Таблицы, к которым инструменту разрешено ходить; сверяются с планом запроса.
{ "tables": ["public.test_table"] }
```

Схема входит в контракт: пишется `"схема.таблица"`, разбор — по **первой** точке. Схема нужна потому,
что план EXPLAIN называет таблицу без неё.

Цепочка целиком:

```
dbase.json → DbaseRights::fromDir($dir) → new Dbase($rights)   ← права входят ОДИН РАЗ, в конструкторе
                                              │
              all/one/run($sql) → guarded($sql) → guard($sql) → demandPlanned($sql) → tablesOf($sql)
                                              │        └ BEGIN до сверки, COMMIT после выполнения
                                              │
                        у инструкции плана не бывает → DbaseMisuse($sql)  — DDL удел миграций
                        таблиц в плане нет → DbasePlanless($sql)  — сверять нечего
                        таблица не объявлена → DbaseDenied($table, $allowed)

              selectUnplanned($sql) → пустой план + чёрный список функций
                                    → SET TRANSACTION READ ONLY
                                    → снимок pg_stat_xact_user_tables до и после ──→ statement($sql)
```

- **Проверка встроена в соединение, а не вынесена в отдельный класс.** Проверка, к которой
  обращаются по желанию, — не проверка. SQL-методов со сверкой три (`all`/`one`/`run`), каждый
  начинается с неё, и внутри них отбросить её нечем. Обхода сверки нет: то, что `EXPLAIN` не
  планирует, эти три метода не выполняют вовсе — схему меняют только миграции. `Dbase` объявлен
  `final`, `guard`/`tablesOf`/`collect` приватны.
- **Права приходят объектом `DbaseRights`, а не массивом таблиц**: массив вызывающий выпишет себе на
  месте (`new Dbase([['public','tools']])`) в обход объявления. `DbaseRights` так не собрать —
  единственный вход `fromDir()` читает `dbase.json`, конструктор приватный. Поэтому `new Dbase()`
  без прав не компилируется, а список таблиц вместо объекта не принимается.
- **Таблицы запроса спрашиваются у самого движка** (`EXPLAIN (VERBOSE, FORMAT JSON)`), а не разбором
  SQL: поэтому алиасы, подзапросы, `JOIN` и `UNION` проверку не обманут. Сбой плана — исключение, а не
  пустой список.
- **Нет таблиц — нет запроса.** План, не назвавший ни одной таблицы, — отказ `DbasePlanless`, а не
  пропуск. Отличить «запрос и не собирался трогать таблицы» от «план погашен» по плану **нельзя**:
  `… WHERE false` и `SELECT 1 WHERE false` дают один и тот же пустой план, поэтому бестабличный
  случай не угадывается, а называется явно — дверью ниже.
- **`all`/`one`/`run` принимают только то, чему план бывает.** Первый значимый знак запроса (после
  пробелов и комментариев) сверяется с закрытым списком `select`, `insert`, `update`, `delete`,
  `values`, `merge`, `with`, `table`. Всё прочее — `TRUNCATE`, `DROP`, `ALTER`, `CREATE`, `COPY`,
  `SET` — отказ `DbaseMisuse` с названной причиной, а не сырая ошибка сервера от `EXPLAIN`
  (`SQLSTATE 42601`). Второго, «непланируемого» режима у этих трёх методов нет: инструкции без плана
  не выполняются вовсе.
- **План спрашивается заново на каждый вызов.** Кэша нет: план зависит не только от текста SQL, но и от
  значений bind-параметров (`… WHERE :cond = 'yes'` при `'no'` гасится в пустой план), поэтому ключ по
  одному тексту отдавал бы вердикт чужого вызова.
- **Сверка и выполнение — одна транзакция.** `EXPLAIN` берёт `ACCESS SHARE` на таблицы плана и держит
  до `COMMIT`: `ALTER`/`DROP` этих таблиц ждёт, поэтому разбор на выполнении видит ту же схему, что и
  проверка. Без транзакции между `tablesOf` и `statement` был бы зазор: `prepare` разбирает запрос
  заново и никем не проверяется — подмена `ALTER … RENAME` + `CREATE VIEW` уводила чтение на другую
  таблицу. Если транзакция уже открыта вызывающим, своя не открывается: там блокировки и так живут до
  его `COMMIT`. Цена — две поездки (`BEGIN`, `COMMIT`) на вызов без транзакции.
- **Соединение — своё у каждого инструмента**, открывается лениво, на первом запросе. Цена — соединений
  столько же, сколько инструментов у места; в обычной странице инструмент один.
- **Транзакции входят целиком**: `beginTransaction`/`commit`/`rollBack` + `inTransaction`. Неверный
  порядок (вложенный `begin`, `commit` без транзакции) → `DbaseMisuse`, а не тихий `false`.
- **DDL в `Dbase` нет вовсе.** `TRUNCATE`, `ALTER TABLE`, `CREATE INDEX`, `DROP TABLE` — не операции
  работы с данными, а смена схемы. Схема меняется в миграции: там она осознанна, обратима и записана
  в журнал со снимками до и после. Отдавать её инструменту значило бы разрешить менять предмет
  разрешения — объявление в `dbase.json` говорит, с какими таблицами инструмент работает, а не каким
  он их сделает. Поэтому `Dbase` умеет только `all`/`one`/`run`, транзакции и `selectUnplanned`.
- **Написание имени таблицы живёт в одном месте на слой.** `Maws\World\System\DbaseSpelling` держит
  правило разбора («схема.таблица», знаки, нижний регистр), и им пользуется объявление
  (`DbaseRights::fromDir` — падает `ContractBroken`). Имя приводится к нижнему регистру:
  `Public.Test_Table` и `public.test_table` — одно и то же. В слое Ai тот же класс свой
  (`Maws\Ai\System\AiDbaseSpelling`): у Ai своя база, общего куска между слоями нет.
- **`lastInsertId()` на PostgreSQL — это `lastval()` соединения, а не «id моей строки».** Пока в
  соединении не тронута ни одна последовательность, сервер отвечает `55000` («lastval is not yet defined
  in this session»), и дверь отдаёт `null` — это «значения ещё нет», а не сбой. После вставки в таблицу
  **без** последовательности остаётся прежнее значение, молча неверное. Замер: до вставки `null`,
  после `INSERT` в таблицу с `serial` — `'1'`, после `INSERT` в таблицу без последовательности — снова
  `'1'`. Поэтому id надёжно берут через `INSERT … RETURNING id` (`one()`), а `lastInsertId()` годится
  только для таблиц с `serial` и только сразу после своей вставки.
- **`selectUnplanned($sql)` — дверь для бестабличных `select`.** Принимает один `select` (иначе
  `DbaseMisuse`), текст без `;` (иначе `DbaseMisuse`), требует **пустой** план (трогает таблицы —
  `DbaseMisuse`), не пускает вызовы из чёрного списка — `query_to_xml`, `table_to_xml`, `pg_read_file`,
  `pg_ls_dir`, `lo_import`, `dblink`, `set_config` и подобные (иначе `DbaseMisuse`) — и выполняется в
  транзакции `SET TRANSACTION READ ONLY`, которая снимается сразу после. Обёртка нужна против
  `SELECT 1 INTO new_table`: план у него пустой, а результат — новая таблица; read-only транзакция такой
  запрос не пропускает. Строки читаются на клиент, поэтому `PDOStatement` переживает откат. План слеп к
  тому, что функция читает у себя внутри, поэтому есть сверка по факту: снимок
  `pg_stat_xact_user_tables` до и после выполнения, и если прибавилась таблица не из `dbase.json` —
  `DbaseDenied`, а результата не будет. Обход назван в контракте (`Effect::DB_UNGUARDED`), а не спрятан.
- **`AiDbase` — та же проверка, другая обвязка.** Те же три метода со сверкой и та же дверь
  `selectUnplanned`, тот же набор операторов в `PLANNED`, тот же страж по плану. Отличий четыре, и все
  они в обвязке: права берутся из `dbaccess.json` (`AiAccess` вместо `DbaseRights`); исключения — те же
  по смыслу, но со своим префиксом (`AiDbaseDenied`, `AiDbaseMisuse`, …); подключение собирается из
  аргументов конструктора — `new AiDbase($access, $dsn, $user, $password)`, тогда как `Dbase` берёт
  константы `DBASE_DSN`, `DBASE_USER`, `DBASE_PASSWORD`; `lastInsertId()` у `AiDbase` нет — метод
  объявлен только у `Dbase`.
- **`PlacePass` соединения не носит** — только имя места.

### 7.4 Движок — PostgreSQL, и он единственный

Проверка держится на том, что движок **строит план запроса и называет в нём таблицы**. Из трёх
популярных баз (MySQL, MariaDB, PostgreSQL) такой план строит только PostgreSQL: он кладёт в один узел
`Relation Name` (настоящее имя), `Schema` (схему) и `Alias` (алиас отдельно). MySQL и MariaDB для
целого класса обычных запросов плана не строят вовсе либо не называют в нём таблицу.

Чужой движок отвергается **прямо**, а не «поддерживается наполовину»: схема DSN читается и сверяется
с `pgsql` **до** открытия соединения. Место проверки — там, где соединение и открывается: внутри
приватного `DbConnector::connect()`, за дверью `pdo()`, в слое World, и в собственном ленивом
коннекте `AiDbase` в слое Ai. `Dbase` её
не повторяет: проверять движок в классе, который работает через уже открытое соединение, значило бы
держать вторую копию правила и надеяться, что обе не разойдутся. Порядок существен: «не тот движок»
не может обернуться «база недоступна» — это разные починки. `#[Throws(DbaseUnsupported::class)]` на
методах `Dbase` описывает то, что видит вызывающий: исключение приходит через соединение на первом
запросе, а не из самого метода.

**Цена сверки — измерена.** План спрашивается отдельным запросом на каждый вызов, поэтому вызов
дороже обычного ровно на стоимость `EXPLAIN`. Замер (300 итераций, локальная PostgreSQL 18.4):

| что | мс на вызов |
|---|---|
| прямой запрос, `prepare` сделан один раз | 0.16 |
| прямой запрос, `prepare` на каждый вызов | 0.49–0.53 |
| только `EXPLAIN (VERBOSE, FORMAT JSON)` | 0.52–0.60 |
| `Dbase::one` целиком | 1.04 |
| `EXPLAIN` + запрос, без транзакции | 1.03 |
| `BEGIN` + `EXPLAIN` + запрос + `COMMIT` | 1.36 |

Сверка добавляет **+0.52…0.55 мс** на запрос — против подготовки, сделанной один раз, это
**+105…114 %**. Внешний замер дал +98 %, но против базовой линии «`prepare` на каждый запрос»:
разница в том, с чем сравнивать, а не в накладных расходах. Двадцать запросов на странице — **+10 мс**.

Транзакция вокруг сверки и выполнения стоит **+0.33 мс** на вызов (1.03 → 1.36 мс, +32 %) — две лишние
поездки к серверу, `BEGIN` и `COMMIT`. Внутри транзакции вызывающего их нет вовсе.

Две оговорки, без которых цифра врёт:

- **`EXPLAIN` планирует заново.** Его цена зависит от сложности плана, а не от времени выполнения:
  запрос на 23 мс прячет сверку в шуме ±1.5 мс, дешёвый — нет. Поэтому «+100 %» относится к дешёвым
  запросам, а не к странице вообще.
- **Кэша нет намеренно** (см. 7.3): ключ по тексту SQL отдавал бы вердикт чужого вызова. Экономия
  здесь была бы куплена дырой в страже, поэтому цена платится целиком.

### 7.5 Миграции: `up()` и `down()`

Схема сайта меняется файлами в `db/migrations/`, журнал — таблица `migrations` в той же базе.

**У миграции две двери — `up()` и `down()`.** Откат пишет автор: только он знает, что делать с тем,
чего в снимке схемы нет, — с последовательностями, представлениями, триггерами и строками, изменёнными
`UPDATE`. Отследить изменения миграции полностью нельзя, поэтому механизм, который выводил бы откат
из разницы снимков, умел бы откатывать только часть изменений и заставлял бы подстраивать миграцию
под себя.

Снимок при этом не выброшен — он стал **проверкой результата**. `Migrator` снимает структуру до
применения и после, оба снимка лежат в журнале, и после `down()` структура сверяется со снимком «до».
Не сошлось — транзакция отменяет откат, база остаётся как была. `down()` — обещание, но невыполненное
обещание видно сразу, а не через полгода.

| Колонка | Смысл |
|---|---|
| `migration` | имя файла без расширения, `UNIQUE` |
| `up_date` / `down_date` | когда применилась / когда откатилась в последний раз |
| `status` | `up`, `down` или **`NULL`** — файл заведён, но не применялся. Отката не было — это не `down` |
| `scheme_before` / `scheme_after` | снимки `jsonb`: таблицы, колонки, ограничения, индексы, число строк |

**Три команды, три разных действия.** `maws make migration <имя>` пишет файл по шаблону и заводит
строку журнала с пустым состоянием; база не меняется. `maws make migrate [<имя>]` применяет
ожидающее по порядку номеров — всё или до названной включительно, каждую миграцию своей транзакцией
вместе с записью в журнал; перескочить предшественников нельзя, очередь идёт подряд. `maws make
rollback <имя>` откатывает **названную** миграцию: «последняя» не угадывается, порядок откатов не
обязан совпадать с порядком применения.

**Откат — выполнение `down()` со сверкой.** `rollback` сначала проверяет, что живая база не ушла от
снимка «после» (по таблицам, которых миграция коснулась), затем выполняет операторы `down()` и требует,
чтобы структура совпала со снимком «до»: созданная миграцией таблица исчезла, изменённая вернулась
к прежним колонкам, ограничениям и индексам. Всё это одна транзакция: не совпало — «down() не
возвращает базу к состоянию до миграции, откат отменён» с причиной в скобках, база остаётся нетронутой.

**Данные не сверяются** — их состояние описывает только автор. Поэтому у отката есть один вопрос
к человеку: если созданные миграцией таблицы уже содержат строки, `make rollback` спрашивает
«Таблицы … содержат данные. Всё равно удалить таблицы?» и по умолчанию отвечает «нет». Молча удалить
наполненную таблицу нельзя, но и запрета нет: решение остаётся за человеком.

**Что чем ловится.** Пустой `down()` у миграции, которая что-то изменила, — отказ «down() пуст».
Изменение, которое `down()` не вернул (или вернул не туда), — отказ по структуре. Миграция, чьи
снимки совпали (её приняли на уже работающей базе), не откатывается вовсе: «не изменила ни структуру,
ни число строк — откатывать нечего», и `down()` при этом даже не выполняется. Отказ самого движка
на любом операторе — «миграция X: оператор N из M не выполнен в up()/down() (SQLSTATE…)»: одной
строкой, без трейса PDO, с номером оператора; транзакция откатывает всё выполненное.

**Чего механизм не видит.** `UPDATE`, не изменивший число строк, в снимке не виден: миграция, которая
только правит данные, считается «ничего не менявшей» и не откатывается. Последовательности,
представления и триггеры в снимок не входят — их откат целиком на совести `down()`.

`0001_initial_schema` создаёт `directions`, `places`, `scenes`, `system`, `areas` с `IF NOT EXISTS`:
на пустой базе таблицы создаются, на уже работающей — принимаются как есть, и снимок фиксирует
фактический результат. В `down()` — пять `DROP TABLE IF EXISTS` в обратном порядке. Откат такой
миграции на давно живущей базе откажет раньше: её снимки совпали, значит откатывать нечего,
и `down()` не выполнится.

Данные в ней тоже есть — главная страница: раздел `Main page` с `title = 'Main page'`, `main = true`,
`parent_id = 0`, пустым `url` и `place_id = 0`. Без этой строки корень чистого развёртывания не
находит раздел: `readRoot` требует ровно один `main = true`. Имя и привязку дозаполняет `make build`:
у миграции нет id места, которое появится позже, поэтому раздел получает имя «Главная страница» и
`place_id` собранного места уже там (§11).

## 8. Экран и сцены

`app/Screen/config.json` — плоский маппинг «ключ → сцена»:

```json
{"Default":"Default","Public":"Default","Error":"Error"}
```

- `Screen::getScene($screenType)`: есть `/` — ключ это первый сегмент; иначе — сам `$screenType`;
  `null` → сцена `Default`. Нет сцены для ключа → `ConfigBroken`.
- Команды (кнопки пульта): **`showPage`**, **`show404`**, **`redirect`**. Неизвестная команда →
  `CommandNotDeclared` (ошибка вызывающего кода, не «страницы нет», поэтому не 404). `redirect` —
  **приватная** кнопка: публичного `redirect` нет ни у `Screen`, ни у `Hands`, нажать её можно только
  командой через `screenInterface` (`$screenType` = `null`).
- **Код переноса — в `$data`.** Строка — адрес, ответ `301`; пара `['url' => адрес, 'status' => код]` —
  адрес и код. Разрешены `301` (постоянный), `302` (временный) и `303` (после POST: браузер обязан
  перейти методом GET). Всё прочее, пустой адрес и не пара — `TransferBroken`. Разбор — `Screen::transfer()`,
  один на все вызовы: `Head::sendAway()` собирает канонический адрес и отдаёт его строкой — код по
  умолчанию 301.
  `307`/`308` не поддерживаются: они нужны там, где важно сохранить метод, а это не «кнопка после формы».
  Адрес прогоном не проверяется (в CLI `headers_list()` пуст), проверяется код и то, что управление
  не вернулось.
- `Screen::screenErrorInterface($status, $message)` сам выбирает команду **по статусу**: 404 →
  `show404` (сцена `Error`, подкаталог `404/`), иначе `showPage` (сцена `Error`). Ключа сбоя в проекте
  нет вовсе. **Код ответа выставляет он же**, до выбора сцены: `(int)`-приведение (`'404'` и `404`
  равнозначны), диапазон 100–599, иначе 500. `showPage` кода не трогает — он показывает и штатные
  страницы, поэтому полагаться на него в ветке ошибки нельзя.
- `sceneUp()` — **конечная точка вывода сцены**: путь собирает `Language::file($каталог, $файл)` —
  `{Сцена}/{Язык}/index.tpl.php`, нет перевода — файл языка по умолчанию; ни того, ни другого →
  `SceneMissing`. Затем `require` в буфер (`ob_start`/`ob_get_clean`) и передача готового тела в
  `Cache::send()`, который
  выставляет заголовки и бросает `ResponseSent`. Буфер обязателен: без него `ETag` считать не по чему,
  а заголовки после первого вывода уже не поставить. Сцена, упавшая на середине, буфер очищает —
  иначе недорисованная страница ушла бы клиенту вместе со страницей ошибки. Конвейер годится только
  для входов, отдающих HTML; воркеры и очереди на нём строиться не должны.
- **Ответ мимо сцены.** Место может ответить само: `Response::send($data, $status, $type)` или
  `Response::json($data, $status)` (`core/System/Helpers/Response/`) печатают тело, ставят
  `Content-Type` и `Cache-Control: no-store`, бросают `ResponseSent` — `initWorkspace()` не вернётся,
  сцена не вызовется. `no-store` там не перестраховка: политику места такой ответ не спрашивает,
  и без явного запрета браузер вправе сохранить его эвристически.
  Строка уходит как есть, массив или объект — в JSON. Так делаются эндпоинты API, страницы без
  обвязки и отдача файлов (для файла — `send` с заголовком руками: `Content-Disposition`).
  `throw`, а не `exit`: `exit` не ловит ни вход, ни тест, а `ResponseSent` даёт во входе пустую
  ветку `catch`, а в прогоне — красный с объяснением. У такого места `#[Returns]` и `#[Changes]`
  снимаются, вместо них `#[Throws(ResponseSent::class, '…')]` и `#[Responds([], '<h1>…</h1>')]` —
  третий аргумент `Responds` это код ответа (по умолчанию 200), и он же порождает прогон тела.
- **Текст сбоя — только в DEV.** Вход передаёт `DEV ? $e->getMessage() : null`; что показать вместо
  текста, решает шаблон сцены (`Error/404` — «404 ошибка», `Error` — «Внутренняя ошибка»).
- **Голова команд экрану не подаёт: пульт держат руки.** `Screen::screenInterface` — сама операция,
  `Hands::useScreenInterface` — релей к ней (симметрично `screenErrorInterface` / `useScreenErrorInterface`).
- **Fail-safe вывода нет — сознательно:** ошибки показываются только файлами сцен,
  текстом на экран не пишем. Цена названа и принята: если сломано именно то, чем показываем сбой,
  исключение вылетит из обработчика, статус уже выставлен, тело пустое, второй сбой виден только в
  логе сервера как PHP-fatal. От php.ini хостинга это не зависит: `index.php` сам выставляет
  `error_reporting(E_ALL)` и `ini_set('display_errors', DEV ? '1' : '0')`. Часовой пояс вход не задаёт:
  его определяет сервер.

### 8.1 Кэш ответа: политика места

Кэшируются **готовые байты ответа**, а не данные и не фрагменты. Второго источника правды нет:
изменились данные — изменилось тело — изменился `ETag`. Поэтому у HTTP-кэша нет отдельной
инвалидации: сверка тела и есть инвалидация.

Объявляет место в `settings.json` (§7.1), разбирает `Policy`, отдаёт `Cache::send()`
(`core/System/Cache/` — часть ядра, не хелпер). Маршрут тот же, что у шапки страницы: место объявляет →
`Head::cachePolicy()` → `Hands::useScreenInterface` → `Screen::sceneUp`. У 404 и `redirect`
политики нет вовсе — `Policy::none()`.

| `settings.json` | `Cache-Control` | `ETag` |
|---|---|---|
| ключа `cache` нет | `no-store` | нет |
| `{"cache": {"ttl": 0}}` | `private, no-cache` | есть |
| `{"cache": {"ttl": 60}}` | `private, max-age=60` | есть |
| `{"cache": {"ttl": 60, "scope": "public"}}` | `public, max-age=60` | есть |

- **`ttl`** — секунды, в течение которых копия свежа; переводится в `max-age`. Внутри этого срока
  сервер **не спрашивают вовсе**: ни рендера, ни запроса к базе, ни сверки `ETag`. Поэтому `ttl` —
  обещание о свежести («час я вправе показывать старую цену»), а не оптимизация; если бизнес такого
  права не даёт, верное значение — `0`. `ttl: 0` даёт `no-cache`: копия хранится, но каждый раз
  сверяется, и при совпадении тела уходит `304` без тела.
- **`scope`** — кто вправе хранить копию. `private` (умолчание) — только браузер посетителя;
  `public` — любой общий кэш, и он вправе отдать копию **другим людям**. `public` ставится только
  явно: это обещание «для всех этот URL даёт байт в байт одно и то же».
- **Разбор строгий**: неизвестный ключ внутри `cache` (в том числе `vary`), `ttl` не целое или
  отрицательное, `scope` не из двух значений → `CacheMisuse`. Опечатка `"scop"` иначе молча
  оставила бы `private`, опечатка в `ttl` — молча `no-store`, и оба случая выглядели бы как «работает».

**Предохранители, без которых `public` — утечка:**

- **`Set-Cookie` отменяет `public`.** Первый заход создаёт сессию и получает печенье; отдать такой
  ответ как `public` — значит выпустить чужой идентификатор сессии в общий кэш. Правило: в ответе
  есть `Set-Cookie` → `public` понижается до `private` молча (`Cache::setsCookie()`). Цена названа:
  **самый первый ответ новому посетителю не попадёт в общий кэш** — на повторных заходах печенье уже
  есть, и `Set-Cookie` не приходит (замер: 1-й заход — `Set-Cookie`, 2-й — нет).
- **Язык из печенья отменяет `public`.** Ответ, собранный под `site_language`, — личный: копия
  ушла бы человеку с другим языком. Правило то же, что с `Set-Cookie`: `public` понижается до
  `private` молча (`Language::fromCookie()`). Кто хочет общий кэш с несколькими языками, кладёт язык
  в адрес — тогда варианты различает сам ключ кэша.
- **Страницы ошибок — всегда `no-store`**, политика места к ним не применяется: `screenErrorInterface`
  зовёт `sceneUp` без политики.
- **`Response::send`/`json` — всегда `no-store`**: ответ места собирается под конкретный запрос и
  политику не спрашивает.

**Механика.** `ETag` — сильный, `"xxh128(тело)"`. `If-None-Match` разбирается как список: `*`
совпадает со всем, `W/` снимается (сравнение слабое, как требует RFC). Совпало → `304` с повторённым
`ETag` и пустым телом; `HEAD` → те же заголовки без тела. Ответ заканчивается `ResponseSent`, а не
`exit`: так его видит и вход, и прогон.

**Сессия не печатает заголовков.** `Session::open()` зовёт `session_cache_limiter('')` перед
`session_start()`: с умолчанием php.ini PHP сам выставляет `no-store`, `Pragma` и `Expires`, и
политика места их уже не перебьёт. До этой правки не кэшировалось ничего — и это был побочный
эффект настройки, а не решение фреймворка.

**Ловушка на стороне сервера.** Сжатие ответа вправе снять `ETag` или ослабить его до `W/` — как
ведёт себя прослойка перед приложением (Apache с `mod_deflate`, nginx с `gzip`, CDN — что у вас),
решает её конфиг, а не приложение. Искать «`ETag` не приходит» всё равно будут в коде.

**Чего сознательно нет.** `Vary` — в MAWS адрес и есть состояние (`?way=…` уже входит в ключ кэша),
поэтому варианты, которым нужен общий кэш, кладутся в адрес, а не в заголовок; язык из печенья
общий кэш просто не получает (§ выше). `Vary: Cookie` — это кэш на каждого посетителя, то есть ноль
выгоды. `Last-Modified` — нет источника правды: mtime шаблона не отражает данные. Кэш данных
(хранилище, ключи, TTL) — отдельное решение со своим вопросом «что делает кэш устаревшим».
`immutable`, `s-maxage`, `stale-while-revalidate` — по строке в тот же разбор, когда появится случай.

**Замер** (живой сервер, сцена `Public`, 720 байт): `Cache-Control: public, max-age=60` +
`ETag`; повтор с `If-None-Match` → `304`, тело 0 байт; `HEAD` → `200`, тело 0 байт; чужой `ETag` →
`200` с телом; `public` + `Set-Cookie` → `private, max-age=60`. Цена: буфер 0.30 мкс, `xxh128` по
720 байтам 0.24 мкс (`sha256` — 4.17 мкс, поэтому взят `xxh128`).

### 8.2 Язык сайта

Язык — **один на запрос и на всё сразу**: сцена и шаблон места берутся из каталогов с одним и тем же
именем. Поэтому он живёт в ядре (`Maws\System\Language`), а не в голове: шаблон места рисуется
глубоко в инструменте, куда голова не дотягивается, а сцену рисует экран, который о голове не знает.

- **Откуда.** `site_language` в печенье, иначе константа `LANGUAGE` из `app/config.php`. Печенье
  принимается только как две строчные латинские буквы (`^[a-z]{2}$`): код становится сегментом пути
  к шаблону, а приходит он от посетителя, поэтому `../x`, `EN` и `english` языком не считаются.
  Нет константы или она не код языка — `LanguageMisuse` (500, «исправить»).
- **Когда.** `Head::getWorkspace()` зовёт `Language::detect($_COOKIE)` до разбора адреса: язык нужен
  и шаблонам, и политике кэша (§8.1 — ответ с языком из печенья не бывает `public`).
- **Где лежат шаблоны.** Сцена — `app/Screen/Scenes/{Сцена}/{Язык}/index.tpl.php`, подкаталог
  ошибки — `.../{Язык}/404/index.tpl.php`. Шаблон инструмента —
  `Tools/{Инструмент}/System/Templates/{Язык}/index.tpl.php`. `Page` собирает путь методом
  `View::template(__DIR__ . '/Templates')`, а не склейкой строки: правило выбора языка одно на всех.
- **Запасной язык.** Нет файла в языке запроса — `Language::file()` берёт файл языка по умолчанию.
  Чужое печенье не роняет сайт: посетитель с `en` увидит `ru`, если перевода нет. Цена названа:
  неполный перевод даёт смешение языков на одной странице — это видно глазами, а не в логе.
- **Новый язык — это каталог.** Скопировать `ru` в `en`, перевести файлы, поставить
  `site_language=en`. Больше ничего: ни реестра языков, ни настройки в `settings.json`.
- **Консоль.** `make direction` и `make tool` спрашивают язык («Укажите язык направления…»,
  «Укажите язык инструмента…») и кладут шаблон сразу в его каталог: константа `LANGUAGE` здесь
  только значение по умолчанию для `make build`, где спросить некого.

## 9. AI-слой: фоновые процессы агентской работы

Агент — **не** орган человека и **не** инструмент места. У него нет ни тела, ни места:
место есть только у человека. Агент — самостоятельный фоновый процесс, **точка входа — сам файл
агента**, а не метод фреймворка. Слой спроектирован так, что проверяется без внешней модели.

Отсюда главное свойство: **`core/Ai/**` не берёт ни одного типа из `Maws\World` / `Maws\Man` /
`Maws\Screen`.** Внешние зависимости слоя — только язык (`JsonException`, `PDO`, `PDOException`,
`stdClass`) плюс базовые `MawsException`/`MawsMisuse`.

`Maws\Ai\Ai` — база агента: `listTools()`, `callTool($name, $arguments)`, `getToolsPromptXml()`,
`getPrompt($data)`, `rights()`. Контракт агента — `tools.json` в каталоге агента (`$agentDir`), формат
MCP: список объектов с `name`, `description`, `inputSchema`. Инструкция — `instruction.prompt.php`
рядом, оставляет в `$prompt` текст. Каталог объявлений объявлен `protected`: ставит его сам агент в
своём конструкторе, а снаружи его не подменить — иначе вместе с каталогом одолжились бы и права.
Наследник расширить видимость до `public` не может: PHP не даёт. Так же объявлена и подсказка —
`protected $prompt` рядом с каталогом: её собирает конструктор агента, и заводить её самому незачем.
Фреймворк подсказку только собирает и **никуда не отправляет**: `$this->prompt` читает `callLLM()`
автора агента. Транспорта к внешнему API в `core/Ai` нет вовсе — в демо `callLLM()` зашит, в бою на
его месте вызов модели. Так же и `work()`: метода с таким именем в `Ai` нет, это соглашение шаблонов
`make agent`; базовый класс даёт пять дверей, точку входа задачи автор выбирает сам.

**Граница «ошибка инструмента / сбой кода»:**

- ошибка **инструмента** (несуществующий инструмент, не тот тип, нет обязательного поля) → **конверт**
  `{"content":{"type":"text","text":"…"},"isError":true}`. Это ответ ДЛЯ МОДЕЛИ, исключения нет.
- сбой **контракта или кода** (объявление не читается; инструмент объявлен, но не реализован) →
  **исключение** — чинит автор агента.

`isError` — параметр исключительно для модели: LLM ошибается в вызове → соединение закрывается →
исключение бросает воркер, в LLM оно уже не уйдёт. Поэтому у `callTool` нет третьего аргумента.

Свой доступ к базе — `$this->rights()`: это `AiAccess` из реестра `dbaccess.json` (формат тот же, что
у `dbase.json`: `{"tables":["схема.таблица"]}`) + `AiDbase` со **встроенной** проверкой прав. Права —
единственная дверь, и она `final`: наследник её не подменит, а `AiAccess` не собрать в обход файла —
конструктор закрыт. Нет `dbaccess.json` — нет прав, отказ `AccessNotDeclared`. Один формат прав на двух
акторов намеренно: два механизма дали бы два места, где права можно забыть.

Требование стоит на **двери**, а не на каждом вызове: агент, который базы не касается, файла может не
иметь и работает (так живут `Agent3` и `Single/Agent`). Поэтому `callTool()` прав не спрашивает —
иначе `make agent` выпускал бы агентов, не способных вызвать ни одного инструмента.

Где живут агенты: `app/Ai/Single/` (`Agent.php` + `tools.json` + `instruction.prompt.php`),
`app/Ai/Multi/{Agent1,Agent2,Agent3}`, `app/Ai/Supervisor/` (`Supervisor.php` + `tools.json` +
`instruction.prompt.php` и под ним `{Agent1,Agent2}`). Реестр прав заведён пока только у
`app/Ai/Multi/Agent1` (`public.test_table` — таблицу для демо заводит миграция `0005`).

**Агент зовёт агента классом.** Сосед — такой же класс со своим объявлением: `Multi/Agent1` объявляет
инструмент `askAgent2`, тот делает `new Agent2()` и зовёт `work($task)` — задача приходит аргументом,
модель выбирает по ней один инструмент, ответ возвращается строкой. Ни процесса, ни строки через
консоль: каталог объявлений у каждого свой и снаружи закрыт, поэтому чужие `tools.json` и
`dbaccess.json` в этот вызов не попадают. Процесс остаётся точкой входа: `php Agent2.php` поднимает
агента и живёт, а класс — это тот же агент, взятый ради одной задачи. В демо цикл при этом **холостой
намеренно**: задача одна, ждать больше нечего. В рабочем коде на его месте блокирующее ожидание задачи
у брокера (Redis, RabbitMQ — что выберет разработчик): процесс спит, пока задачи нет, и просыпается на
новую.

**У надзирателя агенты — его инструменты.** `Supervisor` объявляет подчинённых в своём `tools.json`
ровно так же, как объявляется инструмент: имя (`sayHelloAgent`, `sayByeAgent`), описание и схема
входа с задачей. Модель получает их через `getToolsPromptXml()` и по описанию решает, кого позвать и
с какой задачей; метод-инструмент делает `new Agent1()` и передаёт задачу в `work()`. Задачу «скажи
привет и скажи пока» модель разбирает на два вызова — первому агенту «скажи привет», второму «скажи
пока». Подчинённый вызывается только тогда, когда его выбрала модель: обхода «всем одно и то же»
нет, и порядок задаёт тоже она.

**Демо-агенты отвечают зашитой моделью.** `callLLM()` в этих агентах возвращает зашитый выбор —
какой инструмент и с какими аргументами (`sayHello`, `sayBye`, `askAgent2`), а у `Supervisor` — план
из нескольких вызовов сразу, поэтому демо обходится без цикла «модель → инструмент → снова модель».
Подменена **только модель**: `callTool()` — настоящий, он идёт через `listTools()`, разбор
`tools.json` и проверку аргументов по `inputSchema`. Смысл двоякий: (1) слой работает без внешних
сервисов; (2) виден полный путь задачи — модель выбрала инструмент, инструмент ответил, ответ ушёл
тому, кто позвал (`php app/Ai/Multi/Agent1/Agent1.php`, `php app/Ai/Supervisor/Supervisor.php`).
Подключение внешней модели меняет один метод, не архитектуру.

## 10. Конвенции

- **Инструмент:** путь `{Напр}/Places/{Место}/Tools/{Инстр}/{Инстр}.php`, класс `{Инстр}` в
  `namespace App\World\{Напр}\Places\{Место}\Tools\{Инстр}`. Направление и место в имени класса не
  повторяются: их несёт пространство имён, поэтому одноимённые места в разных направлениях больше не
  сталкиваются.
- **Воркспейс:** `{Напр}/Places/{Место}/Workspace.php`, класс `Workspace` в
  `namespace App\World\{Напр}\Places\{Место}`; база — `{Напр}Workspaces` в
  `namespace App\World\{Напр}\Places` (`PublicWorkspaces`).
- **В корне папки инструмента** — главный класс `{Инстр}.php` и `dbase.json`; **под `System/`** —
  `Repository.php` (репозиторий поверх `Dbase`), `Page.php` (рендер) и, если инструмент рендерит шаблон,
  `Templates/{Язык}/index.tpl.php`. Шаблон не обязателен: `Page` вправе вернуть литерал вместо подключения шаблона.
- **Инструмент рендерит сам:** `serve()` собирает `Repository` поверх `$this->db`, отдаёт данные в
  `Page` (наследник `Maws\Screen\System\View`), а тот через `render()` возвращает готовую строку HTML.
- **Собственного конструктора у инструмента быть не может** — `Tool::__construct` объявлен `final` и
  принимает имя инструмента и `Dbase`; наследник его не переопределит.
- **Докблоков в коде не пишем** (правило проекта). Семантику несут имена свойств атрибутов контракта.
- **Комментарий описывает фреймворк как готовый.** Ни истории разработки («раньше», «теперь»,
  «было — стало»), ни отчётов о том, что когда-то ломалось, ни ссылок на этот документ по номеру
  параграфа: читатель скачал фреймворк и не обязан знать, как его чинили. История живёт в `TODO.md`.
- **Классы в `app/**` автозагружаемы:** `App\` → `app/`, имя класса = имя файла, namespace = путь от
  `app/`. Файл, объявивший другое имя, не загрузится — `make build` называет такие файлы поимённо.
- **Списки листаются `Pager`.** `Pager::over($db)->perPage(20)->at($n)->fetch($sql)` отдаёт `Page`:
  `rows()` — строки страницы, `perPage()` — размер, `total()`, `pages()`, `number()`, `offset()`,
  `has()`, `next()`, `previous()`.
  Размер страницы — политика инструмента, умолчания нет; `LIMIT`/`OFFSET` в запросе не пишутся — их
  добавляет пагинатор, и запрос с ними получает отказ.
- **Органы объявлены строго.** Все пять классов сборки — `Man`, `Body`, `Head`, `Hands`, `Legs` —
  `final`; органы и `world`/`screen` — `readonly` с типом (`public readonly Head $head;`); у каждого
  приватный `__clone`. Это не украшение: так «тело без органов» становится **невыразимым**, а не
  проверяемым — см. §15, пункт 7. Страж `Man` остаётся, но отвечает только за читаемый отказ.
  Утверждение прогоняется, а не декларируется: `core/System/Test/Invariants.php` (25 случаев, §16).
- **`Tools/{Инстр}/System/Templates/{Язык}/index.tpl.php` и `core/**/Cli/**/templates/*.tpl.php` не валидный
  PHP** и не линтуются (подстановка `{{Body}}`, `{{Methods}}`). Исключены из `.php-cs-fixer.php` через
  `notName('*.tpl.php')`.

## 11. Как добавить место / инструмент

**Через CLI (предпочтительно):** `maws make direction|place|tool|agent` — интерактивно, цифровым меню
(`Support::menu`), шаблоны `templates/*.tpl.*` с `{{Placeholder}}`. `make place` создаёт отсутствующий
`{Напр}Workspaces.php`, а если строка в `places` уже есть, а каталога нет — восстанавливает файлы в неё,
не трогая раздел; `make agent` single → `Ai/Single/Agent.php`, multi → `Ai/Multi/{Имя}/`, supervisor →
`Ai/Supervisor/{Имя}/` и рядом, если их ещё нет, `Ai/Supervisor/{Supervisor.php, tools.json,
instruction.prompt.php}` — надзиратель такой же агент, контракт у него свой.

**С нуля:** `maws make build` — применяет миграцию и собирает каркас: направление `Public` (каталог,
базовый класс, сцена, `config.json`), места `Home` и `SecondPlace`, раздел «Главная страница»,
инструменты `ExampleTool` и `ExampleTool_1` у `Home` и `ExampleTool` у `SecondPlace` —
со связями: строка в `directions`, `place_id` в `areas`, `tools.list` в `settings.json` обоих мест и
`tools.needs` у `Home`. Раздел идёт
после места, потому что ведёт в него: `main = true` и `place_id` созданного места ставятся одним
шагом, иначе корень остался бы без главной. Команда не дополняет существующее: если хоть что-то из
каркаса уже создано, она перечисляет найденное и не начинается.
Каркас собран так, чтобы страница сразу что-то показывала: пространство места отдаёт
`$tools->ExampleTool->serve()`, а инструмент читает `test_table` из миграции 0005 через `Repository`
и печатает строки шаблоном. Поэтому имя инструмента уходит в `MakePlace::create()`, а таблица и
`demo: true` — в `MakeTool::create()`: показной инструмент держит чтение и разметку в разных методах
(`getTestData()`, `showHTML()`), чтобы было видно, что разметка — один из его выходов, а не
обязанность.
Второе место существует ради `needs`: без него `settings.json` показывал бы только `list`, а нужду
пришлось бы выдумывать. Раздела у него нет — раздел задаёт адрес страницы, а нужда разрешает
инструмент.
Имена зашиты в `Build::DIRECTION|PLACE|PLACE_1|TOOL|TOOL_1|AREA` — это каркас, а не генератор имён. `make direction` заводит
и строку в `directions`: она первая, файлы вторые, при сбое файловых шагов строка снимается.
Сцену он кладёт в каталог языка, который спросили при создании, —
`Screen/Scenes/{Напр}/{Язык}/index.tpl.php`; `make tool` спрашивает так же:
`System/Templates/{Язык}/index.tpl.php`. `LANGUAGE` — язык сайта по умолчанию: её читает
`Language::configured()` на каждом запросе, когда нет печенья `site_language`. `make build` языка не
спрашивает и берёт `Language::current()`, то есть ту же константу; остальные команды спрашивают явно.

> **Шаблон `*.tpl.php` — не валидный PHP, и это норма.** Подстановка вставляет в него операторы
> (`{{Body}}`, `{{Methods}}`), поэтому сырой файл не проходит `php -l`. Половина шаблонов проекта
> (`agent`, `workspaces`, `workspace`, `dbase`, `tool`, `view`) ведёт себя так же. Поэтому шаблоны не
> линтуются и исключены из `.php-cs-fixer.php` через `notName('*.tpl.php')` — «починить» их нельзя,
> ошибка разбора здесь не дефект.

**Руками — чек-лист:**

1. Строка в таблице `places`: `name` (с большой), `direction_id`. Адреса у места нет — адрес есть
   у РАЗДЕЛА: строка в `areas` (`name`, `url` строчными, `parent_id`, `place_id`, `main`) ставит место
   в дерево сайта. Проще — `maws make place` (строка в `places` и файлы места) и `maws make area`
   (строка в `areas`: родитель, `url`, место). Раздел наследует место, а не наоборот: `make area`
   выбирает готовое место и файлов не трогает.
2. Создать `app/World/{Напр}/Places/{Место}/Workspace.php`: `namespace App\World\{Напр}\Places\{Место}`,
   класс `Workspace extends {Напр}Workspaces`, метод `startWork()`. Конструктор принимает
   `($place, $man, $area)` — раздел приходит от роутинга и приносит метаданные страницы; это объект
   `Area` (`id()`, `name()`, `url()`, `placeId()`, `parent()`, `isMain()`, `fields()`), и он же лежит
   в `$this->area`. Место от раздела не зависит: без раздела оно живёт, но открыть его нечем —
   адреса нет. Случая в контракте у `startWork()` нет: он отдаёт страницу, и сверять её байт в байт
   значило бы заморозить шаблон. Воркспейс проверяется живой пробой — запросом к месту, — и
   `maws make test:` на нём отвечает «в контракте нет проверок».
3. Создать `settings.json` с `tools.list` (и `tools.needs` при необходимости).
4. Инструмент: `Tools/{Инстр}/{Инстр}.php` (класс `{Инстр} extends Tool` в
   `namespace ...\Tools\{Инстр}`, метод `serve()`) и `Tools/{Инстр}/dbase.json`; под `System/` —
   `Repository.php`, `Page.php`, `Templates/{Язык}/index.tpl.php`.
5. Таблицы, объявленные в `dbase.json`, должны существовать в PostgreSQL.
6. Сцена — **только если нужно** (и всегда на направление, см. §6) + запись в `Screen/config.json`.

## 12. Контрактные атрибуты — как читать код

Методы ядра и инструментов описаны **декларативными атрибутами** `Maws\System\Contract\`, а не
докблоками. Читая метод, смотри атрибуты рядом с ним: `Purpose` (зачем), `Param` (параметры),
`Returns` (что возвращает), `Throws` (когда бросает), `Effect` (внешние эффекты), `Gives`/`Has`/
`Fails`/`Changes`/`Responds` (вызов → значение / ключи результата / исключение / проверки состояния /
напечатанный ответ), `Subject` + `Fixture` (как собрать получателя и песочницу для прогона).

Главное правило: **объявленный контракт проверяется ПРОГОНОМ, а не разбором атрибутов** — прочитать их
через Reflection необходимо, но недостаточно. Как прогон устроен изнутри — от разбора атрибутов до
строки `[ok]` в отчёте — описано отдельно, в `HOWITTEST.md`.

Прогон делает команда `maws make test:<файл>` (см. §13). Она читает атрибуты источника, пишет по ним
читаемый тест в `app/Tests/**` и тут же запускает его отдельным процессом. `Subject(factory: ...)`
разворачивается так:

| Запись | Смысл |
|---|---|
| `'new'` | `new <Класс>(...аргументы)` |
| `'метод'` | статический метод **самого класса получателя** |
| `'Класс::метод'` | статический метод другого класса; имя без `\` разворачивается в `Maws\System\Test\<Имя>` |

Прогон **фиксирует часовой пояс** (`Runner::ZONE = 'UTC'`): примеры `Gives` записаны в UTC, а пояс
машины задаётся `php.ini`. Без фиксации оракул отвечал бы на настройку сервера, а не на код, и краснел
бы на другой машине, ничего не проверив по существу. Это свойство прогона, а не фреймворка: сам сайт
живёт в поясе сервера, и `Date` считает даты именно в нём.

Для классов из `app/**` в контракте работает и `'Scaffold::workspace'` с аргументом-адресом: тест сам
подключает файл источника (см. ниже), а `Scaffold` собирает место и его пространство по адресу.

Все `Scaffold::*` живут в `core/System/Test/Scaffold.php` (`Maws\System\Test\Scaffold`) — это строитель
корня: он собирает актёров (`man`, `placePass`, `place`, `workspace`, `tool`), читает права и политику
кэша из песочницы (`dbase`, `dbaseRights`, `aiAccess`, `aiDbase`, `policy`) и собирает агента-пустышку
(`ai`: `agentDir` = песочница плюс один инструмент, чтобы проверить проводку `Ai`). Служебные
`begin`, `sandbox`, `path`, `world`, `screen` — не фабрики: их зовёт `Runner` и разворот токенов,
в контракте они не пишутся. Аргумент файловой фабрики (`'dbase.json'`) — **имя
файла внутри песочницы**: каталог `Scaffold` вычисляет сам. Файлы песочницы объявляет `#[Fixture]` — на
классе или на отдельном методе (смена песочницы липкая: действует, пока следующий метод не объявит
свою), путь к ним доступен как `Token::SANDBOX`.

Фабрики места: `place('Public/Home')` — `Place` по адресу (проверенный по карте мира);
`workspace('Public/Home')` — рабочее пространство места; `tool('Public/Home', 'ExampleTool')` — инструмент с
базой под его правами. Последняя проходит всю цепочку сама (`getWorkspace` → `walk` → `enterPlace` →
`takeTools`): **`takeTools` требует `currentLocation`, а его ставит `enterPlace`, а не `getWorkspace`** —
поэтому одним `placePass` инструмент не берётся: пропуск выписывает вход, а вход требует, чтобы человек
сначала подошёл.

### 12.1 Как ПИСАТЬ разметку — мануал

Порядок: **сначала объявление, потом прогон.** Атрибут — это заявление о методе; пока `make test` не
пройден, оно намерение, а не факт. Правило простое: **описал метод — прогони его.**

**Шаг 1. Класс — `#[Subject]`.** Он говорит, как собрать проверяемого. Обязателен только он; без него
тест не создаётся вовсе. Четыре поля — `class`, `factory`, `args`, `path`; разберём каждое с примером.

**`class`** — класс-получатель, ровно `X::class`; другого вида записи нет.

```php
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]
```

**`factory`** — как собрать **корень** (не получателя). Три формы; третья бывает записана коротко
и полным именем:

```php
#[Subject(Screen::class, 'new', [])]                          // 1. обычное new, без аргументов
#[Subject(Pager::class, 'fixture', ['dbase.json'])]           // 2. свой статический метод получателя
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]   // 3. другой класс: имя без «\» → Maws\System\Test\Scaffold
#[Subject(Place::class, 'Maws\System\Test\Scaffold::place', ['Public/Home'])]   // 3. то же полным именем
```

**`args`** — аргументы фабрики: **только константные выражения** и токены. Путь к файлу — имя файла
внутри песочницы, каталог подставляет `Scaffold`.

```php
#[Subject(Dbase::class, 'Scaffold::dbase', ['dbase.json'])]    // 'dbase.json' — файл в песочнице
#[Subject(Place::class, 'Scaffold::place', ['Public/Home'])]   // 'Public/Home' — адрес места
#[Subject(Screen::class, 'new', [])]                           // аргументов нет
```

**`path`** — цепочка публичных свойств через `->` от корня до получателя; пусто — получатель и есть
корень.

```php
#[Subject(Man::class,   'Scaffold::man', [])]                   // пусто: корень и есть получатель
#[Subject(Head::class,  'Scaffold::man', [], 'head')]           // Man → head
#[Subject(Hands::class, 'Scaffold::man', [], 'body->hands')]    // Man → body → hands
```

Цепочка идёт только по публичным свойствам, и провал здесь не «мягкий»: `subjectUp()` спускается
прямым `$subject->$step`, поэтому приватное свойство даёт `Error: Cannot access private property`,
а опечатка — `Warning: Undefined property` и `TypeError` от `subjectUp(): Return value must be of type
object`. `TestMisuse` («нет свойства …») — это про шаги `before`/`then`: там путь разбирает `peek()`
и сверяет свойство с `isPublic()` до обращения.

Один и тот же класс объявляется **один раз** на файл (атрибут на уровне класса).

**Шаг 2. Метод — что он делает.** `#[Purpose]` ставится на класс и на метод; остальные — по надобности:

- `#[Purpose('…')]` — одна фраза, зачем. Без пересказа реализации.
- `#[Param('имя', 'тип', 'уточнение')]` — **по разу на параметр**, в порядке сигнатуры. Уточнение можно
  не писать, если имя говорит само.
- `#[Returns('тип', 'уточнение')]` — для `void` **не ставить**, тип виден в сигнатуре.
- `#[Throws(КлассИсключения::class, 'когда')]` — по разу на каждый случай отказа.
- `#[Effect(Effect::DB_READ)]` — внешние эффекты; вид брать из констант `Effect::*`. `Effect::NONE`
  ставить явно, чтобы «эффектов нет» было видно, а не подразумевалось.

**Шаг 3. Случаи прогона — `Gives` / `Has` / `Fails` / `Changes` / `Responds`.** Это то, что реально проверяется:

- `#[Gives([аргументы], ожидаемое_значение)]` — успешный вызов.
- `#[Has([аргументы], ['ключ', …])]` — успешный вызов, результат обязан быть массивом, в котором есть
  перечисленные ключи. **Значения и лишние ключи не сверяются**: чем наполнена строка и какие колонки
  в таблице появились — право того, кто ведёт данные. Так проверяют форму, а не содержимое.
- `#[Fails([аргументы], КлассИсключения::class)]` — отказной вызов.
- `#[Changes([аргументы], [[путь, аргументы, ожидание], …])]` — мутирующий: что стало **после** вызова.
- `#[Responds([аргументы], 'тело', код)]` — метод сам завершил ответ: сверяются напечатанное и код
  ответа, а `ResponseSent` обязателен (см. §8).

Аргументы — **только константные выражения** и ссылки-токены (`Token::SANDBOX`, `@subject`…). Каждый
случай — отдельный атрибут; их бывает несколько на метод.

**Подготовка до вызова — `before`.** Четвёртый/третий аргумент: список шагов, которые надо выполнить,
чтобы дойти до интересного состояния. Шаг — `[путь, аргументы]` (или `[путь, аргументы, имя]`).

```php
#[Gives([], true,  before: [['beginTransaction', []]])]                 // сначала открыть транзакцию
#[Changes(['Public/Home'], [['head->currentLocation', [], 'Public/Home']],
          before: [['legs->walk', ['Public/Home']]])]                   // сначала дойти до места
#[Gives(['probe'], 'value', before: [['set', ['probe', 'value']]])]     // сначала положить в память
```

Путь в шаге и в проверке — **тот же `'->'`-синтаксис**, что и в `path`: без ведущего `$this`, просто
`'head->currentLocation'`.

**Песочница — `#[Fixture]`.** Файлы, создаваемые до прогона, — пары «путь в песочнице → содержимое»:

```php
#[Fixture(files: ['dbase.json' => '{"tables":["public.test_table"]}'])]
```

Путь в аргументах фабрики — **имя файла внутри песочницы** (`'dbase.json'`), не путь на диске: каталог
`Scaffold` подставляет сам. Отдать путь песочницы наружу можно через `Token::SANDBOX` в аргументах случая.

**Токены** (`Maws\System\Contract\Token`) — не атрибут, а имена-затычки там, где объект аргументом не
передать: `Token::SUBJECT`, `Token::SANDBOX`, `Token::WORLD`, `Token::SCREEN`. Особый случай —
`Token::STATEMENT` в `Gives`: он ставится на место **ожидаемого значения** и означает «вернулось готовое
выражение `PDOStatement`», потому что объект в атрибут не записать:

```php
#[Gives(['SELECT 1'], Token::STATEMENT)]
```

Такой случай прогон сверяет не на равенство, а на `instanceof \PDOStatement`.

**Чего в разметке не делать.** Докблоков — нет (правило проекта, семантику несут имена атрибутов).
Не выдумывать `Gives` «на будущее» — пустой тест команда не создаст. Не описывать в атрибуте то, что
видно из сигнатуры (`void`, типы). Не забывать: у примитивных типов без разметки попадание верное, а
**разойдётся объявление с телом — поймает только прогон.**

### 12.2 Разметка на `app/**`

Классы `app/**` автозагружаются так же, как ядро: PSR-4 ведёт `App\ → app/`, поэтому имя класса — это
имя файла, а пространство имён — путь от `app/`. Тест всё равно подключает файл источника явно
(`require_once $root . '/<источник>';`): так ошибка «класс не найден» остаётся внятной, а не тонет в
автозагрузке. Родитель — база направления `App\World\{Напр}\Places\{Напр}Workspaces` — грузится вызовом
`\Maws\World\World::loadDirection('{Напр}');`, который генератор ставит в шаблон теста перед
`require_once`: прогон не должен зависеть от того, что до него выполнил другой файл.

Если класс после этого не объявлен — отказывает **генератор**, ещё до создания теста: «Класс источника
не объявлен: …», файл в `app/Tests/` не появляется, код возврата 1. У прогона свой отказ — `TestMisuse`
«класс … не найден: файл источника не объявил его — проверь имя класса и то, что его родитель
загружен», — но в `make test:` до него не доходит: он остаётся для теста, написанного руками, и для
сгенерированного, чей класс исчез позже (и только если фабрика названа без класса: при
`Scaffold::workspace` `Runner` класс не сверяет; генератор требует его всегда, при любой фабрике).

Это **ошибка разработчика, а не фреймворка**: контракт объявляется на классе, который грузится сам.
Рабочий пример — `Workspace.php` любого места: он и `#[Subject(Workspace::class, 'Scaffold::workspace',
['Напр/Место'])]` несёт, и родителя получает автозагрузкой.

## 13. CLI

`maws.php` (корень, класс `Maws`, глобальное пространство) разбирает `$argv[1]` и зовёт классы из
`core/System/Cli/**` (namespace `Maws\System\Cli\`).

### 13.1 Команды

| Команда | Что делает |
|---|---|
| `maws make direction\|place\|area\|tool\|agent` | создаёт сущность по шаблонам |
| `maws make migration <имя>` | пишет файл миграции в `db/migrations` и заводит строку журнала |
| `maws make migrate [<имя>]` | применяет ожидающие по порядку номеров — все или до названной включительно |
| `maws make rollback <имя>` | откатывает названную миграцию: выполняет `down()` и сверяет структуру со снимком |
| `maws make build` | собирает каркас с нуля: миграция, направление Public, места Home и SecondPlace, раздел «Главная страница», инструменты ExampleTool, ExampleTool_1 и нужда Home в SecondPlace |
| `maws make test:<файл>` | прогоняет контракт файла: создаёт тест и выполняет его |
| `maws test` | прогоняет **все** контракты `core/**`: файлы с `#[Subject]`, каждый своим процессом, со сводкой |
| `maws style` | PHP-CS-Fixer по `core/`, `app/`, `public/`, `db/` |
| `maws doctor` | проверяет окружение: PHP, расширения, константы, права на каталоги, базу, проверки приложения |
| `maws list` | список команд |
| `maws about` | сведения о проекте |

### 13.2 Каркас: `make`

`make place` заводит место: строка в `places`, каталог `{Напр}/Places/{Место}/` с `Workspace.php`,
`settings.json` и `Tools/`. Раздел не спрашивается — место от него не зависит. `make area` заводит
раздел в дереве `areas` (`url`, `parent_id`, `main`) и **наследует готовое место**: `areas.place_id` —
то, что делает место видимым, поэтому порядок обратный: сначала место, потом раздел. `make direction`
и `make tool` спрашивают язык и кладут шаблон сразу в каталог языка; `make agent` заводит агента
(`single` или именованного) вместе с `tools.json`.

`make migration` пишет файл `db/migrations/NNNN_имя.php` (`up()` и `down()`, только SQL) и заводит
строку журнала; `make migrate [<имя>]` применяет ожидающие по порядку номеров — все или до названной
включительно; `make rollback` выполняет `down()` и сверяет структуру со снимком, снятым до `up()`.
`make build` собирает каркас с нуля:
миграция, направление Public, места Home и SecondPlace, раздел «Главная страница», инструменты
ExampleTool и ExampleTool_1 у Home и ExampleTool у SecondPlace, нужда Home в инструменте соседа.
Второй инструмент Home — обычная заготовка: он нужен не странице, а тому, чтобы `settings.json` места
показывал список из двух. Второе место нужно тому же `settings.json`: без него `needs` показывать
не на чем. Подробности каждого шага — в руководстве, §14.

### 13.3 Прогон контрактов: `make test:` и `maws test`

`maws make test:<файл>` берёт путь **от корня проекта**: `maws make test:core/World/System/Place.php`.
Тест ложится зеркально в `app/Tests/**` (`core/…` → `Core/…`, `app/…` → `App/…`, `.php` → `Test.php`),
перезаписывается при каждом запуске и запускается **отдельным процессом** — состояние не течёт между
файлами (`Memory` — синглтон на процесс, см. §15). Прогон требует живую PostgreSQL и падает, если её
нет. Если в файле нет `#[Subject]` или нет ни одной проверки `Gives`/`Has`/`Fails`/`Changes`/`Responds`, тест не
создаётся, и команда говорит об этом прямо. Полноту она проверяет до записи: сначала судит **имена**
атрибутов — опечатка или забытый `use` даёт отказ с номером строки и подсказкой, — потом считает случаи
дважды, по тексту и отражением (§15.2). Созданный тест она предваряет строкой «Проверок в контракте:» и
числом — по нему видно, что тест неожиданно похудел. **Код возврата различает три исхода:** 0 — всё
прошло,
1 — провал ИЛИ «ничего не проверено» (нет файла, нет `#[Subject]`, нет проверок, класс не загрузился).
«Не проверялось» больше не выглядит успехом.

Тесты **не версионируются** (`/app/Tests/` в `.gitignore`): они выводятся из атрибутов и перезаписываются
при каждом прогоне, поэтому в репозитории лежала бы копия контракта, которая устаревает молча. Проверено
на чистом чекауте: без `app/Tests` целиком прогон создаёт дерево сам. Условие для CI одно — каталог
должен быть записываемым.

`maws test` — тот же прогон, но по всем контрактам сразу, для CI. Источники ищутся по тексту
(`^#[Subject(` с начала строки), а не отражением: контракт объявляется и на классе, который грузится
только вместе с родителем, и в обход по классам он не попал бы. Каталоги `templates/` пропускаются —
там объявление написано для будущего класса. Каждый файл по-прежнему идёт **своим процессом**, иначе
фатал в одном обрывал бы остальные, а соединение и сессия текли бы между контрактами. Строка `[ok]`,
`[!!]` или `[--]`: третья значит «`#[Subject]` объявлен, а случаев нет» — файл ничего не проверяет, и
это не провал прогона, но и не успех. Провал печатается подробностью (`[fail]` и что получено), код
возврата — 1. Полный обход 50 контрактов занимает около минуты: почти всё время — запуск PHP и
подключение к базе, поэтому параллелить не стали, пока это не мешает.

### 13.4 `style` — формат

`maws style` ищет фиксер по **жёстко прописанному пути** `dirname(__DIR__, 4) . '/.tools/php-cs-fixer.phar'`
(это `<корень проекта>/.tools/php-cs-fixer.phar`, см. `Style.php`), а конфиг — `.php-cs-fixer.php` в корне.
Не `vendor/bin/` — php-cs-fixer не зависимость composer. Запускается через `PHP_BINARY`. Команда
**реально правит файлы** и лишние аргументы игнорирует — для проверки запускать фиксер напрямую с
`--dry-run`.

> **`.tools/` целиком в `.gitignore`** — фиксер не хранится в репозитории: это сторонняя сборка
> (3.95.27 под PHP 8.1.33). Каталог создаётся вручную; пока файла нет, команда печатает инструкцию
> и ничего не делает:
>
> ```
> mkdir .tools
> curl -L https://github.com/PHP-CS-Fixer/PHP-CS-Fixer/releases/download/v3.95.27/php-cs-fixer.phar -o .tools/php-cs-fixer.phar
> ```
>
> Последняя версия — https://cs.symfony.com/download/php-cs-fixer-v3.phar. Версию держат той же, что
> у остальных: разные версии фиксера дают разные правки форматирования.
>
> **Проверять только свои каталоги:** `fix --dry-run --config=.php-cs-fixer.php --path-mode=intersection
> core/System/Test core/System/Cli/MakeTest`. Без `--path-mode` фиксер идёт по всему `Finder` (`core/`,
> `app/`, `public/`, `db/`) и в отчёт попадают чужие находки.

### 13.5 `maws doctor` — окружение и связность

Первая команда на новой машине и первая после переезда на хостинг: она отвечает «что именно не
работает», а не «что-то не работает». Строка на проверку, три состояния и итог; **код возврата 1 при
любом провале**.

| Метка | Значение |
|---|---|
| `[ok]` | проверено, в порядке |
| `[!!]` | провал: без этого сайт не работает |
| `[??]` | предупреждение: не работает часть хелперов, но сайт жив |
| `[--]` | не проверялось — и тут же сказано, почему |

Три состояния, а не два, потому что провал и предупреждение — разные вещи: `gd` нужен `Image` и
`Upload`, а сайт без картинок живёт; красный doctor на здоровом сайте приучил бы не смотреть на его цвет.

Ядро проверяет версию PHP, расширения, константы конфига, права на каталоги, доступность базы и версию
фреймворка.

**Порог PHP берётся из `composer.json`** (`require.php`, вид `>=8.1`), а не из константы в коде: два
места с одним и тем же числом расходятся — вопрос времени, а не вероятности. Там же, где порог не
объявлен или записан нераспознаваемо, doctor не выдумывает версию, а говорит `[--]`.

**Расширения.** `pdo_pgsql`, `mbstring`, `json` — провал, и в строке сказано, что именно встанет:
без первого нет соединения с базой, без второго рвётся русский текст в `Text` и `Csv`. `gd` —
предупреждение.

**Константы конфига** — одиннадцать обязательных. Пустая строка считается незаданной: пустой
`DBASE_DSN` выглядит объявленным и не описывает базу. `DBASE_PASSWORD` в списке нет — пустой пароль
законен. Отсутствие константы не отменяет остальные проверки: каждая говорит, что ей нужно, и одна
дыра в конфиге не прячет сбой в другом месте.

**Права проверяются записью, а не `is_writable()`**: бит «на запись» ничего не говорит о разделе,
смонтированном только для чтения, и о переполненном диске. В каталог кладётся файл
`.maws-doctor-<pid>`, читается обратно по длине и сразу удаляется — это единственное место, где
`doctor` пишет на диск. Каталог журнала может отсутствовать: `Log` заводит его сам, поэтому тогда
проверяется родитель, и это сказано в самой строке отчёта.

**База проверяется той же дверью, что и сайт** — `DbConnector::pdo()`, и `Doctor` вписан в его список
`OPEN_TO` поимённо. Соединение, собранное вторым способом, отвечало бы за другое: не тот DSN, не та
проверка движка. Отсюда же приходит `DbaseUnsupported`: на MySQL doctor скажет об этом прямо, а не
напишет «база отвечает».

**Проверки приложения — снаружи.** Ядро не знает, какие таблицы должны быть на месте и какой внешний
сервис обязан ответить; список приходит из `app/config.php` константой `DOCTOR_CHECKS` — `имя =>
callable`:

```php
define('DOCTOR_CHECKS', [
    'имя проверки' => static fn (): ?string => null,  // null — в порядке, строка — что сломалось
    'или метод'    => [App\Doctor\Checks::class, 'service'],
]);
```

`define()`, а не `const`: замыкание в `const` не положить, а именно оно и удобно для короткой проверки.
Правило ответа одно: `null` — в порядке, непустая строка — что именно сломалось; исключение — тоже
провал, и печатается его текст. Объявленная проверка, которая не вызывается (опечатка в имени класса),
— **провал**, а не пропуск: иначе она создаёт видимость, что этот случай кто-то стережёт. Отсутствие
`DOCTOR_CHECKS` — `[--]`, а не ошибка: приложению может быть нечего проверять.

**Версия фреймворка** читается из `composer.json`; пока её там нет — `[--]` с отсылкой к пункту 1.4
`PRODUCTION.md`. Это не провал: сайт работает и без номера версии.

## 15. Ловушки

1. **Подстановки имён классов под `namespace` не бывает** (в отличие от функций и констант): голое
   `extends Exception` ищет `NS\Exception` и падает `Class not found`. Нужен ведущий `\`.
   `php -l` этого не видит.
2. **Неразрешимый тип в `catch` — молча мёртвая ветка.** Классы для `catch` PHP не подгружает, поэтому
   `catch (JsonException $e)` без `use JsonException;` не даёт ни ошибки, ни предупреждения — просто не
   совпадает никогда. Проверяется прогоном: сломать базу или имя класса в `catch` → ветка не сработает.
   **То же с атрибутами контракта:** `#[Fails(...)]` без `use ...\Contract\Fails;` превращается в
   `NS\Fails` — класс, которого нет. PHP при объявлении его не проверяет, отражение ищет случаи по
   настоящему классу, и случай исчез бы из теста молча. Поэтому генератор судит **имена**: каждый
   атрибут файла разрешается по `use` и пространству имён, и если такого класса нет — отказ до записи
   теста: «Атрибут Fails (строка 19) не разрешился: … Добавь use Maws\System\Contract\Fails; — или
   исправь имя». Опечатка ловится тем же правилом: `#[Fail]` — это `NS\Fail`, класса нет, и в ответе
   подсказка «Похоже на Fails». Групповой `use A\{B, C}` разбирается, а не пропускается — он в
   контрактах самый частый. Второй счёт, объявлено против собрано, ловит то, чего не видно по имени:
   атрибут стоит не на методе — «Объявлено случаев Fails: 1 (строки 12), собрано 0». Счёт в выводе
   остаётся для человека, но следит за ним машина.
3. **`new` с неразрешимым именем — громкий фатал.** Лечится `use stdClass;`.
4. **`app/**` автозагружается** — PSR-4 ведёт `App\ → app/`, имя класса равно имени файла, пространство
   имён — путь от `app/`. Контракт на `app/**` объявляется в самом файле; генератор добавляет
   `require_once` источника и `World::loadDirection('{Напр}')` перед ним — база направления грузится
   явно, а не «повезло, что уже подключена». Если класса нет, отказывает **генератор** — «Класс
   источника не объявлен: …», тест не создаётся, код 1. У прогона свой отказ (`TestMisuse` «класс …
   не найден: файл источника не объявил его»), но в `make test:` до него не доходит: он остаётся для
   теста, написанного руками, и для сгенерированного, чей класс исчез позже. Фабрика на генератор не
   влияет: класс он требует при любой, в том числе при `Scaffold::…`. Разница видна только на
   прогоне — там при `Scaffold::…` `Runner` класс не сверяет: предмет берётся из окружения (§12.2).
5. **В ядре нет глобальных функций.** Часть привычных строковых/массивных операций обычно живёт
   глобальными функциями; здесь их заменяют статические методы классов (`Text`, `Path`) или прямое
   тело. Функции под `namespace` падают на своём имени, а классы через такой fallback не разрешаются
   вовсе — короткое `instanceof Stringable` молча дало бы `false`.
6. **`Memory` — синглтон на процесс**: состояние течёт между прогонами, прогон порядкозависим.
7. **Сборка органов сторожится `debug_backtrace()`**: `Body` — только из `Man`; `Head`/`Hands`/`Legs` —
   только из `Body`; `PlacePass` — только из `Man`. Иначе `OrganAssembly`. Вызов **один**, при сборке
   `Man`, глубина **2**, без аргументов (`debug_backtrace(DEBUG_BACKTRACE_IGNORE_ARGS, 2)`) — аргументы
   не нужны, потому что читается только `$trace[1]['class']`. **Это сдерживание, а не гарантия:**
   `Closure::bind($fn, null, Man::class)` подменяет область вызывающего кадра, и страж пропускает
   (`$trace[1]['class']` из обычной функции — `null`, из привязанной — `'Maws\Man\Man'`). Поэтому
   инвариант держат типы (`readonly` + типизированные свойства): `newInstanceWithoutConstructor()` даёт
   `Error: Typed property … must not be accessed before initialization`, `unset`/подмена — `Cannot
   unset/modify readonly property`, клон — `Call to private … __clone()`. Одна декларация закрывает все
   обходы конструктора разом: у всех один эффект — свойство не инициализировано. **Точность, добытая
   замером:** `unset` запрещён только у **заполненного** readonly-свойства, у пустого он разрешён и
   молча ничего не делает — поэтому запрет проверяется после заполнения (`Invariants::stripped`),
   иначе проверка доказывала бы пустоту, а не запрет. Предел этого
   решения: замыкание в области класса может ДОСТРОИТЬ пустую оболочку чужими органами — «органы
   именно свои» типы не гарантируют; цена подделки — активное вмешательство вместо тихого `null`,
   и в этом и состоит выбранная граница.
8. **Базу направления грузит `World`, а не вход.** `{Напр}Workspaces.php` подключается в
   `World::find` и `World::place` — по имени направления найденного места, и объявляет класс
   `App\World\{Напр}\Places\{Напр}Workspaces`. Грузится только оно: после `find('Public/Home')`
   объявлен `PublicWorkspaces`, а файла другого направления в запросе нет вовсе — поэтому ошибка в нём
   не касается ни этой страницы, ни остальных. Второй пояс —
   `make test:`: генератор ставит `World::loadDirection('{Напр}')` в шаблон теста, потому что прогон
   собирает место в обход роутинга и не должен зависеть от чужой загрузки.
9. **Windows регистронезависима, Linux — нет.** При `core.ignorecase=true` git не видит смену регистра:
   `git status` чист, а индекс хранит старое имя. Лечится `git rm -r --cached <каталог> && git add <каталог>`.
10. **Хелперы — большая часть ядра.** `core/System/Helpers/**` — 19 модулей (см. §3).
    Все 24 класса-хелпера объявлены `#[Subject]` и прогнаны через `make test:`; вне контракта
    только 23 класса исключений — их проверяют `Fails` тех методов, что их бросают.

## 16. Проверка

Основной путь — `maws make test:<файл>` (§13): контрактные атрибуты исполняются, а не пересказываются.
Раннер (`core/System/Test/Runner.php`) зовёт объявленные случаи и печатает отчёт; тест — обычный
читаемый PHP-скрипт, его видно целиком и можно запустить напрямую (`php app/Tests/…/PlaceTest.php`).

Правило: **сначала убедиться, что инструмент СПОСОБЕН увидеть разницу.** Дифф против эталона слеп к
вызовам глобальных функций, которых в MAWS нет; случай, где обе стороны дружно предупреждают PHP,
проходит «зелёным», ничего не проверяя.

Атрибут держится рукой: поменял тело метода — обязан поменять атрибут. Пока раннер не прогнан,
`Gives`/`Has`/`Fails`/`Changes`/`Responds` — это **заявление о намерении**, а не проверенный факт. Но
рассинхрон прогон не прячет: `maws test` не запускает сохранённые файлы, а перегенерирует каждый из
текущего источника — новое тело против старого ожидания даёт красный. Устаревшим может оказаться
только файл, запущенный руками (`php app/Tests/…/PlaceTest.php`).

**Правило модальности.** «Никогда», «только», «всегда», «невозможно» в этом документе — утверждение о
коде, а не стиль изложения. Каждое либо ссылается на прогон, который падает при нарушении, либо
помечено словом **замысел**. Третьего не бывает: обещание, которое нельзя выразить случаем
`Gives`/`Has`/`Fails`, — это пожелание, и читатель обязан видеть разницу.

Утверждение в прозе ничем не проверяется: прогон не падает, когда документ расходится с кодом.
Поэтому обещания, выразимые кодом, выражаются им. Так `final`, тип и `readonly` органов, «пустой
объект не отдаёт органы», запрет клона и снятия органа прогоняются `core/System/Test/Invariants.php` —
25 случаев на пяти классах. Прогон проверен на способность краснеть: на классе, где все четыре
обещания нарушены, он даёт `false` по каждому.

**Двери контрактом не проверяются.** `DbConnector`, `Session` и `Hands` — это не «значение на входе →
значение на выходе»: они открывают общий ресурс или завершают ответ (`ResponseSent`), и прогон с ними
был бы проверкой php.ini или `exit`, а не кода. Их проверяют пробником на живом процессе (у сессии —
`ini_set('session.save_path', ...)` до `open()`, чтобы файл случая не остался в системном temp).
Политика такой двери — обычный класс и проверяется прогоном (`SessionSettings` — 11 случаев,
`Tools` — 9), как и чистая часть её хелпера (`Csrf::check`).

Та же граница у `Upload`: решения `fits` (тип содержимого против расширения) и `tooBig` (размер против
объявленного предела) проверяются прогоном, а сам перенос — пробником: `is_uploaded_file()` вне настоящей
отправки формы всегда `false`, а ответ `finfo` зависит от версии libmagic на машине.

`Upload::upload` отвечает массивом `status` / `message` / `name`: виноват файл — слова для человека
(«файл больше допустимого размера»), виноват сервер или разработчик — исключение. Это то же разделение,
что у двух родов сбоя (§5): показать или починить. Посетитель не должен видеть 500 из-за того, что выбрал
файл на 20 МБ.

**Кэш — тот же разрез.** Чистая часть проверяется прогоном: `Cache::line` и `Cache::notModified` —
11 случаев (`no-store`, `no-cache`, `max-age` в обоих `scope`; точное совпадение `ETag`, список, `W/`,
`*`, пустая строка), `Policy` — 5 (нет ключа → `no-store`, три отказа разбора). Сам `send` прогоном
не проверяется: в CLI `header()` не отправляет заголовки, и `headers_list()` пуст — случай проверял бы
не код. Его проверяют пробником на живом процессе: `304` с нулевым телом, `HEAD` без тела, чужой
`ETag` → `200`, `public` + `Set-Cookie` → `private` (замер в §8.1).

## 17. Границы и принятые ограничения

- **Инвариант сборки держат типы, а не страж.** В PHP нет «дружественных» классов: «собирает только
  `Man`» и «тело никогда не бывает без органов» одним механизмом не гарантируются. Выбрана строгая
  невыразимость инварианта через типы (`readonly` + типизированные свойства) — и она проверяется
  `core/System/Test/Invariants.php` (25 случаев): окончательность пяти классов, тип и `readonly`
  каждого органа, отказ чтения у пустого объекта, запрет клона и запрет снятия органа. Страж на
  `debug_backtrace()` стоит ради читаемого отказа и **защитой не является** — иначе он сам становится
  дефектом: выглядит как защита, которой нет (см. §15.7).
- **`way` несёт три роли** — контекст, страница, сцена. Слота «страница внутри места» нет; состав
  страницы задан в `startWork()`, а не шаблоном.
- **Повторный вход запрещён** — граф обхода модулей ациклический: два блока страницы, зависящие от
  одного модуля, дают отказ на втором обращении.
- **Композиция между направлениями запрещена** — это граница доверия (см. §7), а не отсутствие случаев.
- **Инструмент отдаёт HTML** — рендеринг живёт в инструменте, а не в сцене.
- **Запрос без плана отвергается, а не пропускается.** `all`/`one`/`run` требуют, чтобы план `EXPLAIN`
  назвал таблицу: `SELECT 1`, `SELECT now()` → `DbasePlanless`. Иначе «план погашен» прошло бы как
  «таблиц нет» — по плану эти случаи неразличимы (см. §7.3). Инструкции, которым плана не дают
  (`TRUNCATE`, DDL), поданные в `all`/`one`/`run` текстом, отвергаются `DbaseMisuse` по первому слову,
  не доходя до сервера: дверей под них нет, схему меняют миграции. Названная граница проверки:
  функции, чьи чтения план не показывает, не проверяются.
- **Стандарты.** PSR-1, PSR-4 и PSR-12 соблюдены. Свои классы ядро руками не подключает — это делает
  PSR-4; `require` остался там, где файл приходит не от автозагрузки: `Workspace.php` места, шаблон
  сцены, файл агента, источник теста. Гибрид «фреймворк на PSR-4 / мир на ручном `require`» намеренный:
  автозагрузка отдала бы инструмент по имени в обход рук.
  **PSR-11 (Container) не вводится** — `get()` по строковому имени дал бы путь к органу в обход тела.
